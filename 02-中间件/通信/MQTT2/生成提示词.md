## 通用规范

Use case: infographic-diagram. Generate ONE finished Chinese technical infographic, 16:9 landscape 2048x1152, opaque flat RGB PNG. Consistent series style: full-bleed warm ivory paper #F8F5ED, dark navy hand-drawn lines and legible Chinese handwritten lettering, muted teal and ochre accents, thin rounded cards, very subtle shadow, no neon, no stickers. Title at top in navy 64px handwritten style; a small independent numbered card immediately LEFT of title. Body large readable 30-36px, generous spacing. Exact watermark 'code闲录' centered at precisely (50%,50%), #CCCCCC at 35% opacity, same font as title, exactly 32px (half title), zero rotation. Keep central patch clear so watermark doesn't overlap body. All arrows must clearly terminate at correct objects. Include bottom takeaway. Do not invent extra facts or text.

## 3-Topic路由

Title Topic 怎样找到订阅者. Number card 3. Topic strip farm / p1 / d001 / state labels 业务域 / 产品 / 设备 / 消息类型. Card 发布主题 farm/p1/d001/state. Card 订阅过滤器 farm/p1/+/state matches farm/p1/d001/state and farm/p1/d002/state, does NOT match farm/p1/d001/sensor/state. Second card farm/p1/d001/# matches farm/p1/d001 and farm/p1/d001/sensor/state. ## 4-连接与订阅时序

Title 从建立连接到收到命令. Number card 4. Clear two-lane sequence chart device d001 left Broker right, time downward. Phase TCP → 可选 TLS; device to Broker CONNECT; Broker to device CONNACK; device to Broker SUBSCRIBE command; Broker to device SUBACK; device to Broker PUBLISH state; Broker to device PUBLISH command. Distinguish arrows carefully. Side cards 成功 CONNACK：MQTT 连接被接受; 检查 SUBACK：订阅可能被拒绝; Client ID 稳定且唯一; 同 ID 新连接会使旧连接断开. Bottom API 调用成功不等于异步结果成功，更不等于业务执行完成.

## 6-QoS交付边界

Title QoS 0、1、2 的交付边界. Number card 6. Three side-by-side mini sequence diagrams sender left receiver right: QoS 0 最多一次 PUBLISH→ no acknowledgment; QoS 1 至少一次 PUBLISH→ and ←PUBACK, 可能重复; QoS 2 恰好一次 PUBLISH→ ←PUBREC PUBREL→ ←PUBCOMP, 单段协议交付避免重复向接收端应用交付. Bottom separate two-hop flow 设备→Broker→后台. Label 第一段：设备发布 QoS; 第二段：通常不高于原消息 QoS 与订阅获准最大 QoS 的较低值. Takeaway PUBACK 只确认当前协议对端；QoS 2 不能替代业务幂等与事务.

## 7-业务控制闭环

Title 从协议确认到执行完成. Number card 7. Three top cards SDK 提交成功 → 协议交付完成 → 业务执行结果 (do NOT suggest each implies next). Main workflow backend publishes command requestId=r001 → Broker routes → device validates and deduplicates → control task → hardware feedback → command/ack completed 或 failed → backend updates UI. Separate state report device→backend state 实际状态＋stateVersion. Distinguish accepted=已受理 and completed=执行完成. Dedup card 同 ID 同参数：返回已存结果；同 ID 不同参数：冲突；正在执行：不重复启动. Bottom 设置为开启比切换状态更易幂等；跨重启去重需要持久化与掉电恢复设计.

## 8-快照会话与遗嘱

Title Retain、持久会话与遗嘱. Number card 8. Three horizontal comparison cards. Retain / 围绕 Topic / 保存最新快照 / 新订阅者获取状态 / 非历史数据库. 持久会话 / 围绕 Client / 订阅与待交付状态 / 同一客户端断线恢复 / 受过期、队列与持久化配置影响. 遗嘱 Last Will / 围绕一次连接 / CONNECT 预先声明 / 异常失联由 Broker 发布 / 正常 DISCONNECT 不触发（MQTT 3.1.1）. Footer example state、online：Retain 开启；瞬时 command：Retain 关闭. Small note 清除保留快照：同 Topic、Retain=1、零字节 Payload. Bottom 三种机制各有职责；保留快照仍需检查数据时间.

## 9-断网恢复流程

Title 断网后的检测与恢复. Number card 9. Upper strip Keep Alive=60秒（MQTT 3.1.1）→ Broker 超过约90秒未收控制报文则断开; 底层链路也可能更早发现; 异常失联发布遗嘱 online=false. Main left-to-right five-state diagram 等待网络 → 连接 → 恢复订阅 → 同步状态 → 就绪; note 成功 CONNACK 后检查 Session Present，必要时订阅并检查 SUBACK. Side two version cards 3.1.1：稳定 Client ID + Clean Session=0; 5.0：稳定 Client ID + 适当会话过期时间，恢复时 Clean Start=0. Bottom strips 旧命令：检查 requestId、有效期与前置条件; 重试：有上限指数退避＋随机抖动，统一连接管理. Takeaway 恢复连接后，还要恢复订阅和业务状态；离线采样需设备自行缓存.

## 10-嵌入式控制任务

Title MQTT 消息如何进入控制任务. Number card 10. Three columns diagram 网络回调 → 受控队列 → 控制任务; Network callback card 核对 Topic、长度、分片完整性; 有界复制 Payload; 非阻塞投递，尽快返回. Queue card 容量设上限；满队列按约定报告忙. Control task card JSON 校验→requestId 去重→前置条件检查→硬件驱动（有超时）→读取反馈→发布 command/ack 与 state. Side note 示例最多255字节，缓冲256字节；SDK 数据不保证以零字符结尾；生产实现需有界重组. Bottom GPIO 输出改变 ≠ 水泵实际运行；实际运行需要电流、水流等相应反馈. Tiny ESP32→电脑局域网IP，127.0.0.1 指板子自身.

## 11-安全与故障排查

Title 安全配置与分层排障. Number card 11. Top three shield cards TLS：校验证书链与服务器名; 认证：独立凭据证明身份; ACL：限制可发布与订阅的主题. Note Client ID 本身不是身份证明，端口号本身不提供加密. Bottom diagnostic path four aligned cards 网络/TLS：IP、端口、监听、时间、CA → MQTT连接：CONNACK、认证、版本 → 订阅与消息：SUBACK、Topic、ACL、会话 → 业务与硬件：JSON、队列、requestId、驱动反馈. Sidebar 轮流掉线先查重复 Client ID；回调阻塞也会影响通信. Bottom 用 requestId 串联命令与结果，日志保留必要证据并脱敏.
