# eRPC 技术图文配图方案

来源：同级 eRPC.md。用户授权直接执行。正文含 5 个章标题，触发章节总览规则；最终计划 8 张，图序与要点层级分别编号。

1、技术定位
1.1、跨芯片、跨核通信包装成函数接口
1.1.1、IDL 和生成代码减少打包、解包与请求分发工作；业务实现仍由开发者编写。
1.2、调用边界
1.2.1、远端调度、通信延迟、故障和内存差异仍需工程设计。

2、构建与运行
2.1、构建时生成两端代码
2.1.1、sensor.erpc → erpcgen → 客户端 Stub / 服务端 Shim → 各自编译。
2.2、运行时处理调用
2.2.1、Stub 编码请求，Transport 传字节，Shim 分发业务，普通调用返回响应。

3、接口示例
3.1、温度、LED 与心跳
3.1.1、getTemperature(0) 返回 25375 毫摄氏度；setLed 返回 void 仍等响应；oneway heartbeat 不等 RPC 响应。
3.2、结果边界
3.2.1、无效通道可通过正常 RPC 响应返回业务错误；响应是否代表完成取决于业务实现。

4、核心机制
4.1、编码与传输
4.1.1、BasicCodec 按约定顺序编码；FramedTransport 帧头为 6 字节，含长度与 CRC16；CRC 不自动重传、不认证身份。
4.2、超时与重试
4.2.1、超时表示结果未知；调用序号只匹配响应；重试须考虑幂等、requestId 去重与状态查询。
4.3、任务与内存
4.3.1、耗时业务交专门任务，必要时复制异步参数，明确内存所有权、长度限制和双向接收仲裁。

5、适用场景
5.1、按项目需求选型
5.1.1、eRPC 适合明确业务方法；RPMsg 传消息；Protobuf 序列化；gRPC 面向网络服务；eCAL 侧重数据交换及工具。
5.2、工程前提
5.2.1、接口语义一致、通信通道可用、两端运行时匹配；硬实时闭环先设计本地控制与有上限的等待。
