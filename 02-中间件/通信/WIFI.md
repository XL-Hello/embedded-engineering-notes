# Wi-Fi：智能设备联网扫盲、代码阅读与面试准备

> 目标：理解 Wi-Fi 的连接链路、IP 网络、配网、安全与断线恢复边界；能在智能设备项目中快速定位驱动初始化、扫描、配网、连接、DHCP、事件回调与重连代码；能清楚回答常见面试问题。
>
> 核心结论：**Wi-Fi 是 IEEE 802.11 无线局域网技术。设备先关联到 AP，再通过 DHCP 或静态配置获得 IP、网关和 DNS，随后才可以使用 TCP/UDP/HTTP/MQTT 等上层协议访问局域网或互联网。**

## 1. 先用一张图理解 Wi-Fi 联网

```text
设备（STA）                    路由器（AP）                     局域网 / Internet
    | -- Scan：寻找 SSID ------> |                                      |
    | <- Beacon / Probe Resp ---|                                      |
    | -- Authentication ------->|                                      |
    | -- Association ---------->|                                      |
    | -- WPA2/WPA3 4-way ------>|  验证密码并生成会话密钥             |
    | -- DHCP Discover -------->| -- DHCP 转发/分配 --> IP/网关/DNS   |
    | <- DHCP Ack：192.168... -|                                      |
    | -- DNS / TCP / UDP --------------------------------------------> |
```

能“连上 Wi-Fi”只说明 802.11 关联和安全协商可能已成功；能“访问云端”还依赖 DHCP、网关、DNS、路由、TLS 时间和服务器可用性。排查必须分层，不能把所有问题都归为“Wi-Fi 不好”。

## 2. 为什么智能设备常用 Wi-Fi

| 需求 | Wi-Fi 的对应能力 | 典型例子 |
| --- | --- | --- |
| 接入家庭网络和互联网 | 连接路由器，经网关访问云服务 | 智能家居上报状态、接收控制 |
| 较高带宽 | 比 BLE/多数低速无线更适合大数据 | 摄像头、语音、OTA 下载 |
| 手机配网生态 | 手机与路由器普遍具备 Wi-Fi | SoftAP/SmartConfig/BLE 辅助配网 |
| 本地控制 | 同一 LAN 内可直连/发现 | 局域网调试、设备互联 |
| 常见安全机制 | WPA2/WPA3、TLS 等可组合使用 | 家庭网络认证和云端加密通信 |

Wi-Fi 不是应用协议：它只提供局域网接入。HTTP、MQTT、WebSocket、DNS、NTP、OTA 都是其上的网络服务；Wi-Fi 密码正确也不保证这些服务可用。

## 3. 角色与关键名词

| 名词 | 含义 | 看代码时常见名字 |
| --- | --- | --- |
| STA（Station） | 作为客户端连接 AP 的设备 | `station`、`sta` |
| AP（Access Point） | 提供无线接入的热点/路由器 | `softap`、`ap` |
| SSID | Wi-Fi 网络名称，不是密码 | `ssid` |
| BSSID | 一个 AP 无线接口的 MAC 地址 | `bssid` |
| Channel | 所在射频信道 | `channel` |
| RSSI | 接收信号强度估计 | `rssi` |
| Authentication / Association | 加入 AP 的链路层过程 | `auth`、`assoc` |
| WPA2/WPA3 | 无线接入认证和加密机制 | `psk`、`sae` |
| DHCP | 自动获取 IP、网关、DNS 等 | `dhcp_client` |
| DNS | 将域名解析为 IP 地址 | `getaddrinfo` |

一个家用路由器常同时承担 AP、DHCP 服务器、默认网关、NAT 和 DNS 转发器，但这些是不同职责。企业网络、访客网或 Mesh 网络中，它们可能不在同一台设备上。

## 4. 2.4 GHz、5 GHz 与信道：先看兼容性再谈速度

| 项目 | 2.4 GHz | 5 GHz |
| --- | --- | --- |
| 覆盖/穿墙 | 通常较好 | 通常较弱 |
| 可用带宽 | 相对较低 | 相对较高 |
| 干扰 | 蓝牙、微波炉及邻居网络较多 | 通常较少，但信道/法规更复杂 |
| IoT 兼容性 | 大多数低成本 IoT 设备支持 | 许多 IoT 设备不支持 |

很多嵌入式设备仅支持 2.4 GHz。配网失败时先确认手机和路由器是否把 2.4/5 GHz 混合为同一 SSID、路由器是否启用不兼容的安全模式、信道是否在模块支持范围内；不要一开始就反复重刷固件。

## 5. 从上电到访问云端：完整链路

```text
设备
 | 初始化 Wi-Fi 驱动/协议栈
 v
扫描或读取已保存的 SSID/密码
 | -> 认证、关联、WPA 握手
 v
获得 LINK_UP（仅无线链路已建立）
 | -> DHCP 获取 IP / Gateway / DNS，或配置静态 IP
 v
获得 GOT_IP（可进行 IP 网络通信）
 | -> DNS 解析域名 -> 建立 TCP/TLS -> MQTT/HTTP 等业务连接
 v
业务在线；任意层断开后按状态机恢复
```

| 阶段 | 成功代表什么 | 失败优先检查 |
| --- | --- | --- |
| 扫描 | 能看到附近 AP 信息 | 射频、地区码、信道、天线、扫描策略 |
| 认证/关联 | 已加入指定 AP | SSID、密码、安全模式、MAC 过滤、RSSI |
| DHCP/GOT_IP | 已有可用 IP 配置 | DHCP 服务、地址池、VLAN、静态配置 |
| DNS | 域名可解析为 IP | DNS 地址、域名、网络劫持/隔离 |
| TCP/TLS | 可连接目标服务 | 路由、端口、防火墙、时间、证书 |
| 应用在线 | 云协议已登录/订阅完成 | 账号、Token、业务协议、服务端状态 |

## 6. 配网：把“如何拿到 SSID 和密码”单独看待

| 方式 | 流程概述 | 优点 | 风险/注意点 |
| --- | --- | --- | --- |
| SoftAP 配网 | 设备开热点，手机连入后提交路由器凭据 | 直观、兼容性好 | 热点要有超时和鉴权；传输凭据需保护 |
| SmartConfig/声波等 | 手机把凭据编码到特殊无线流量，设备监听 | 用户不必切热点 | 兼容性、可靠性、安全设计要评估 |
| BLE 辅助配网 | 手机经 BLE 把 Wi-Fi 凭据写给设备 | 体验较好、可做加密认证 | 仍要保护 BLE 写入权限与凭据生命周期 |
| 预置/二维码 | 出厂或扫码取得网络/绑定信息 | 步骤少 | 不适合任意家庭网络，需防泄露 |

配网凭据是敏感数据：不要写到普通日志、广播包或未受保护的调试接口；持久化时应采用芯片平台提供的安全存储能力。设备应提供可控的“进入配网模式”和“清除旧网络”路径，避免任何人远程触发重置。

## 7. 安全：Wi-Fi 加密与业务 TLS 缺一不可

| 层次 | 主要保护对象 | 典型措施 |
| --- | --- | --- |
| Wi-Fi 接入层 | 设备到 AP 的空口通信 | WPA2-PSK / WPA3-SAE，强密码 |
| IP/传输层 | 端到端业务通信 | TLS、证书链与主机名校验 |
| 业务层 | 命令权限、账号、重放风险 | Token、设备身份、签名/序号、ACL |
| 本地存储 | 已保存的凭据和私钥 | 加密分区、安全存储、权限隔离 |

WPA2/WPA3 只覆盖设备与 AP 之间的无线接入，不能代替设备到云端的 TLS；反过来，即使使用 TLS，也不应该连接开放/伪造 AP 而没有正确的接入和证书策略。为“先跑通”关闭证书校验是高风险临时手段，不能作为量产方案。

## 8. 断线、重连与网络状态机

```text
NET_INIT -> STA_CONNECTING -> WIFI_ASSOCIATED -> GOT_IP -> CLOUD_CONNECTING -> CLOUD_ONLINE
                 |                 |              |                 |
                 v                 v              v                 v
             退避重试          重新关联      重新 DHCP/DNS       重连并恢复业务
                 \____________________ 任意错误/断开 _____________________/
```

重连策略应区分“密码错误/不支持安全模式”等永久性错误与“AP 暂时不可达、DHCP 超时”等瞬时错误。瞬时故障可采用指数退避、随机抖动和最大重试间隔；认证失败不应每秒无限重试，应提示重新配网或等待用户操作。网络恢复后，应用层（MQTT/HTTP/WebSocket）通常仍需要重新登录、订阅或同步状态。

### 8.1 不要只看一个 `connected` 标志

建议分别维护：`wifi_associated`、`ip_ready`、`dns_ready`（或按需解析）、`cloud_connected`、`time_valid`。例如 TLS 失败可能是系统时间未同步，而无线链路和 IP 都正常；MQTT 断线也可能只是 Broker 暂不可达，而不需要重复清除 Wi-Fi 配置。

## 9. 智能设备实现要点

### 9.1 事件驱动，不要阻塞业务线程等待联网

```text
Wi-Fi/IP 事件回调（快速更新状态/投递事件）
        |
        v
网络管理任务：连接、退避、DHCP 结果与配网状态
        |
        v
业务网络任务：DNS、NTP、MQTT/HTTP、状态同步
        |
        v
设备控制任务：保持与网络任务解耦
```

驱动或 IP 事件回调里不应直接做长时间 DNS、TLS、文件下载或硬件控制。回调只更新状态、保存错误码和唤醒网络任务；这样能避免阻塞协议栈并使重连逻辑可测试。

### 9.2 已联网不等于可信时间可用

TLS 证书校验、消息时间戳、OTA 签名有效期常依赖正确时间。开机后应在网络可用时通过 NTP 或受信任服务同步时间；在时间未可信前，明确业务的降级策略，不能简单忽略证书有效期。

### 9.3 信号强度不是唯一质量指标

RSSI 只能反映接收功率的粗略估计。网络卡顿还可能来自同信道竞争、丢包重传、路由器负载、DNS、网关或公网服务。可结合 RSSI、重连次数、DHCP 耗时、DNS 耗时、TCP 重试和应用 RTT 共同定位。

## 11. 伪代码：设备端最小骨架

```c
static void network_event_handler(net_event_t event)
{
    switch (event.type) {
    case WIFI_DISCONNECTED:
        network_state.ip_ready = false;
        cloud_stop();                         // 业务连接与 Wi-Fi 状态解耦
        schedule_sta_retry(event.reason);     // 密码错时不应无限快速重试
        break;

    case IP_GOT_IP:
        network_state.ip_ready = true;
        network_task_wakeup();                // DNS/NTP/云端连接在任务中完成
        break;

    default:
        break;
    }
}

static void network_task(void *arg)
{
    for (;;) {
        wait_until_ip_ready();
        sync_time_if_needed();
        if (cloud_connect_with_tls() == 0)
            cloud_restore_subscription_and_state();
        wait_for_network_change_or_cloud_error();
    }
}
```

真实 SDK 的函数名不同，但职责边界应成立：Wi-Fi 事件负责链路状态，网络任务负责可能阻塞的 IP/云端操作，设备控制任务不依赖网络回调直接执行。

## 12. 常见问题与排查顺序

| 现象 | 优先检查 | 常见原因 |
| --- | --- | --- |
| 扫描不到家里 Wi-Fi | 是否仅支持 2.4 GHz、地区码、信道、SSID 是否隐藏 | 路由器仅开 5 GHz；模块不支持该信道 |
| 一直认证失败 | SSID/密码、安全模式、路由器 MAC 过滤 | 密码错；仅 WPA3 或企业网不被模块支持 |
| 已关联但没有 IP | DHCP 日志、地址池、VLAN、静态 IP | DHCP 未响应；地址池耗尽；隔离网络 |
| 有 IP 但域名解析失败 | DNS 地址、域名、网关网络 | DNS 配置错误；网络需网页认证 |
| TLS 失败 | 系统时间、CA、主机名、SNI | 时间未同步；证书链不完整；关闭校验后才“成功” |
| Wi-Fi 经常掉线 | RSSI、断开 reason、路由器、供电、天线 | 信号弱/干扰；省电策略；电源纹波 |
| 重连后云端不工作 | DHCP/DNS、应用重连、订阅/登录恢复 | 只重连 Wi-Fi，未恢复 MQTT/Token 状态 |
| 配网成功后仍离线 | 凭据保存、事件顺序、实际连接的 SSID | 保存失败；应用过早启动；连到访客隔离网 |

排查日志至少包含：SSID（必要时脱敏）、BSSID、信道、RSSI、连接/断开 reason、IP/网关/DNS（按安全要求脱敏）、DHCP 和 DNS 耗时、NTP 结果、TLS 错误码、云端连接状态与重试次数。不要记录明文密码、Token 或私钥。

## 13. 面试高频问答

### 13.1 STA、AP 分别是什么？

STA 是连接热点的终端角色，IoT 设备通常以 STA 连接家用路由器；AP 是提供无线接入的热点角色。设备的 SoftAP 配网模式中，设备临时充当 AP，让手机连接它并提交家庭网络凭据。

### 13.2 为什么连上 AP 后还不能访问云端？

关联 AP 只是二层无线链路建立。设备还要获得正确 IP、网关和 DNS，目标服务还要可达；若使用 TLS，系统时间、证书链、主机名校验也必须通过。应按“关联 -> IP -> DNS -> TCP/TLS -> 应用登录”逐层排查。

### 13.3 DHCP 做什么？

DHCP 动态分配 IP 地址以及子网掩码、默认网关、DNS 等网络参数。没有这些参数，设备可能显示已连接 Wi-Fi，却无法正确访问局域网或互联网。

### 13.4 2.4 GHz 与 5 GHz 如何取舍？

2.4 GHz 通常覆盖和 IoT 兼容性较好，但干扰更多、带宽较低；5 GHz 通常带宽更高、干扰较少，但覆盖较弱且低成本模块常不支持。产品必须以实际 Wi-Fi 芯片规格和目标环境为准。

### 13.5 为什么不能无限快速重连？

密码错误或不支持的安全模式不会因高频重试而恢复；频繁扫描和关联会耗电、占用空口并给路由器造成压力。应记录失败原因，对瞬时错误做指数退避，对永久配置错误进入重新配网或等待用户处理。

### 13.6 Wi-Fi 使用 WPA2 还需要 TLS 吗？

需要。WPA2/WPA3 主要保护设备与 AP 之间的无线接入；TLS 保护设备到云服务的端到端传输和服务端身份校验。两者覆盖范围和威胁模型不同。
