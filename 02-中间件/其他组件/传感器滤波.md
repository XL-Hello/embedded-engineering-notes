# 第1章 滤波的基础认知

## 1.1、为什么传感器数据需要滤波？

假设温度真实值是：

```text
25.0℃
```

ADC/传感器实际可能输出：

```text
25.1
24.9
25.0
25.2
24.8
25.0
37.5   ← 突然毛刺
25.1
24.9
```

误差可能来自：

* 传感器自身噪声
* ADC 量化误差
* 电源纹波
* EMI / EMC 干扰
* PCB 串扰
* 机械振动
* 温漂
* 通信错误
* 瞬间毛刺
* 高频噪声
* 采样时序不稳定

因此滤波的目标一般有三类：

```text
① 去毛刺
② 降低随机噪声
③ 提取真正关心的信号
```

---

## 1.2、必须知道的几个概念

### 1.2.1、采样频率 Fs

例如：

```text
每 10ms 采样一次

Fs = 100Hz
```

对于最高有效频率为 `Fmax` 的带限信号，根据奈奎斯特采样定理：

```text
Fs > 2 × Fmax
```

工程上还应为模拟抗混叠滤波器的过渡带预留余量，通常取更高采样率，并在 ADC 前使用模拟低通抗混叠滤波器抑制奈奎斯特频率以上的成分；否则仍可能发生混叠。

例如真正关心的是：

```text
0~10Hz
```

可能采用：

```text
Fs = 100Hz
```

---

### 1.2.2、截止频率 Fc

例如：

```text
真实温度变化：< 1Hz
高频噪声：10~100Hz
```

那么可以设计：

```text
低通滤波器

Fc ≈ 1~5Hz
```

把高频噪声过滤掉。

---

## 1.3、四种基本滤波器

这是面试必须知道的。

```text
低通 LPF
低频通过，高频衰减

高通 HPF
高频通过，低频衰减

带通 BPF
只允许某一频段通过

带阻 BSF / Notch
抑制某一频段
```

典型：

```text
温度                → 低通
加速度去重力/DC      → 高通
心率特定频率          → 带通
50Hz/60Hz 工频干扰    → 陷波
```

---

## 1.4、嵌入式最常用滤波算法

如果按照工程中出现频率，我会把它们分成下面几档。

| 算法   | 计算量 | 延迟 |  去毛刺 |    平滑 | 典型用途       |
| ---- | --: | -: | ---: | ----: | ---------- |
| 限幅滤波 |  极低 | 极低 |  ★★★ |     ★ | ADC/传感器异常值 |
| 中值滤波 |   低 |  中 | ★★★★ |    ★★ | 脉冲毛刺       |
| 算术平均 |   低 |  中 |    ★ |   ★★★ | 温度、电压      |
| 滑动平均 |   低 |  中 |    ★ |  ★★★★ | ADC、温湿度    |
| 加权平均 |   低 |  中 |    ★ |  ★★★★ | 最近数据更重要    |
| EMA  |  极低 |  低 |    ★ |  ★★★★ | MCU 最常用    |
| 一阶低通 |  极低 |  低 |    ★ |  ★★★★ | IMU/ADC    |
| FIR  | 中~高 |  中 |   ★★ | ★★★★★ | DSP/音频     |
| IIR  | 低~中 |  低 |   ★★ | ★★★★★ | MCU/DSP    |

| 互补滤波 |   低 |  低 |   ★★ |  ★★★★ | IMU 姿态融合   |

其中最值得真正掌握的是：

```text
限幅
中值
滑动平均
EMA
一阶低通
FIR/IIR
互补滤波
Kalman
```

# 第2章 常用滤波算法详解

## 2.1、限幅滤波 / 限幅消抖

### 2.1.1、原理

如果新数据和上一次数据差距过大：

```c
if (abs(new_value - old_value) > threshold)
{
    new_value = old_value;
}
```

例如温度：

```text
上一帧：25℃
当前帧：80℃
```

如果物理上不可能在 10ms 内发生这种变化，就可以认为是异常值。

### 2.1.2、优点

```text
计算量极低
实现简单
非常适合 MCU
```

### 2.1.3、缺点

如果真实信号确实发生快速变化：

```text
真实跳变也可能被误判
```

若直接把超阈值样本替换为旧输出，持续的真实阶跃也可能始终无法被接受。可根据场景采用“连续超阈值 N 次后接受新值”、限斜率而非直接丢弃，或结合有效范围、状态机判断。

### 2.1.4、应用

非常适合：

```text
温度
湿度
电池电压
压力
液位
光照
ADC
```

通常作为：

> **第一层异常数据过滤。**

---

## 2.2、中值滤波 Median Filter

假设采样：

```text
10  11  12  100  13
```

排序：

```text
10  11  12  13  100
```

取中位数：

```text
12
```

于是：

```text
100
```

这个毛刺基本被干掉。

### 2.2.1、特点

特别擅长：

> **脉冲噪声、尖峰毛刺。**

相比平均滤波：

```text
10 11 12 100 13

平均值 = 29.2
```

平均值直接被 100 带飞了。

而中值：

```text
12
```

就稳定得多。

### 2.2.2、缺点

需要：

```text
缓存 N 个数据
排序
```

通常窗口：

```text
3
5
7
9
```

嵌入式里：

```text
3点
5点
```

非常常见。

---

## 2.3、算术平均滤波

公式：

$$
y=\frac{x_1+x_2+\cdots+x_N}{N}
$$

例如：

```text
10
11
9
10
10
```

平均：

```text
10
```

对零均值且近似独立（或不相关）的随机噪声，平均后其影响通常会减小；偏置和低频漂移不能靠简单平均消除。

### 2.3.1、适合

变化非常慢的数据：

```text
温度
湿度
压力
电池电压
ADC
光照
```

### 2.3.2、最大问题

实时性差。

例如：

```text
窗口 N = 100
```

虽然数据很稳，但变化需要很久才能反映出来。

因此：

> **窗口越大 → 越平滑 → 延迟越严重。**

这是非常重要的面试点。

---

## 2.4、滑动平均滤波 Moving Average

它其实是平均滤波的工程升级版。

维护一个长度为 N 的窗口：

```text
x[n-4]
x[n-3]
x[n-2]
x[n-1]
x[n]
```

每来一个新数据：

```text
删除最老
加入最新
重新计算平均
```

但实际不会每次重新累加，因为那属于拿 CPU 当暖手宝。

通常维护：

```c
sum = sum - old + new;
average = sum / N;
```

复杂度从：

```text
O(N)
```

变成：

```text
O(1)
```

---

## 2.5、加权滑动平均

普通平均：

```text
20 20 20 30
```

每个样本权重一样。

但我们可能认为：

```text
最近的数据更可信
```

于是：

```text
y =
0.1*x[n-3]
+0.2*x[n-2]
+0.3*x[n-1]
+0.4*x[n]
```

通常取各权重之和为 1；否则应再将加权和除以权重和，才能保证恒定输入的幅值不变。

### 2.5.1、用途

适合：

```text
既想平滑
又希望响应稍快
```

---

## 2.6、指数移动平均 EMA

这是嵌入式领域特别重要的一种。

公式：

$$
y[n]=\alpha x[n]+(1-\alpha)y[n-1]
$$

代码：

```c
if (!initialized)
{
    filtered = input;
    initialized = true;
}
else
{
    filtered = alpha * input + (1.0f - alpha) * filtered;
}
```

例如：

```c
alpha = 0.1
```

那么：

```text
10% 当前值
90% 历史值
```

### 2.6.1、α 参数怎么理解？

非常重要。

#### 2.6.1.1、α 小

例如：

```text
α = 0.01
```

特点：

```text
非常平滑
响应很慢
```

#### 2.6.1.2、α 大

例如：

```text
α = 0.8
```

特点：

```text
响应快
滤波效果弱
```

所以：

```text
α ↓

滤波能力 ↑
响应速度 ↓
```

### 2.6.2、为什么 EMA 在 MCU 上特别常用？

因为只需要：

```text
一个历史值
几次乘加
```

不需要保存整个窗口。

例如：

```text
滑动平均 N=100

需要保存：
100 个样本
```

EMA：

```text
只需要：

previous
```

所以对于：

```text
STM32
ESP32
Nordic
NXP
TI MCU
```

非常常见。

---

## 2.7、一阶低通滤波

工程里经常写成：

$$
y[n]=y[n-1]+\alpha(x[n]-y[n-1])
$$

实际上就是 EMA 的另一种形式。

### 2.7.1、α 与截止频率关系

常用的 Euler 离散化近似为（适合 `Fc << Fs` 的情况）：

$$
RC=\frac{1}{2\pi f_c}
$$

$$
\alpha=\frac{dt}{RC+dt}
$$

其中：

```text
dt = 采样周期
Fc = 截止频率
```

例如：

```text
Fs = 100Hz
dt = 0.01s

Fc = 5Hz
```

计算：

```text
RC ≈ 0.0318s

α ≈ 0.239
```

该近似得到的数字滤波器 −3 dB 截止频率不严格等于设定的 `Fc`。若希望一阶数字低通的时间常数严格对应 `Fc`，可用：

$$
\alpha=1-e^{-2\pi F_c/F_s}
$$

本例中 `α ≈ 0.270`；使用哪一种公式应与设计目标保持一致。

代码：

```c
float low_pass(float input)
{
    static float output;
    static bool initialized = false;

    if (!initialized)
    {
        output = input;
        initialized = true;
        return output;
    }

    output += 0.239f * (input - output);

    return output;
}
```

这个公式很值得面试时说出来。

因为这说明你不是：

> “我感觉 0.1 挺顺眼，所以 alpha 就写 0.1。”

---

## 2.8、高通滤波

一阶高通常见：

$$
y[n]=\alpha(y[n-1]+x[n]-x[n-1])
$$

若采用这一 Euler 形式：

$$
\alpha=\frac{RC}{RC+dt},\quad RC=\frac{1}{2\pi F_c}
$$

这里的 `α` 定义与上一节低通公式不同；实现时需保存上一输入 `x[n-1]` 和上一输出 `y[n-1]`。

典型应用：

### 2.8.1、IMU 去掉重力/DC

加速度传感器数据：

```text
真实运动
+
重力
+
低频漂移
```

高通可以：

```text
去掉低频部分
保留快速变化
```

---

## 2.9、FIR 滤波器

FIR：

> Finite Impulse Response
> 有限冲激响应滤波器

公式：

$$
y[n]=\sum_{k=0}^{N-1} h[k]x[n-k]
$$

实际上就是：

```text
历史数据 × 系数
然后累加
```

例如：

```c
y =
h0*x[n] +
h1*x[n-1] +
h2*x[n-2];
```

你前面的：

```text
滑动平均
加权平均
```

其实都可以看作：

> **特殊 FIR。**

### 2.9.1、FIR 优点

最大的理论优势：

```text
稳定
可以实现严格线性相位
```

因此：

```text
音频
通信
生物信号
高质量数字信号处理
```

非常常见。

### 2.9.2、缺点

为了得到陡峭滤波效果：

```text
阶数可能很高
```

比如：

```text
64阶
128阶
256阶
```

意味着大量：

```text
乘法
加法
历史数据
```

普通小 MCU 压力就比较明显。

---

## 2.10、IIR 滤波器

IIR：

> Infinite Impulse Response

典型公式：

以下假设分母系数已归一化为 `a0 = 1`：

$$
y[n]=b_0x[n]+b_1x[n-1]-a_1y[n-1]
$$

通用 IIR 差分方程还包含 `a0y[n]`；若设计工具给出的 `a0 ≠ 1`，实现前应将所有 `ak`、`bk` 系数除以 `a0`，再代入递推式。

相比 FIR：

最大的特点是：

```text
会使用之前的输出
```

例如：

```text
输入历史：
x[n]
x[n-1]

输出历史：
y[n-1]
```

### 2.10.1、IIR 最大优势

在仅比较幅频选择性、且不要求线性相位时，IIR 往往能以比 FIR 更低的阶数满足相近指标；具体阶数须由通带/阻带指标、过渡带和滤波器类型设计确定。

因此：

```text
计算量小
内存小
```

非常适合 MCU。

常见 IIR 类型：

```text
Butterworth
Chebyshev
Bessel
Elliptic
```

面试里最常见：

> Butterworth。

---

## 2.11、Butterworth

### 2.11.1、Butterworth 为什么常见？

特点：

> **通带最大平坦。**

也就是：

```text
不会在通带里产生明显波纹
```

非常适合：

```text
传感器
ADC
音频
IMU
```

如果面试官问：

> 为什么选 Butterworth？

可以回答：

> 传感器滤波通常希望通带比较平坦，不希望有效信号产生明显幅值波动，因此 Butterworth 是比较常用的折中方案。

---

## 2.12、Chebyshev / Bessel

不需要入门阶段钻得太深，但面试知道区别很好。

| 类型          | 特点         |
| ----------- | ---------- |
| Butterworth | 通带平坦       |
| Chebyshev I 型 | 通带有波纹，过渡带更陡 |
| Chebyshev II 型 | 阻带有波纹 |
| Bessel      | 相位特性好      |
| Elliptic    | 过渡最陡，但波纹明显 |

简单记：

```text
Butterworth → 幅值平坦
Bessel      → 相位友好
Chebyshev I → 通带有波纹、滚降快
Chebyshev II → 阻带有波纹
Elliptic    → 更激进
```

---

## 2.13、陷波滤波器 Notch

用来专门干掉某个频率。

例如：

```text
50Hz
60Hz
```

电网工频干扰。

例如医疗设备：

```text
ECG
EEG
PPG
```

经常出现：

```text
50Hz Notch
```

---

## 2.14、互补滤波

这是 IMU 必会。

例如姿态角估计：

陀螺仪：

```text
短时间非常准
长期会漂移
```

加速度计（静止或低动态时）：

```text
可提供重力方向，用于长期校正横滚/俯仰
短时间噪声大
线性加速度或剧烈运动时会受干扰
```

于是：

```text
陀螺积分得到的角度通路 → 高频部分
Accel → 低频重力方向
```

最后融合：

$$
Angle=\alpha(Angle+Gyro\times dt)+(1-\alpha)AccelAngle
$$

例如：

```c
angle =
0.98f * (angle + gyro * dt)
+ 0.02f * accel_angle;
```

本质：

```text
Gyro：负责快速变化

Accel：在低动态时负责横滚/俯仰的长期校正
```

仅使用陀螺仪和加速度计不能长期校正航向角；航向角通常还需磁力计、GNSS 或其他外部参考。

这就是：

> **互补滤波。**

---

## 2.15、Kalman Filter 卡尔曼滤波

卡尔曼不是简单意义上的：

> “把数据变平滑。”

它真正解决的问题是：

> **根据系统模型和一个或多个带噪声的观测，对系统状态进行估计。在线性系统、模型正确且噪声统计假设满足时，标准卡尔曼滤波可给出最小均方误差意义下的最优估计。**

非线性系统通常考虑 EKF、UKF 等近似方法；模型失配时也不保证最优。

例如：

```text
真实位置
真实速度
真实姿态

这些状态无法直接准确测量
```

但是你有：

```text
加速度计
陀螺仪
GPS
编码器
```

Kalman 会融合这些观测。

### 2.15.1、Kalman 的基本思想

分两步：

```text
预测 Predict

↓

根据模型预测当前状态

↓

更新 Update

↓

根据传感器数据修正预测
```

可以理解：

```text
模型说：
现在应该在 10.2m

GPS说：
现在大概在 10.8m

Kalman：
根据双方可信程度

最终估计：
10.4m
```

### 2.15.2、Q 和 R 是什么？

这是 Kalman 面试高频题。

```text
Q：
过程噪声协方差

代表：
你多不相信系统模型
```

```text
R：
测量噪声协方差

代表：
你多不相信传感器
```

粗略理解：

```text
R 大
→ 不相信传感器
→ 更依赖模型

Q 大
→ 不相信模型
→ 更依赖传感器
```

这个一定要会。

### 2.15.3、Kalman 典型用途

```text
无人机姿态
机器人定位
汽车导航
GPS + IMU
编码器 + IMU
目标跟踪
姿态估计
```

但普通：

```text
温度
湿度
光照
电池电压
```

上 Kalman 通常属于：

> 算法比问题复杂。

EMA 就能干完，没必要拉出矩阵运算开会。

---

## 2.16、Savitzky-Golay 滤波

相对没那么常见，但算法岗位或者信号处理可能问。

它通过：

> 局部多项式拟合

实现平滑。

相比滑动平均，它最大的优点是：

```text
能较好保留：
峰值
波形
斜率
```

适合：

```text
光谱
曲线
生物信号
传感器趋势数据
```

---

## 2.17、Hampel Filter

可以理解为：

> 比中值滤波更智能的异常值检测。

通常根据：

```text
median
MAD
```

判断：

```text
当前值是不是异常值
```

适合：

```text
偶发离群点
工业传感器
压力/温度数据
```

比简单限幅更有统计意义。

# 第3章 如何选择滤波算法

## 3.1、实际项目通常不是一个滤波器

真正工程代码经常是：

```text
Sensor

↓

数据合法性检查

↓

限幅

↓

中值滤波

↓

低通 / EMA

↓

业务逻辑
```

例如温度：

```text
25.0
25.1
100
24.9
25.0
```

先：

```text
中值滤掉 100
```

再：

```text
EMA 平滑随机波动
```

效果往往比单一算法更好。

---

## 3.2、不同传感器怎么选？

这是实际开发最重要的一张表。

| 场景     | 推荐                     |
| ------ | ---------------------- |
| 温度     | 限幅 + EMA               |
| 湿度     | 限幅 + EMA               |
| 电池电压   | 滑动平均 / EMA             |
| ADC 电压 | 滑动平均 / IIR             |
| 光照     | 中值 + EMA               |
| 压力     | 中值 + 低通                |
| 超声波    | 中值                     |
| ToF 测距 | 中值 + EMA               |
| 红外测距   | 中值 + EMA               |
| 加速度计   | LPF                    |
| 陀螺仪    | LPF                    |
| IMU 姿态 | Complementary / Kalman |
| GPS    | 质量检查 +（有运动模型或需与 IMU 等融合时）Kalman |
| ECG    | Bandpass + Notch       |
| 麦克风    | FIR/IIR                |
| 机械振动   | 按目标频段选带通/低通/高通；用 FFT 做频谱分析、识别特征频率或辅助设计滤波器 |
| 编码器速度  | Moving Average / LPF   |

上述推荐需结合动态特性、采样率、噪声和允许延迟调参；例如单独 GPS 的简单显示或轨迹平滑，并不一定需要 Kalman。

---

## 3.3、几个算法的核心区别

建议面试前记住：

```text
按任务：异常值抑制（限幅、中值）／平滑（滑动平均、EMA）／频段选择（低通、高通、带通、带阻、陷波）／状态估计（互补滤波、Kalman）

按实现结构：FIR／IIR。两者都可实现低通、高通、带通、带阻、陷波等频率选择功能；滑动平均属于 FIR，EMA 可视为一阶 IIR。
```

更加高级：

```text
                         多传感器融合
                              │
                    ┌─────────┴─────────┐
                    │                   │
              Complementary          Kalman
```

## 3.5、浮点还是定点？

低端 MCU：

```text
Cortex-M0/M0+
```

可能没有 FPU。

那么：

```c
float
```

计算成本比较高。

可以使用：

```text
Q15
Q31
```

定点计算。

例如：

```text
α = 0.25
```

Q15：

```text
0.25 × 32768 = 8192
```

所以：

```text
8192 / 32768 = 0.25
```

## 3.6、采样频率非常重要

很多人写：

```c
filtered =
    0.1 * input +
    0.9 * filtered;
```

然后觉得自己完成了数字滤波。

问题是：

如果：

```text
Fs = 10Hz
```

和：

```text
Fs = 1000Hz
```

同一个：

```text
α = 0.1
```

实际截止频率完全不同。

所以专业一点的做法是：

```text
先确定：

采样频率 Fs

↓

目标截止频率 Fc

↓

计算滤波参数
```

而不是：

```text
α = 0.1 看起来挺吉利
```

# 第4章 面试相关问题

## 4.1、面试问：你用过哪些滤波算法？

不要回答：

> 我用过平均滤波、卡尔曼滤波。

太像算法名背诵比赛。

比较好的回答是：

> 在嵌入式传感器处理中，我一般会根据噪声特点选择算法。如果是 ADC、温度、电压这类慢变化信号，常用滑动平均，或一阶低通（EMA）；如果存在明显脉冲毛刺，会先加中值或者限幅滤波。如果涉及 IMU 姿态估计，可以使用互补滤波，而 GPS、IMU、编码器等多源状态估计则会考虑 Kalman。对于频率特征明确的信号，例如音频或者振动数据，则更适合 FIR、IIR、带通或者陷波滤波。

这个回答的信息密度已经很不错。

---

## 4.2、面试问：平均滤波和中值滤波有什么区别？

可以回答：

```text
平均滤波：

主要针对随机噪声，
但容易受到异常值影响。
```

例如：

```text
10 10 10 100 10
```

平均：

```text
28
```

中值：

```text
10
```

所以：

> 中值滤波更适合脉冲噪声和离群点，而平均滤波更适合零均值随机噪声。

---

## 4.3、面试问：为什么不用更大的平均窗口？

回答：

> 增大窗口虽然能够提高平滑效果，但会增加系统延迟，同时增加 RAM 占用。滤波本质上是在噪声抑制和动态响应之间权衡，因此窗口并不是越大越好。

这句话可以反复用。

---

## 4.4、面试问：为什么用 EMA？

回答：

> EMA 只需要保存上一次滤波结果，空间复杂度是 O(1)，计算也只需要简单乘加，非常适合资源有限的 MCU。同时通过调整 α 可以控制滤波强度和响应速度。

然后补一句：

> 如果知道采样周期和目标截止频率，我通常会根据截止频率计算 α，而不是简单经验取值。

这一句明显比“α 我一般写 0.1”靠谱得多。

---

## 4.5、面试问：FIR 和 IIR 有什么区别？

建议直接记这个表：

| FIR      | IIR       |
| -------- | --------- |
| 只使用输入历史  | 输入 + 输出历史 |
| 天然稳定     | 可能不稳定     |
| 系数对称/反对称时可严格线性相位 | 一般非线性相位   |
| 阶数通常高    | 阶数低       |
| 计算量较大    | 计算量较小     |
| 音频/DSP常见 | MCU传感器常见  |

一句话：

> FIR 天然稳定，并可通过对称/反对称系数实现严格线性相位，但通常需要较高阶数；IIR 利用反馈结构，常能以较低阶数取得较强的幅频选择性。

---

## 4.6、面试问：什么情况下用 Kalman？

不要回答：

> 精度要求高的时候。

这其实不够准确。

应该说：

> 当系统存在可用的状态模型，且需要基于一个或多个带噪声观测量进行状态估计或融合时，Kalman 才比较有价值，例如 GPS + IMU、编码器 + IMU、位置和速度联合估计。如果只是普通温度或者 ADC 平滑，EMA 或 IIR 通常更合适。

## 4.9、如果只针对“嵌入式面试”压缩成 8 个关键词

直接记：

```text
① 限幅：处理异常跳变

② 中值：处理脉冲毛刺

③ 滑动平均：抑制随机噪声

④ EMA：低资源 MCU 平滑神器

⑤ LPF/HPF：理解频率滤波

⑥ FIR/IIR：数字滤波核心体系

⑦ Complementary：IMU 简单融合

⑧ Kalman：状态估计 + 多传感器融合
```

真正面试时，重点并不是能报出二十种算法，而是能够讲清楚：

> **噪声是什么 → 为什么选这个算法 → 参数怎么确定 → 对实时性有什么影响 → MCU 资源是否允许。**

能把这条逻辑讲清楚，已经比单纯背“均值、中值、卡尔曼”强不少。
