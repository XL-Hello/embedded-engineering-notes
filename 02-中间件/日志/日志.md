# 基于 Flash 的分层日志存储与环形管理（C 语言实现）

嵌入式日志既要在掉电后保留，又不能频繁擦写同一片 Flash。本方案将日志系统划分为**元数据区、目录区和日志数据区**：元数据区保存可恢复的写入状态，目录区按“日期 + 扇区片段”索引日志，数据区按扇区擦除、顺序追加，并在空间耗尽后回绕覆盖。

本文假设底层为 NOR SPI Flash（写入只能将位从 `1` 改为 `0`；重新写入前必须擦除整个扇区）。若使用 NAND Flash、eMMC 或 EEPROM，应保留上层接口、记录提交和恢复状态机，替换底层擦写策略。

## 0. 核查结论与修订标记（已修复）

下表保留了原方案的全部关键问题点、原因和本版处理方式，便于评审时追溯；后续章节均已按“修复后”的流程表述。

| 点位 | 原问题及原因 | 本版修复 |
| --- | --- | --- |
| §4 目录结构 | `log_catalog_t` 没有记录类型或删除目标，却要求重放 `ADD` / `DELETE`；目录无法实现所述删除语义。 | 增加带 `ADD_FRAGMENT`、`DROP_SECTOR` 操作的追加式目录记录，并以 `entry_id` 保证重放幂等。 |
| §4、§6 日期索引 | 一个“日期项”可跨任意多个扇区；回收其中一个扇区时删除整天，会无谓丢弃其余仍有效日志；当前日期跨回绕后长度还可能超过日志区容量。 | 目录粒度改为“某日期在某一扇区内的连续片段”。同一天可有多个片段，回收只失效目标扇区的片段。 |
| §6 数据写入 | 原流程在数据写完后才提交写指针。掉电留下半写数据时，重启会在同一地址重写，NOR Flash 可能需要 `0→1`，无法安全续写。 | 写入前先持久化“已预留”的下一写地址；日志帧使用 CRC 和最后提交标记。未完成预留只形成可跳过的空洞，绝不重写。 |
| §6 擦除顺序 | 目录删除与擦除之间、擦除与元数据更新之间没有持久化状态；掉电后当前临时目录可能仍指向已擦除数据。 | 引入 `RECLAIM_PENDING` 状态：先持久化回收意图，再写目录失效记录、擦除扇区，启动时可幂等续做。 |
| §4、§7 提交与 CRC | “CRC 覆盖 CRC 前字段”却又要求先清零 CRC，表述矛盾；仅描述最后写 `magic`，未定义目录和元数据的槽位/银行切换。 | 固定 CRC 覆盖范围；所有持久化记录均采用“正文（magic 保持擦除值）→ CRC 已写入 → 最后写 magic”的提交协议。 |
| §7 目录压缩 | 原文要求写入“新目录区”，但布局中只有一个目录区，无法在压缩掉电时同时保留新旧完整副本。 | 目录区明确拆为 A/B 两个银行；切换完成前绝不擦除旧银行。元数据区也采用 A/B 银行。 |
| §8 导出 | 按 `start + length` 原样导出会输出填充、半写内容或已损坏字节；代码也没有实际合并当前临时目录。 | 导出改为逐帧校验并仅发送已提交且 CRC 正确的 payload；有效目录与元数据中的当前片段按 `entry_id` 去重合并。 |
| §9 格式化 | 示例遗漏 `<stdarg.h>`，截断后仍返回原始长度，并忽略 Flash 写入失败，调用方会误认为整条日志已保存。 | 显式处理格式化失败、截断和持久化失败；串口发送仍不阻塞已完成的 Flash 状态。 |

## 1. 目标与约束

- 日志可按日期查询，并支持导出全部**有效且已提交**的日志帧。
- 日志区顺序追加，写到末尾后从起始地址回绕；每次复用扇区前必须先完成目录失效和扇区擦除。
- 目录索引粒度为“日期 + 扇区内连续片段”，不是“一个日期只有一个连续地址范围”。同一天跨扇区、跨回绕时会对应多个片段。
- 掉电重启后，只恢复最新一份 CRC 正确、已提交的元数据；已提交日志帧可导出，已预留但未提交的帧必须跳过，绝不作为文本导出。
- 单个**日志帧**不得跨擦除扇区，但底层写入可以跨 Flash 页；业务层长消息应拆成多个带续帧标志的日志帧。单帧长度不得超过一个扇区可用空间。
- 所有擦除、元数据、目录和日志数据访问都由同一个日志任务串行执行；中断和其他任务只能投递事件到队列。

> “按日期”是查询索引，不是永久归档承诺。环形区回绕后，已被擦除扇区中的片段会从目录中失效；同一天其余扇区片段仍可查询。

## 2. 存储布局

以下地址仅为示例，所有区间均为**闭区间**，容量为 `end - start + 1`。目录区和元数据区必须各至少有两个可独立擦除的银行，才能在压缩或轮换时抵抗掉电。

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <string.h>

#define FLASH_SECTOR_SIZE          (4u * 1024u)
#define FLASH_PAGE_SIZE            256u
#define FLASH_ERASED_U32           UINT32_MAX

#define FLASH_CATALOG_START        0x03200000u
#define FLASH_CATALOG_BANK0_END    0x0327FFFFu
#define FLASH_CATALOG_BANK1_START  0x03280000u
#define FLASH_CATALOG_END          0x032FFFFFu

#define FLASH_META_START           0x03300000u
#define FLASH_META_BANK0_END       0x0337FFFFu
#define FLASH_META_BANK1_START     0x03380000u
#define FLASH_META_END             0x033FFFFFu

#define FLASH_LOG_START            0x03400000u
#define FLASH_LOG_END              0x03FFFFFFu

#define ARRAY_SIZE(a)              (sizeof(a) / sizeof((a)[0]))
#define ALIGN_DOWN(v, a)           ((uint32_t)(v) & ~((uint32_t)(a) - 1u))
#define ALIGN_UP(v, a)             (((uint32_t)(v) + (uint32_t)(a) - 1u) & \
                                    ~((uint32_t)(a) - 1u))

_Static_assert((FLASH_SECTOR_SIZE & (FLASH_SECTOR_SIZE - 1u)) == 0u,
               "sector size must be a power of two");
_Static_assert((FLASH_PAGE_SIZE & (FLASH_PAGE_SIZE - 1u)) == 0u,
               "page size must be a power of two");

typedef enum {
    FLASH_ZONE_CATALOG,
    FLASH_ZONE_META,
    FLASH_ZONE_LOG,
} flash_zone_t;

typedef struct {
    flash_zone_t zone;
    uint32_t start;
    uint32_t end;
} flash_region_t;

static const flash_region_t g_regions[] = {
    { FLASH_ZONE_CATALOG, FLASH_CATALOG_START, FLASH_CATALOG_END },
    { FLASH_ZONE_META,    FLASH_META_START,    FLASH_META_END    },
    { FLASH_ZONE_LOG,     FLASH_LOG_START,     FLASH_LOG_END     },
};
```

`ALIGN_DOWN()` 只适用于对齐值为 2 的幂；本方案的页和扇区均满足该条件。原始 `BLOCK_32K_BASE(addr)` / `BLOCK_64K_BASE(addr)` 一类宏如果掩码漏写 `- 1` 会产生错误地址，应统一替换为 `ALIGN_DOWN(addr, size)`。

## 3. 底层接口与严格边界检查

上层不应直接调用芯片驱动。统一封装后，可检查跨区访问；擦除必须验证**整个扇区**都在目标区域内。`bsp_flash_write()` 内部还必须按 `FLASH_PAGE_SIZE` 切分页写，并向上报告忙、写保护和校验失败。

```c
/* BSP 返回 0 表示成功。 */
int bsp_flash_read(uint32_t addr, void *buf, uint32_t len);
int bsp_flash_write(uint32_t addr, const void *buf, uint32_t len);
int bsp_flash_erase_sector(uint32_t sector_addr);
uint32_t crc32(const void *buf, uint32_t len);

static const flash_region_t *flash_region(flash_zone_t zone)
{
    for (size_t i = 0; i < ARRAY_SIZE(g_regions); ++i) {
        if (g_regions[i].zone == zone) return &g_regions[i];
    }
    return NULL;
}

static bool range_in_region(const flash_region_t *r, uint32_t addr, uint32_t len)
{
    /* len == 0 不应发起 Flash 访问；减法形式避免 addr + len 溢出。 */
    return r != NULL && len != 0u && addr >= r->start &&
           addr <= r->end && len <= r->end - addr + 1u;
}

static int flash_read(flash_zone_t zone, uint32_t addr, void *buf, uint32_t len)
{
    const flash_region_t *r = flash_region(zone);
    return (buf != NULL && range_in_region(r, addr, len)) ?
           bsp_flash_read(addr, buf, len) : -1;
}

static int flash_write(flash_zone_t zone, uint32_t addr, const void *buf, uint32_t len)
{
    const flash_region_t *r = flash_region(zone);
    return (buf != NULL && range_in_region(r, addr, len)) ?
           bsp_flash_write(addr, buf, len) : -1;
}

static int flash_erase_sector(flash_zone_t zone, uint32_t addr)
{
    const flash_region_t *r = flash_region(zone);
    if (r == NULL || addr != ALIGN_DOWN(addr, FLASH_SECTOR_SIZE) ||
        !range_in_region(r, addr, FLASH_SECTOR_SIZE)) {
        return -1;
    }
    return bsp_flash_erase_sector(addr);
}
```

只校验擦除起始地址不够：最后几个字节即使落在区域内，整扇区仍可能越界到下一个分区。日志区、目录银行和元数据银行的起止地址还应在初始化时校验扇区对齐且互不重叠。

## 4. 持久化记录与目录模型

不要把 C 结构体直接写入 Flash。以下结构仅描述字段含义；实际落盘必须通过固定大小、固定字节序（建议小端）的 `encode_*()` / `decode_*()` 函数。禁止把指针、枚举默认宽度、位域或未初始化的结构体填充字节写入 Flash。

```c
typedef struct {
    uint16_t year;
    uint8_t  month, day, hour, minute, second;
} log_time_t;

typedef enum {
    META_READY = 1u,
    META_CLOSE_PENDING,
    META_RECLAIM_PENDING,
    META_CLEAR_PENDING,
} log_meta_phase_t;

typedef enum {
    CATALOG_ADD_FRAGMENT = 1u,
    CATALOG_DROP_SECTOR,
} catalog_op_t;

/* 所有 offset 相对于 sector_addr，范围为 [0, FLASH_SECTOR_SIZE]。 */
typedef struct {
    uint32_t magic;              /* 最后写入，作为提交标记 */
    uint16_t version;
    uint16_t phase;
    uint32_t sequence;
    uint32_t catalog_generation; /* 当前有效目录银行的代次 */
    uint32_t write_addr;         /* 下一个“未预留”地址 */
    uint32_t frame_sequence;
    uint64_t next_entry_id;      /* 持久化分配器；0 永不作为有效 ID */
    uint64_t current_entry_id;   /* 0 表示没有打开片段 */
    log_time_t current_day;
    uint32_t current_sector;
    uint16_t current_begin;
    uint16_t current_end;        /* 已预留范围的末端，可能含未提交帧 */
    uint32_t pending_sector;     /* phase 为 PENDING 时使用 */
    uint64_t pending_entry_id;
    uint32_t crc32;
} log_meta_t;

typedef struct {
    uint32_t magic;              /* 最后写入 */
    uint16_t version;
    uint16_t op;                 /* catalog_op_t */
    uint32_t sequence;
    uint64_t entry_id;           /* ADD 的唯一 ID；重放按此幂等 */
    log_time_t day;              /* DROP_SECTOR 时忽略 */
    uint32_t sector_addr;
    uint16_t begin_offset;       /* ADD 的有效扫描范围 */
    uint16_t end_offset;
    uint32_t crc32;
} log_catalog_record_t;

typedef struct {
    uint32_t magic;              /* 最后写入 */
    uint16_t version;
    uint16_t flags;              /* 首帧/续帧/末帧等 */
    uint32_t frame_sequence;
    log_time_t timestamp;
    uint16_t payload_len;
    uint8_t reserved[3];          /* 编码时固定为 0，使头长为 32 字节 */
    uint32_t payload_crc32;
    uint32_t header_crc32;
} log_frame_header_t;

#define LOG_META_MAGIC       0x4C4D4554u /* "LMET" */
#define LOG_CATALOG_MAGIC    0x4C434154u /* "LCAT" */
#define LOG_FRAME_MAGIC      0x4C46524Du /* "LFRM" */
#define LOG_FRAME_HEADER_SIZE 32u       /* 固定编码头长，含保留字节 */
#define LOG_FRAME_ALIGN      4u
```

`log_frame_header_t`、目录记录和元数据的序列化长度应定义为常量，不能使用 `sizeof` 作为协议长度。构造编码缓冲区前清零；CRC 覆盖除 `magic` 和自身 CRC 字段之外的固定正文。日志帧还应保存独立的 payload CRC。写入顺序统一为：

1. 写入正文、长度和 CRC，`magic` 对应的 4 字节保持擦除值 `0xFFFFFFFF`；
2. 写入 payload；
3. 最后只把 `magic` 写成对应常量。

读者只有在 `magic`、版本、边界和全部 CRC 都正确时才承认该记录。由于提交标记只发生 `1→0` 转换，掉电时的半写记录不会被误判为完成。

目录中一个 `ADD_FRAGMENT` 只描述一个扇区内、同一日期的范围；同一天出现多个 `entry_id` 是正常情况。`DROP_SECTOR` 表示该扇区的所有早期 `ADD_FRAGMENT` 失效。目录重放按 sequence 顺序执行：添加或更新 `entry_id`，遇到 `DROP_SECTOR` 则删除该扇区的有效条目。当前未关闭片段只存在于最新元数据中，查询时临时叠加。

## 5. 环形地址、帧边界与时间校验

```c
static bool day_equal(const log_time_t *a, const log_time_t *b)
{
    return a->year == b->year && a->month == b->month && a->day == b->day;
}

static uint32_t log_capacity(void)
{
    return FLASH_LOG_END - FLASH_LOG_START + 1u;
}

static uint32_t log_next_addr(uint32_t addr, uint32_t step)
{
    uint32_t offset = addr - FLASH_LOG_START;
    return FLASH_LOG_START + ((offset + step) % log_capacity());
}

static uint32_t sector_base(uint32_t addr)
{
    return ALIGN_DOWN(addr, FLASH_SECTOR_SIZE);
}

static uint32_t frame_span(uint16_t payload_len)
{
    return ALIGN_UP(LOG_FRAME_HEADER_SIZE + (uint32_t)payload_len,
                    LOG_FRAME_ALIGN);
}

static bool frame_fits_sector(uint32_t addr, uint32_t span)
{
    uint32_t offset = addr - sector_base(addr);
    return span <= FLASH_SECTOR_SIZE - offset;
}
```

`LOG_FRAME_HEADER_SIZE` 是编码后的固定头长。`log_next_addr()` 的调用前提是 `addr` 位于日志区、`step <= log_capacity()`；初始化和断言必须保证该前提。帧不跨擦除扇区，所以不再使用“一个日期范围跨环形区”的区间相交判断，也不会产生超过日志区容量的 `current_len`。

写入前必须校验 RTC 时间（年、月、日、时分秒均合法）。RTC 回拨或跨日时，关闭当前片段并为新日期开启新片段；目录按日期聚合，不要求日期单调递增。

## 6. 写入流程

核心原则是“**先持久化预留，再写帧；先持久化回收意图，再失效目录和擦除**”。以下流程由唯一日志任务在持有 Flash 互斥锁时执行。

1. 从 RTC 取得并校验时间，将超长业务消息拆成不跨扇区的帧。
2. 若日期改变、`write_addr` 已进入另一扇区，或下一帧放不进当前扇区，执行“关闭当前片段”事务：先提交 `META_CLOSE_PENDING`（含 `entry_id`、日期、扇区和范围），再追加对应 `ADD_FRAGMENT`，最后提交 `META_READY` 并清除当前片段。关闭时先扫描该范围；没有任何已提交帧则只清除元数据，不写空目录项。恢复时可按 `entry_id` 补写或确认目录记录，重复执行不会产生重复条目。
3. 若 `write_addr` 位于新扇区起点，执行“回收扇区”事务：提交 `META_RECLAIM_PENDING`，追加并提交 `DROP_SECTOR`，擦除目标日志扇区，最后提交新的 `META_READY`。掉电后启动恢复会从该 phase 继续；目录在物理擦除前已不可见，因此宁可少显示旧日志，也不会显示已覆盖日志。
4. 建立或扩展当前“日期 + 扇区”片段，计算帧占用长度，先提交更新后的 `META_READY`：其中 `write_addr` 已前移，`frame_sequence` 已递增，`current_end` 已包含本帧预留空间。
5. 在已擦除空间依次写入帧头正文、payload，最后写 `LOG_FRAME_MAGIC`。任何一步失败均返回错误；下一次写入从已预留区域之后开始，失败位置作为扫描时跳过的空洞。

关键骨架如下；`meta_commit()`、`catalog_append()`、`recover_reclaim_sector()` 和 `program_frame()` 必须遵循第 4、7 节的提交协议，不能用原地改写替代。

```c
static int log_write_frame(const uint8_t *payload, uint16_t len,
                           uint16_t flags, const log_time_t *now)
{
    const uint32_t span = frame_span(len);

    if (payload == NULL || now == NULL || span > FLASH_SECTOR_SIZE) return -1;

    if (g_meta.current_entry_id != 0u &&
        (!day_equal(&g_meta.current_day, now) ||
         g_meta.current_sector != sector_base(g_meta.write_addr) ||
         !frame_fits_sector(g_meta.write_addr, span))) {
        if (close_current_fragment_transaction() != 0) return -1;
    }

    if (g_meta.write_addr == sector_base(g_meta.write_addr) &&
        recover_reclaim_sector(g_meta.write_addr) != 0) {
        return -1;
    }
    if (!frame_fits_sector(g_meta.write_addr, span)) return -1; /* 状态机错误 */

    const uint32_t frame_addr = g_meta.write_addr;
    log_meta_t next = g_meta;
    uint32_t offset = frame_addr - sector_base(frame_addr);
    if (next.current_entry_id == 0u) {
        next.current_entry_id = next.next_entry_id++;
        if (next.current_entry_id == 0u || next.next_entry_id == 0u) return -1;
        next.current_day = *now;
        next.current_sector = sector_base(frame_addr);
        next.current_begin = (uint16_t)offset;
    }
    next.current_end = (uint16_t)(offset + span);
    next.frame_sequence++;
    next.write_addr = log_next_addr(frame_addr, span); /* 预留，不回退 */

    if (meta_commit(&next) != 0) return -1;
    g_meta = next;
    return program_frame(frame_addr, payload, len, flags, now,
                         g_meta.frame_sequence);
}
```

`frame_addr` 必须在提交前保存并直接传给 `program_frame()`；不得在提交后由新写指针反推旧地址。

若帧放不进扇区余量，关闭片段事务同时将 `write_addr` 前移到下一个扇区起点并持久化；余下的擦除字节不属于任何片段。长业务日志以多个帧保存，使用首帧、续帧、末帧标志关联，不能把一条大消息直接写成跨扇区的原始字节流。

## 7. 元数据、目录轮换与启动恢复

元数据和目录均为追加槽位；每个槽位独立两阶段提交。启动时验证 magic、版本、地址、offset、phase 和 CRC，选择 sequence 最新的有效元数据。sequence 比较可用 `(int32_t)(a - b) > 0`，但必须保证任意一次扫描中候选记录的序号跨度小于 `2^31`。

元数据银行的轮换流程如下：在另一已擦除银行写入最新完整状态并提交，再将其标记为活动银行，最后才擦除旧银行。目录压缩同理：向非活动目录银行写入银行头和当前有效 `ADD_FRAGMENT` 集合，提交新银行头；随后提交指向新 `catalog_generation` 的元数据；确认后才允许擦除旧目录银行。任一步掉电时，启动代码选择“由最新有效元数据引用且银行头有效”的银行；若切换处于中间状态，则完成或回退，绝不同时擦除两份副本。

启动恢复顺序必须固定：

1. 扫描元数据 A/B 银行；完全没有有效元数据时，**不得信任旧目录**，创建新的空目录代次和默认元数据，首写前回收日志起始扇区。
2. 加载元数据指定代次的目录，并重放已提交目录记录。
3. 若为 `META_CLOSE_PENDING`，检查 `entry_id` 是否已有相同有效条目；没有则追加 `ADD_FRAGMENT`，然后提交 `META_READY`。
4. 若为 `META_RECLAIM_PENDING`，确保 `DROP_SECTOR` 已生效，擦除目标扇区后提交 `META_READY`。擦除可重复执行。
5. 若为 `META_CLEAR_PENDING`，按保存的进度继续清空，完成后建立新的空目录和默认元数据。
6. `META_READY` 时，直接从 `write_addr` 继续。预留区域内即使存在半写帧也不会被再次写入；导出扫描会因提交标记或 CRC 不合法而跳过它。

默认状态至少应包含有效目录代次和日志起点，不能只把 `write_addr` 设为起点：

```c
static void meta_set_default(log_meta_t *m, uint32_t catalog_generation)
{
    memset(m, 0, sizeof(*m));
    m->phase = META_READY;
    m->sequence = 1u;
    m->catalog_generation = catalog_generation;
    m->write_addr = FLASH_LOG_START;
    m->frame_sequence = 1u;
    m->next_entry_id = 1u;
}
```

`magic` 和 `crc32` 由编码提交函数填入；不要在内存默认对象中提前把 `magic` 当作“已持久化”。

## 8. 读取、AT 命令与导出

查询层合并“目录重放得到的已关闭片段”和元数据中的当前片段。若二者 `entry_id` 相同，以目录中的已关闭片段为准，避免关闭事务掉电时重复导出。按日期查询时返回当天的全部片段；按 `entry_id` 查询时只导出该片段。

导出绝不能把扇区范围当作 C 字符串或原始连续 payload。应从 `begin_offset` 扫描到 `end_offset`：验证帧头、长度、提交标记和两类 CRC；有效帧发送显式长度的 payload 并跳过完整帧长；无效或擦除内容按 `LOG_FRAME_ALIGN` 前进，直到范围结束。这样可越过预留但未完成的帧，不会把半写字节传给上位机。

```c
static int export_fragment(const catalog_fragment_t *item)
{
    uint32_t off = item->begin_offset;

    while (off < item->end_offset) {
        log_frame_view_t frame;
        int rc = frame_decode_and_verify(item->sector_addr + off,
                                         FLASH_SECTOR_SIZE - off, &frame);
        if (rc == FRAME_VALID) {
            if (bsp_debug_send(frame.payload, frame.payload_len) != 0) return -1;
            off += frame.span;
        } else {
            off += LOG_FRAME_ALIGN; /* 可能是预留空洞或半写帧 */
        }
    }
    return 0;
}
```

`frame_decode_and_verify()` 必须先限制 `payload_len` 和 `frame.span` 不越过本扇区，再读 payload 和计算 CRC；不得使用头中的长度直接分配内存。`bsp_debug_send()` 需要返回状态，串口拥塞应由发送队列、超时或分片机制处理。

建议命令和返回格式如下。二进制日志不应直接拼进文本行；用长度字段后跟原始字节，或使用 Base64/CBOR 等明确编码。

| 命令 | 含义 | 示例响应 |
| --- | --- | --- |
| `AT+CATALOG?` | 列出有效片段 | `+CATALOG:37,2026-07-29,0x03412000,96,1840` |
| `AT+CATALOG=<entry_id>` | 导出指定片段；`0` 导出全部 | `+LOG:37,128,84\r\n<84 bytes>`，结束后 `OK` |
| `AT+RMLOG` | 请求可靠清空日志、目录和元数据 | `+RMLOG:IN_PROGRESS`，完成后 `OK` |

`AT+RMLOG` 必须由日志任务串行执行：停止接收新日志，先提交 `META_CLEAR_PENDING` 和进度，再逐扇区擦除日志区、重建空目录银行、写入新的默认元数据，最后擦除旧元数据银行并恢复接收。中途掉电时启动恢复继续清空；不能采用“依次擦完所有区域，最后才写默认元数据”的非事务流程。

## 9. 与调试输出集成

日志格式化使用 `vsnprintf()`，禁止 `vsprintf()`。格式化失败、截断和 Flash 持久化失败必须传回调用方；串口调试发送失败可以单独统计，不得回滚已经提交的 Flash 状态。

```c
#include <stdarg.h>

int log_format(uint8_t level, const char *fmt, ...)
{
    char payload[256];
    va_list ap;
    va_start(ap, fmt);
    int n = vsnprintf(payload, sizeof(payload), fmt, ap);
    va_end(ap);

    if (n < 0 || (size_t)n >= sizeof(payload)) return -1;

    int persist_rc = 0;
    if (log_should_persist(level)) {
        persist_rc = system_log_write((const uint8_t *)payload, (uint32_t)n);
    }
    if (log_console_enabled(level)) {
        (void)bsp_debug_send((const uint8_t *)payload, (uint32_t)n);
    }
    return persist_rc == 0 ? n : persist_rc;
}
```

`log_should_persist()` 和 `log_console_enabled()` 应明确等级语义，避免依赖未说明的数值大小关系。生产环境应设定队列容量、丢弃策略、写入最长时间和 Flash 忙重试上限；中断上下文只能投递固定大小事件，不能格式化、等待互斥锁或执行擦除。

## 10. 验证清单

- 首次上电、两份元数据都损坏、目录银行头损坏：不得导出旧目录；系统应建立新的空目录代次并从日志区起点安全开始。
- 单帧跨 Flash 页、帧恰好填满扇区、扇区余量不足、写到日志区末尾、下一帧回绕到起点，以及业务消息拆成多帧。
- 同一天跨多个扇区、跨回绕；跨日期但仍位于同一扇区；RTC 回拨后再次出现同一日期。
- 回收一个旧扇区后：该扇区所有目录片段被删除，其他扇区中同日期的片段仍可导出；当前元数据不得再指向该扇区的旧范围。
- 分别在“预留元数据提交前后”“帧头写入中”“payload 写入中”“帧 magic 写入前后”“关闭片段事务三步之间”“目录银行切换中”“回收事务各步骤之间”掉电，再启动核对恢复结果。
- 篡改 magic、版本、sequence、地址、offset、长度、头 CRC、payload CRC 和目录操作字段；系统应跳过损坏记录并继续工作。
- `AT+RMLOG` 在每个擦除进度点掉电，启动后应自动完成清空，且在完成前不接收普通日志写入。
- 长时间压力测试：统计各日志扇区、目录银行和元数据银行的擦除次数，确认轮换符合芯片擦写寿命和日志量预算。

该设计保留“元数据 + 目录 + 环形数据区”的原有核心结构，但将索引边界、提交顺序、掉电恢复和银行轮换落实为可执行状态机。它的结果是：目录不会指向已擦除数据，半写帧不会阻塞后续写入或被错误导出，且同一天的有效日志不会因回收其中一个扇区而整体丢失。
