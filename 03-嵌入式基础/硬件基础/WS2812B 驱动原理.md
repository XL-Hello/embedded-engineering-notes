# WS2812B 驱动原理

> 目标：只分析 WS2812B 如何被驱动，不绑定某个具体项目、芯片平台或代码实现。重点从数据流角度理解：应用层的 RGB 颜色，如何一步步变成 WS2812B 能识别的单线时序波形。
>
> 核心结论：**WS2812B 不是通过寄存器配置颜色，而是通过 DIN 数据线上一串严格定时的高低电平脉冲接收颜色数据。**

## 1. 一句话理解 WS2812B

**WS2812B 是一颗内置控制 IC 的 RGB LED，通过一根 `DIN` 数据线接收颜色数据，每颗灯通常接收 24 bit：8 bit Green、8 bit Red、8 bit Blue。**

它与 I2C、SPI、UART 的主要区别是：没有设备地址、寄存器、独立时钟线和 ACK，仅靠一个 bit 周期内高低电平的持续时间区分 `0` 和 `1`。

```text
+-------------+      DIN       +-----------+ DOUT  +-----------+ DOUT
| MCU / SoC   | -------------->| WS2812B 1 | ----> | WS2812B 2 | ----> ...
+-------------+                +-----------+       +-----------+
```

第一颗灯接收最前面的 24 bit；从第 25 bit 开始，后续数据经内部整形后由 `DOUT` 输出给下一颗灯。每经过一颗灯，数据流中的像素位置就向后移动一组 24 bit。

## 2. WS2812B 需要什么数据

应用层通常使用 `RGB`，但 WS2812B 常见的线上顺序是 `GRB`，并且每个字节高位在前：

```text
G7 G6 G5 G4 G3 G2 G1 G0
R7 R6 R5 R4 R3 R2 R1 R0
B7 B6 B5 B4 B3 B2 B1 B0
```

```text
1 颗灯 = 8 bit Green + 8 bit Red + 8 bit Blue = 24 bit
N 颗灯 = N × 24 bit
```

实际器件也可能存在 RGB、RGBW 等变体，因此颜色通道数和顺序最终应以具体型号的数据手册为准。

数据转换过程如下：

```text
应用层 RGB 颜色数组
        |
        v
按器件要求重排为 GRB
        |
        v
每个字节按 MSB first 展开
        |
        v
把每个 bit 编码成定时脉冲
```

## 3. 底层原理：用脉冲宽度表示 0 和 1

WS2812B 判断 bit 值时，看的不是静态电平，而是一个 bit 周期内高、低电平分别持续多久：

| bit 值 | 高电平 | 低电平 | 含义 |
| --- | --- | --- | --- |
| `0` | 短 | 长 | 高电平占比较小 |
| `1` | 长 | 短 | 高电平占比较大 |

```text
bit 0:  ┌──┐________
________┘  └________    高短、低长

bit 1:  ┌──────┐____
________┘      └____    高长、低短
```

所以驱动的本质不是“发送普通字节”，而是：

```text
把每一个颜色 bit 翻译成一个时序满足要求的高低电平脉冲。
```

## 4. 完整数据流示例

以红色 `R=255、G=0、B=0` 为例：

```text
应用层 RGB
  R=0xFF, G=0x00, B=0x00
        |
        v
重排为 GRB
  G=0x00, R=0xFF, B=0x00
        |
        v
展开为 24 bit
  00000000 11111111 00000000
        |
        v
0 -> 高短低长，1 -> 高长低短
        |
        v
DIN 输出连续脉冲
        |
        v
灯珠解码并暂存颜色
        |
        v
reset 低电平后锁存到 PWM 输出
```

传输 24 bit 时，灯珠先接收并暂存数据；发送完全部灯珠的数据后，主控保持足够长的低电平，所有灯珠再锁存并更新显示。

## 5. 多颗灯级联时的数据流

主控发送的不是带地址的数据包，而是整条灯带的连续颜色数据：

```text
[LED1 的 GRB 24 bit][LED2 的 GRB 24 bit][LED3 的 GRB 24 bit]...
```

每颗灯可以按下面的逻辑理解：

1. 从 `DIN` 接收数据。
2. 截取最前面的 24 bit，暂存为自己的颜色。
3. 从第 25 bit 开始，把后续波形整形后从 `DOUT` 输出。
4. reset 低电平到来后，锁存自己的颜色并更新内部 PWM。

因此，第几颗灯显示什么颜色取决于它在数据流中的位置，而不是地址：

```text
发送顺序： [颜色1][颜色2][颜色3][颜色4]
显示结果：  LED1   LED2   LED3   LED4
```

即使只改变第 10 颗灯，通常也要维护完整的像素缓冲区并重新发送整帧，否则前面的灯珠仍会按顺序截取数据。

## 6. reset/latch 低电平的作用

发送完一帧后，主控必须让数据线持续保持低电平。它的作用是：

- 标记本帧结束，并让接收逻辑回到下一帧起点。
- 将各灯珠暂存的颜色锁存到内部 PWM 输出。
- 让整条灯带近似同时更新显示。

不同版本和兼容器件的 reset 要求可能不同，必须以实际器件数据手册为准。以 WS2812B V5 为例，复位低电平要求大于 `280 us`，工程上还应留出余量。

```text
连续发送 N 颗灯的颜色脉冲
        |
        v
保持足够长的低电平
        |
        v
所有灯珠锁存并显示新颜色
```

若低电平不足，可能无法可靠锁存；若传输过程中意外出现长到足以触发 reset 的低电平，则当前帧会被提前截断，后续数据会被当成新帧。

## 7. 亮度如何体现

每个颜色通道通常为 8 bit，取值为 `0~255`。该数值写入灯珠后，由内部 PWM 转成相应占空比：

```text
R = 255 -> 红色通道接近最大占空比
R = 128 -> 红色通道占空比约为一半
R = 0   -> 红色通道关闭
```

人眼对亮度的感知不是线性的，因此 `128` 虽约对应一半 PWM 占空比，视觉上不一定是 `255` 的一半亮。需要平滑调光时，通常在发送前进行 gamma 校正。

```text
颜色数值
  -> GRB 24 bit
  -> DIN 定时脉冲
  -> 内部锁存
  -> 内部 PWM
  -> RGB 发光强度
```

## 8. 主控如何产生 WS2812B 波形

无论使用哪种 MCU，数据处理都相同：先把颜色数组整理成 GRB bit 流，再选择能够稳定控制脉冲宽度的波形生成方式。

WS2812B 常见的单 bit 周期约为 `1.25 us`。下表仅用于理解，实际数值和容差必须以具体器件版本的数据手册为准：

| 符号 | 高电平 | 低电平 | 总时间 |
| --- | ---: | ---: | ---: |
| `0` | 约 `0.4 us` | 约 `0.85 us` | 约 `1.25 us` |
| `1` | 约 `0.8 us` | 约 `0.45 us` | 约 `1.25 us` |
| reset/latch | - | WS2812B V5 要求低电平 `> 280 us` | - |

### 8.1 CPU 直接翻转 GPIO

CPU 按 bit 拉高、等待、拉低、再等待。这种方式最直观，但函数调用、中断、任务切换和动态时钟都可能破坏亚微秒级时序，通常只适合学习、验证或少量灯珠。

```c
for each pixel in pixels {
    bytes = { pixel.green, pixel.red, pixel.blue };

    for each byte in bytes {
        for bit from 7 down to 0 {
            if (byte & (1 << bit))
                output_waveform(T1H, T1L);
            else
                output_waveform(T0H, T0L);
        }
    }
}

drive_data_low();
wait_reset_time();
```

`output_waveform()` 必须使用可预测的周期计数或硬件定时机制，不能直接使用毫秒级操作系统延时。纯数据发送时间约为：

```text
LED 数量 × 24 bit × 1.25 us
```

例如 100 颗灯约需 `3 ms`；若整个过程都禁止抢占，会明显影响系统实时性。

### 8.2 专用脉冲或波形外设

许多 MCU 提供能够描述“某个电平持续多少 tick”的外设。可把 bit `0` 和 bit `1` 分别编码为两个电平段，再通过缓冲区或 DMA 连续输出：

```text
GRB bit 流
  -> 0/1 脉冲符号
  -> 外设缓冲区或 DMA
  -> 硬件按 tick 输出
  -> WS2812B DIN
```

这种方式的边沿时序主要由硬件保证，不容易受任务调度影响。灯珠较多时仍需检查外设缓冲容量、DMA 支持以及续传过程中是否会出现异常间隙。

### 8.3 SPI 波形编码

WS2812B 不是 SPI 设备，但可以只利用 SPI 数据输出脚产生稳定波形。例如选择合适的 SPI 时钟后，将每个 WS2812B bit 扩展为多个 SPI bit：

```text
WS2812B bit 0 -> SPI bits 100 -> 高 1 拍，低 2 拍
WS2812B bit 1 -> SPI bits 110 -> 高 2 拍，低 1 拍
```

若 SPI 时钟为 `2.5 MHz`，每拍约 `0.4 us`，三个 SPI bit 约为 `1.2 us`。`100` 形成高短低长，`110` 形成高长低短。关键不在于固定使用这组参数，而在于编码后的实际波形必须满足目标器件的数据手册容差。

```text
RGB -> GRB 24 bit -> SPI 扩展编码 -> DMA/SPI 数据输出 -> WS2812B DIN
```

具体 SPI 外设能否与其他设备共享，取决于驱动对总线和引脚的占用方式，不能仅凭“WS2812B 没有 CS”作绝对判断。

## 9. SPI 模拟方式的数据膨胀

若采用 `0 -> 100`、`1 -> 110`，一个 WS2812B bit 会变成 3 个 SPI bit：

```text
1 颗灯原始颜色数据：24 bit = 3 byte
1 颗灯 SPI 波形数据：24 × 3 = 72 bit = 9 byte
```

例如颜色字节 `0xA5`：

```text
原始 bit：10100101
扩展后：  110 100 110 100 100 110 100 110
```

WS2812B 不知道这些波形由 SPI 产生，它只看到高低电平的持续时间是否满足协议要求。

## 10. 为什么 WS2812B 对时序敏感

WS2812B 没有独立时钟线，只能根据 DIN 的高低电平宽度判断 bit 值。时序不准可能造成：

- 高电平太短，`1` 被误判成 `0`。
- 高电平太长，`0` 被误判成 `1`。
- 高、低电平落入无效区间，产生误码。
- 帧内低电平过长，提前触发 reset，截断当前帧。
- 帧尾 reset 不足，数据不能可靠锁存。
- 软件发送被中断打断，整条灯带显示异常。

因此，驱动 WS2812B 的关键不是“把字节发出去”，而是保证每个 bit 的实际波形都处于允许的时序范围内。

## 11. 常见排查思路

| 现象 | 可能原因 | 排查重点 |
| --- | --- | --- |
| 完全不亮 | 供电、共地、DIN 方向、电平或波形错误 | 电源、地线、数据方向、示波器波形 |
| 颜色通道错乱 | RGB/GRB 顺序不匹配 | 检查器件型号和颜色排列 |
| 只有第一颗正常 | DOUT/DIN 接反、后级供电或数据长度错误 | 级联方向、焊点、发送字节数 |
| 随机闪烁 | 时序抖动、中断干扰、供电不足 | 脉宽、电源纹波、退耦和地线 |
| 后面灯颜色错位 | 少发/多发 bit，或帧内出现异常长低电平 | 整帧长度、连续性和中断干扰 |
| 刷新不稳定 | reset 不足或波形超出容差 | 帧尾低电平和实际脉宽 |
| 亮度异常 | 通道数值、亮度缩放或供电限流 | RGB 数值、gamma、最大电流 |

排查时应沿数据流反向检查：颜色数组 → GRB 排列 → bit 展开 → 实际 DIN 波形 → 级联方向 → reset → 内部 PWM。

## 12. 关键结论

```text
应用层 RGB 颜色
  -> 可选的亮度缩放或 gamma 校正
  -> 按器件要求重排为 GRB
  -> 每个字节按高位在前展开
  -> 每个 bit 编码为定时脉冲
  -> DIN 连续输出整帧
  -> 每颗灯截取自己的 24 bit
  -> reset 低电平锁存
  -> 内部 PWM 控制 RGB 发光
```

- 数据层：每颗 WS2812B 通常为 24 bit，常见顺序是 GRB。
- 协议层：`0` 和 `1` 由高低电平持续时间区分。
- 传输层：只有单线 DIN，没有地址、寄存器、独立时钟和 ACK。
- 级联层：每颗灯截取前 24 bit，从第 25 bit 起将后续波形整形后输出。
- 显示层：reset 后锁存数据，内部 PWM 根据颜色值控制亮度。

所以，驱动 WS2812B 的本质就是：**把 RGB 颜色数组转换成满足器件时序要求的单线脉冲流。**
