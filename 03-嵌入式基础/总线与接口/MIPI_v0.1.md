# MIPI 基础知识总结

> 目标：这篇文档只作为 MIPI 入门和项目面试复习使用，不展开高速硬件布线、信号完整性等复杂内容。重点记住：MIPI 是什么、CSI 和 DSI 有什么区别、DSI 怎么把画面送到屏幕、常见问题怎么排查。
>
> 来源：围绕MIPI主题跟AI多轮对话后的总结文档，仅供参考。

## 第一章、先用一句话理解 MIPI

**MIPI 不是某一种屏幕接口，而是 MIPI 联盟制定的一系列移动设备接口标准的总称，其中显示和摄像头场景常用的是高速串行接口。**

在嵌入式图像和显示项目里，最常见的是下面两类：

| 名称 | 主要方向 | 通俗理解 | 常见用途 |
| --- | --- | --- | --- |
| `MIPI CSI-2` | 常见为 Sensor TX → SoC RX | 摄像头把图像送进芯片 | 摄像头、扫码、车载摄像、工控采集 |
| `MIPI DSI` | 常见为 SoC Host → 显示 Peripheral | 主控把画面送到屏幕 | 手机屏、智能硬件屏、车载屏、穿戴屏 |

简单记法：

- `CSI`：Camera Serial Interface，按典型系统用途偏 **摄像头输入**；CSI-2 接口包含发送端（TX）和接收端（RX）。
- `DSI`：Display Serial Interface，按典型系统用途偏 **屏幕输出**；DSI 接口包含 Host 和 Peripheral。
- 二者经常使用同一类底层物理层，例如 `D-PHY`，但上层协议和数据包格式不同。

“摄像头输入/显示输出”是按典型系统用途对主控侧数据流的概括：CSI-2 图像链路在一次连接中固定为 TX 到 RX，摄像头寄存器控制通常走独立的 CCI（如 I²C/I3C）；DSI 的主数据流通常为 Host 到 Peripheral，也可通过 LP 下的 BTA 做读回等有限反向控制，但并非双向同时传输视频数据。

> 注意：不要简单说“CSI 和 DSI 硬件完全一样，可以随便切换”。实际能不能复用，要看芯片手册和 SoC 内部设计。有些芯片 CSI/DSI 是独立资源，有些芯片会共享 PHY、PLL、Lane 或时钟资源。

## 第二章、MIPI DSI 在显示项目里做什么

以 LCD 显示为例，MIPI DSI 的工作可以理解为：

1. 应用层或 UI 框架绘制界面，通过 CPU/GPU 渲染并写入 framebuffer。
2. 显示控制器读取 framebuffer 中的像素数据（Video Mode 下按行场时序持续读取，Command Mode 下在需要更新时读取），DSI 控制器再将像素数据和控制命令打包。
3. 数据通过 MIPI Lane 发送到屏幕驱动 IC。
4. 屏幕驱动 IC 解析数据，再驱动 LCD/OLED 面板显示。

也就是说，MIPI DSI 并不是自己“画图”，它更像一条高速通道：

- 上层负责准备图像。
- DSI 负责按协议发送图像和命令。
- 屏幕驱动 IC 负责接收并刷新屏幕。

## 第三章、本项目中的 MIPI 关系

从项目总结和代码看，本项目关注的是 **MIPI DSI 屏幕显示**，不是 MIPI CSI 摄像头输入。

以下以本项目采用 D-PHY 的 MIPI DSI 2-Lane 为例。信号名称为原理图中的常见命名：

| 信号 | 类别 | 含义 |
| --- | --- | --- |
| `MIPI_CLKP / MIPI_CLKN` | D-PHY 信号 | DSI 时钟差分线 |
| `MIPI_D0P / MIPI_D0N` | D-PHY 信号 | DSI 数据 Lane 0 |
| `MIPI_D1P / MIPI_D1N` | D-PHY 信号 | DSI 数据 Lane 1 |
| `LCD_RST` | 面板辅助控制信号 | 屏幕复位脚，不属于 DSI 数据链路 |

部分面板还会引出 `TE`（Tearing Effect）信号，由面板输出给主控，用于 Command Mode 局部刷新时的撕裂同步；是否使用要看面板和项目设计。

如果说本项目是 `MIPI DSI 2-Lane`，意思就是：

- 有 1 组时钟 Lane。
- 有 2 组数据 Lane。
- 两条数据 Lane 一起传图像数据，带宽比 1-Lane 更高。

面试时可以这样说：

> 本项目 LCD 使用 MIPI DSI 2-Lane 接口。主控通过 DSI 控制器把屏幕初始化命令和 framebuffer 中的像素数据封装成 DSI 数据包，再通过一组时钟 Lane 和两组数据 Lane 发送给屏幕驱动 IC。2-Lane 的好处是在引脚数量不多的情况下提供更高显示带宽。

## 第四章、D-PHY 的 HS 和 LP 模式

MIPI D-PHY 常见两种工作状态：`HS` 和 `LP`。

| 模式 | 全称 | 通俗理解 | 主要用途 |
| --- | --- | --- | --- |
| `HS` | High Speed | 高速模式，跑大数据 | 传输整帧图像、视频流、像素数据 |
| `LP` | Low Power | 低功耗模式，跑小数据 | 常用于初始化、寄存器配置、休眠唤醒、状态切换 |

### 4.1、HS 高速模式

`HS` 模式主要用来传输大量数据。

特点：

- 使用差分信号，抗干扰能力更好。
- 速度高，适合传图像和视频。
- 功耗相对更高。
- 一般在真正传输像素数据时使用。

直白理解：

> 需要快速搬运一整屏图像时，就进入 HS 模式。

### 4.2、LP 低功耗模式

`LP` 模式主要用来传输少量控制信息。

特点：

- 使用 1.2 V 单端信号（P/N 两线各自独立驱动），不是差分信号，速率通常不超过 10 Mbps。
- 速度低，但功耗小。
- 常用于屏幕初始化命令、状态切换、休眠唤醒等低速控制传输。
- DSI 的读操作（读 ID、读寄存器）通过数据 Lane 0 在 LP 下做总线反向（BTA）完成；在 DSI 链路中，Lane 0 用于这类有限的反向读回。
- 不适合传大量像素数据。

直白理解：

> 不需要大量传图像时，就用 LP 模式省电；发一些小命令也够用。

具体命令使用 LP 还是 HS 传输，还要以屏幕规格书和 DSI 控制器配置为准。

## 第五章、DSI 的 Command Mode 和 Video Mode

DSI 显示常见两种工作方式：`Command Mode` 和 `Video Mode`。

| 模式 | 通俗理解 | 优点 | 缺点 | 常见场景 |
| --- | --- | --- | --- | --- |
| `Command Mode` | 主控像“发命令”一样更新屏幕 | 适合局部刷新，静态界面省电 | 大面积连续刷新时需要频繁发送命令和像素数据，带宽利用与刷新时序协调通常不如 Video Mode 直接 | 手表、仪表、小屏 UI、RTOS 静态界面 |
| `Video Mode` | 主控持续不断把整帧画面送给屏幕 | 全屏刷新稳定，适合动态画面 | 常规配置下静态画面也会按帧时序传输，通常功耗更高 | 视频播放、高清 LCD、动态 UI |

### 5.1、Command Mode

`Command Mode` 可以理解为：屏幕自己有一定的缓存能力，主控不一定每一刻都持续发送整屏画面。

它适合：

- 静态页面多。
- 局部刷新多。
- 比较关注功耗。
- 屏幕尺寸不大或 UI 变化不频繁。

直白说法：

> 若面板具备 GRAM 并支持地址窗口等命令，Command Mode 可以只发送需要更新区域的像素数据；实际局部刷新能力还取决于面板和驱动实现。

### 5.2、Video Mode

`Video Mode` 可以理解为：主控像视频流一样持续输出画面，屏幕按照固定节奏接收和显示。

它适合：

- 全屏刷新频繁。
- 画面变化多。
- 对刷新率和流畅度要求高。
- 视频、动画、复杂 UI 场景。

直白说法：

> Video Mode 更像“主控一直给屏幕喂完整画面”。

### 5.3、两种模式没有绝对好坏

不要简单说 Command Mode 一定好，或者 Video Mode 一定好。

更准确的说法是：

- 静态、低功耗、局部刷新：优先考虑 `Command Mode`。
- 动态、视频、全屏刷新：优先考虑 `Video Mode`。
- 成本：Command Mode 面板端通常需要完整 GRAM（或等效帧存储），会增加显示驱动 IC 的面积和成本；Video Mode 面板通常无需完整帧缓存，面板端成本可能更低；实际以面板规格和厂商方案为准。
- 最终还是要看屏幕 IC、SoC DSI 控制器、驱动配置和产品需求。

Video Mode 在常规配置下通常功耗较高；若平台支持降低刷新率或其他省电机制，还应结合具体实现判断。

在项目代码中，也能看到类似 `CONFIG_DSI_VIDEO_MODE` 的配置分支：

- 如果定义了 `CONFIG_DSI_VIDEO_MODE`，就走 `DSI_VIDEO_MODE`。
- 否则通常走 `DSI_COMMAND_MODE`。

这说明模式不是口头决定的，而是会落实到驱动配置里。

## 第六章、CSI-2 和 RAW 数据

这一部分主要用于理解摄像头输入，不是本项目显示屏的重点，但面试中经常会问。

### 6.1、RAW8 / RAW10 / RAW12 是什么

`RAW8`、`RAW10`、`RAW12` 通常表示每个原始颜色采样值的位宽。

| 格式 | 含义 | 通俗理解 |
| --- | --- | --- |
| `RAW8` | 每个原始颜色采样值 8 bit | 数据少，画质层次相对少 |
| `RAW10` | 每个原始颜色采样值 10 bit | 比 RAW8 能表达更多亮度层次 |
| `RAW12` | 每个原始颜色采样值 12 bit | 层次更细，但数据量更大 |

位宽越高：

- 可表示更多量化等级和亮度层次。
- 实际动态范围还取决于 Sensor 的满阱容量、读出噪声、模拟增益和 ADC 等设计。
- 传输带宽和存储压力也更大。

注意：`RAW10`、`RAW12` 在 MIPI 中通常会做 **数据打包**，把多个像素紧凑地塞进字节流里。例如 CSI-2 中 RAW10 是每 4 个像素占 5 字节（4 个字节存高 8 位，1 个字节存放 4 组低 2 位），RAW12 是每 2 个像素占 3 字节。这里更准确叫“打包”，不要说成“压缩”。压缩一般意味着可以用算法减少信息量，而 RAW 打包只是改变数据排列方式。

### 6.2、为什么 Sensor 常输出 RAW，而不是直接输出 RGB

摄像头 Sensor 最原始采集到的通常不是完整 RGB 图像，而是 Bayer 格式的原始亮度/颜色采样数据。

要变成最终能看的 RGB 图像，还需要 ISP 处理，例如：

- 去马赛克。
- 白平衡。
- 降噪。
- 锐化。
- HDR。
- 色彩校正。

所以很多系统让 Sensor 输出 RAW，再交给主控 SoC 的 ISP 处理。

好处是：

- 原始信息保留更多，后期可调空间大。
- 可将主要 ISP 处理放在主控侧，主控 ISP 通常算力和算法资源更充足，也便于统一调参。

直白说法：

> Sensor 输出 RAW，就像把“原材料”交给主控。主控的 ISP 再负责加工成最终图片。是否降低成本或功耗，以及可调空间的大小，还要结合 Sensor 是否集成 ISP 和系统架构判断。

## 第七章、CSI 和 DSI 能不能同时用

这个问题不能只看协议名字，要看芯片硬件资源。

### 7.1、可以同时用的情况

如果 SoC 内部有独立的 CSI PHY 和 DSI PHY，或者资源设计上支持并发，那么可以一边接摄像头输入，一边接屏幕输出。

例子：

- 摄像头采集图像。
- 主控处理图像。
- DSI 屏幕实时显示结果。

### 7.2、不能同时用的情况

如果 CSI 和 DSI 共享同一个 PHY、PLL、Lane 或者电源域，就可能只能二选一，或者只能分时复用。

这种情况下要注意：

- CSI 配置可能会影响 DSI。
- DSI 下电可能会影响 CSI。
- 时钟、复位、Lane 配置不能互相覆盖。

直白说法：

> CSI 和 DSI 能不能一起跑，不是协议说了算，而是芯片资源说了算。

## 第八章、驱动里容易出问题的资源

做 MIPI 驱动时，常见问题不是“协议概念不会”，而是资源配置互相影响。

常见风险：

- **PHY 配置冲突**：CSI 和 DSI 如果共用 PHY，不能随便重新初始化。
- **PLL/时钟冲突**：一个模块改时钟，可能影响另一个模块。
- **Lane 数量不匹配**：屏幕要求 2-Lane，驱动配成 1-Lane，就可能显示异常。
- **像素格式不匹配**：例如屏幕要 `RGB888`，驱动却按 `RGB565` 发，容易色彩异常。
- **功耗管理错误**：一边还在用，另一边把电源域关掉，会导致链路挂掉。
- **带宽不够**：摄像头输入、屏幕输出、DDR 访问同时很高时，可能丢帧或卡顿。

## 第九章、屏幕花屏、横纹、闪屏怎么排查

排查顺序建议从软件上层往底层看，先排除简单问题，再怀疑硬件。

### 9.1、先确认是不是应用画错了

做法：

- 显示全屏纯色：红、绿、蓝、白、黑。
- 显示简单色块或测试图。
- 看异常是全屏都有，还是只有某个控件区域有。

判断：

- 只有局部控件异常：更像 UI 或绘图问题。
- 全屏颜色、位置、行列都异常：更像 framebuffer、DSI 或屏参数问题。

### 9.2、再确认 framebuffer 是否正确

检查点：

- framebuffer 中的数据是否正常。
- 分辨率是否正确。
- stride 是否正确。
- 像素格式是否正确。

常见错误：

- `RGB565` 和 `RGB888` 配错。
- 行跨度 stride 算错。
- 宽高或旋转方向不一致。

### 9.3、核对屏幕基础参数

重点看：

- 分辨率。
- 刷新率。
- Lane 数量。
- 像素格式。
- Command/Video 模式。
- DSI 时钟和单 Lane 速率。
- 若使用 Video Mode，还要看 porch、sync 等行场时序参数。

这些参数必须和屏幕规格书、屏幕初始化代码一致。

### 9.4、核对屏幕初始化命令

很多屏幕显示异常，最后都是初始化命令不对。

重点看：

- 上电时序是否满足要求。
- 复位脚拉高/拉低时间是否正确。
- `sleep out` 后延时是否足够。
- 像素格式设置是否正确。
- 显示开关命令是否发送。
- 厂商给的初始化表是否漏命令或顺序错误。

### 9.5、看日志和错误状态

可以通过日志检查：

- DSI 发送命令是否失败。
- PHY 是否进入异常状态。
- 是否有 ECC、CRC、timeout、underrun 等链路或控制器错误。
- 若使用 Command Mode 局部刷新，TE 同步信号与刷新时机是否正确。

### 9.6、降低速率做对比

如果画面有横纹、闪屏、偶发花屏，可以尝试：

- 降低 DSI 时钟。
- 降低刷新率。
- 减小分辨率或测试小图。
- 改成简单纯色画面。

如果降速后变稳定，通常说明原配置接近或超过链路能力，或者时序余量不够。

## 第十章、面试常见问法和直白回答

### 10.1、MIPI 是什么

> MIPI 是 MIPI 联盟制定的一系列接口标准的总称，不是单纯的屏幕接口。其中显示常用 DSI，摄像头常用 CSI-2。它的优势是引脚少、速度高，适合手机、智能硬件、车载和嵌入式显示/图像场景。

### 10.2、CSI 和 DSI 有什么区别

> CSI-2 主要用于摄像头输入，常见为 Sensor 的 TX 到主控 RX，图像高速数据链路为单向；DSI 主要用于屏幕输出，常见为主控 Host 到屏幕 Peripheral，且可通过 LP/BTA 做有限读回。它们底层可能都用 D-PHY，但上层协议和数据包不同。

### 10.3、HS 和 LP 有什么区别

> HS 是高速模式，用来传大量图像数据；LP 常用于初始化、控制、休眠唤醒等低速传输。具体命令使用 LP 还是 HS，要看屏幕规格书和控制器配置。简单说，搬大画面通常用 HS，发小命令常用 LP。

### 10.4、Command Mode 和 Video Mode 有什么区别

> Command Mode 更适合静态界面和局部刷新，省电；常见实现会在面板端配置完整 GRAM，成本可能更高。Video Mode 更适合持续全屏刷新和视频画面，常可采用流式显示而无需完整帧缓存。具体仍以面板规格和厂商实现为准，选型还要看主控能力、功耗、成本和产品需求。

### 10.5、Sensor 为什么通常输出 RAW

> Sensor 采到的是比较原始的 Bayer 数据，还不是最终 RGB 图片。输出 RAW 后，主控 ISP 可以做白平衡、降噪、HDR、色彩校正等处理，画质可调空间更大。

### 10.6、屏幕花屏怎么排查

> 先显示纯色图，判断是不是应用绘图问题；再检查 framebuffer、分辨率、stride、像素格式；然后核对 Lane 数、DSI 模式、时钟、时序和初始化命令；最后看 DSI/PHY 日志，必要时降速测试。

## 第十一章、高频易错点

| 错误说法 | 更准确的说法 |
| --- | --- |
| MIPI 就是屏幕接口 | MIPI 是一套标准，DSI 才是显示接口，CSI 是摄像头接口 |
| CSI 和 DSI 完全一样 | 它们可能共用 D-PHY，但上层协议不同，硬件是否复用要看 SoC |
| RAW10/RAW12 是压缩 | 更准确叫打包，不是压缩算法 |
| Command Mode 一定比 Video Mode 好 | 没有绝对好坏，按场景选 |
| Video Mode 一定不适合低功耗 | 常规配置下通常功耗更高；是否可省电还要看屏幕、刷新率和驱动策略 |
| CSI、DSI 协议数据都是双向的 | CSI-2 图像数据链路是单向 TX→RX；DSI 可用 LP/BTA 做有限反向控制 |
| Sensor 直接输出 RGB 画质一定更好 | RAW 保留原始信息，交给 ISP 后可调空间更大 |
| 所有芯片都能 CSI + DSI 同时工作 | 要看 PHY、Lane、PLL、电源域是否独立 |

## 第十二章、最简记忆版

只想快速记住，可以背下面几句：

- MIPI 是高速串行接口标准，不是单独的显示接口。
- `CSI-2` 管摄像头输入，`DSI` 管屏幕输出。
- `D-PHY` 里 `HS` 负责高速传图像；`LP` 常用于低功耗控制传输，具体命令模式看屏幕和驱动配置。
- `Command Mode` 适合静态、局部刷新、省电场景。
- `Video Mode` 适合动态、视频、全屏连续刷新场景。
- `RAW8/10/12` 表示原始颜色采样位宽；位宽更高可表示更多亮度层次，带宽压力也更大。
- 屏幕异常先查应用和 framebuffer，再查屏参数、初始化、时钟、Lane、日志。
