# I2C 基础知识总结

> 目标：这篇文档只作为 I2C 入门和项目面试复习使用，不展开复杂的硬件电气设计、信号完整性和芯片内部控制器实现。重点记住：I2C 是什么、SCL/SDA 怎么工作、设备地址和读写流程、ACK/NACK 的意义、常见问题怎么排查。
>
> 来源：围绕I2C主题跟AI多轮对话后的总结文档，仅供参考。

## 1. 先用一句话理解 I2C

**I2C 是一种两线制、主从式、半双工的串行通信总线。**

结构可以先按下面这张图理解：一个主机通过同一组 `SCL` / `SDA` 线访问多个 I2C 设备，每个设备靠自己的地址被选中。

```text
                 VCC
                  |
             上拉电阻
          +-------+-------+
          |               |
主机/Master            I2C 总线
+-----------+      SCL  =====================+==========+==========+
| MCU / SoC |      SDA  =====================+==========+==========+
+-----------+                              |          |          |
                                           |          |          |
                                      +----+----+ +---+----+ +---+----+
                                      | 设备1  | | 设备2 | | 设备3 |
                                      | 0x50  | | 0x68 | | 0x3C |
                                      +-------+ +------+ +------+
                                      EEPROM   传感器    屏幕/触摸IC
```

> 关键点：`SCL` 和 `SDA` 是所有设备共享的两根线；主机发起访问并提供时钟，从设备根据地址判断这次通信是不是发给自己。

它最典型的特点是：

- 只需要两根信号线：`SCL` 和 `SDA`。
- 一条总线上可以挂多个从设备。
- 通过设备地址区分不同从设备。
- 适合低速、短距离、板级芯片之间通信。

常见用途：

| 用途 | 常见器件 |
| --- | --- |
| 传感器配置和读取 | 温湿度、光感、加速度计、陀螺仪 |
| 电源管理 | PMIC、电池管理芯片、充电芯片 |
| 显示相关 | 触摸 IC、背光芯片、屏幕配置 |
| 存储器 | EEPROM |
| 音频和外设配置 | Codec、IO 扩展芯片 |

简单记法：

- `SCL`：Serial Clock，时钟线，由主机提供时钟。
- `SDA`：Serial Data，数据线，用来传输地址、数据和应答。
- `Master`：主机，发起通信、产生时钟。
- `Slave`：从机，被主机通过地址访问。

## 2. I2C 在嵌入式项目里做什么

I2C 通常不是用来传输大块高速数据，而是用来做 **配置、控制和少量数据读取**。

以读取一个传感器寄存器为例，I2C 的工作可以理解为：

1. 主控发起起始信号。
2. 主控发送从设备地址。
3. 从设备地址匹配后返回 ACK。
4. 主控发送要访问的寄存器地址。
5. 主控重新发起读操作。
6. 从设备把寄存器数据返回给主控。
7. 主控发送 NACK 并结束通信。

也就是说，I2C 更像一条低速控制通道：

- 主控负责发起访问。
- 从设备负责响应地址。
- 双方按照时钟节拍在 SDA 上交换数据。
- 每传完一个字节，接收方要通过 ACK/NACK 告诉对方是否继续。

## 3. SCL 和 SDA 为什么需要上拉电阻

I2C 的 SCL 和 SDA 通常是 **开漏输出** 或 **开集输出** 结构。

这意味着：

- 设备可以主动把总线拉低。
- 设备不能主动把总线强推成高电平。
- 高电平依靠外部或内部上拉电阻拉起来。

这样设计的好处是：多个设备可以安全地共享同一条总线。

如果两个设备同时操作 SDA：

- 任意设备拉低，总线就是低电平。
- 没有设备拉低时，总线才会被上拉成高电平。

直白理解：

> I2C 总线上的设备主要负责“拉低”，高电平交给上拉电阻恢复。这样多个设备挂在一起时，不容易发生一个输出高、另一个输出低的硬冲突。

### 3.1 上拉电阻不合适会怎样

上拉电阻太大：

- 上升沿变慢。
- 高速通信容易波形不好。
- 可能出现读写不稳定、偶发 NACK。

上拉电阻太小：

- 拉低时电流变大。
- 功耗增加。
- 器件驱动能力不足时低电平可能不够低。

常见经验值：

- 板级短距离低速通信常见 `4.7k`。
- 速度更高或总线电容更大时，可能用 `2.2k`。
- 具体要结合电压、速率、总线电容和芯片手册。

## 4. I2C 的起始和停止条件

I2C 通信不是靠单独的片选线选择设备，而是靠总线上的特殊时序表示开始和结束。

| 条件 | SDA 变化 | SCL 状态 | 含义 |
| --- | --- | --- | --- |
| `START` | 高到低 | 高电平 | 开始一次通信 |
| `STOP` | 低到高 | 高电平 | 结束一次通信 |

重点：

- 在普通数据传输期间，SDA 通常要在 SCL 低电平时变化。
- 当 SCL 为高电平时，SDA 的特殊跳变会被解释为 START 或 STOP。

直白说法：

> SCL 高电平时，SDA 从高变低就是开始；SDA 从低变高就是结束。

## 5. 地址、读写位和 ACK/NACK

### 5.1 7 位地址和读写位

常见 I2C 设备使用 7 位地址。

但在总线上发送地址时，通常会发送 8 bit：

| 位 | 含义 |
| --- | --- |
| bit7 ~ bit1 | 7 位设备地址 |
| bit0 | 读写位，0 表示写，1 表示读 |

所以经常会看到两种地址写法：

| 写法 | 示例 | 含义 |
| --- | --- | --- |
| 7 位地址 | `0x50` | 芯片真实 I2C 地址 |
| 8 位写地址 | `0xA0` | `0x50 << 1 | 0` |
| 8 位读地址 | `0xA1` | `0x50 << 1 | 1` |

注意：

> 调驱动时一定要分清楚代码里要填的是 7 位地址，还是已经左移过的 8 位地址。这个错误非常常见。

### 5.2 ACK 是什么

I2C 每传输 8 bit 数据后，第 9 个时钟周期用于应答。

| 应答 | SDA 状态 | 含义 |
| --- | --- | --- |
| `ACK` | 被接收方拉低 | 收到了，可以继续 |
| `NACK` | 保持高电平 | 没收到、不想继续、读完了 |

常见情况：

- 主机发送地址后，从设备地址匹配就返回 ACK。
- 主机写数据后，从设备收到就返回 ACK。
- 主机读最后一个字节后，通常发送 NACK 表示读完了。

直白说法：

> ACK 就是“我收到了，继续”；NACK 就是“没响应”或“到这里结束”。

## 6. I2C 写寄存器流程

写寄存器是最常见的 I2C 操作之一。

典型流程：

1. `START`
2. 发送设备地址 + 写位
3. 从设备返回 ACK
4. 发送寄存器地址
5. 从设备返回 ACK
6. 发送要写入的数据
7. 从设备返回 ACK
8. `STOP`

可以理解为：

> 先告诉从设备“我要写你”，再告诉它“我要写哪个寄存器”，最后把数据写进去。

示例：

```text
START -> DevAddr(W) -> ACK -> RegAddr -> ACK -> Data -> ACK -> STOP
```

## 7. I2C 读寄存器流程

读寄存器通常要先写寄存器地址，再重新发起读操作。

典型流程：

1. `START`
2. 发送设备地址 + 写位
3. 从设备返回 ACK
4. 发送要读取的寄存器地址
5. 从设备返回 ACK
6. `Repeated START`
7. 发送设备地址 + 读位
8. 从设备返回 ACK
9. 从设备返回数据
10. 主机发送 NACK
11. `STOP`

示例：

```text
START -> DevAddr(W) -> ACK -> RegAddr -> ACK
Repeated START -> DevAddr(R) -> ACK -> Data -> NACK -> STOP
```

为什么读之前还要先写一次寄存器地址：

- 第一次写不是写数据，而是告诉从设备内部地址指针要指向哪个寄存器。
- 第二次读才是真正把该寄存器的数据读回来。

直白说法：

> 读寄存器前，先告诉芯片“我要读哪个地址”，再切换成读模式把数据拿回来。

## 8. I2C 常见速率

I2C 常见速率如下：

| 模式 | 速率 | 常见理解 |
| --- | --- | --- |
| `Standard Mode` | 100 kHz | 标准模式，最常见、兼容性好 |
| `Fast Mode` | 400 kHz | 快速模式，很多传感器支持 |
| `Fast Mode Plus` | 1 MHz | 更高速，对硬件要求更高 |
| `High Speed Mode` | 3.4 MHz | 高速模式，使用场景较少 |

实际项目里，`100 kHz` 和 `400 kHz` 最常见。

选速率时要看：

- 从设备是否支持。
- 上拉电阻是否合适。
- 总线电容是否过大。
- 线长是否较长。
- 波形上升沿是否满足要求。

不要只在软件里把频率改高。频率越高，对上拉、电容、布线和器件时序要求越严格。

## 9. 驱动里容易出问题的点

做 I2C 驱动时，常见问题通常不在协议名词，而在地址、时序和硬件连接。

常见风险：

- **地址写错**：7 位地址和 8 位地址混用。
- **读写位错误**：读操作却发成写地址，或反过来。
- **寄存器地址宽度错误**：有些芯片寄存器地址是 8 bit，有些是 16 bit。
- **大小端或多字节顺序错误**：读出的高低字节拼接反了。
- **上拉电阻缺失或不合适**：导致总线无法正常拉高。
- **电压不匹配**：主控和从设备 I/O 电平不一致。
- **设备未上电或未复位完成**：访问时没有 ACK。
- **总线被拉死**：SDA 或 SCL 被某个设备一直拉低。
- **速率过高**：低速器件或波形条件不支持。
- **驱动初始化顺序不对**：GPIO 复用、时钟、复位、I2C 控制器没有准备好。

## 10. I2C 不通怎么排查

排查建议从最简单、最可观测的地方开始。

### 10.1 先确认硬件连接

检查点：

- `SCL` 和 `SDA` 有没有接反。
- 主控和从设备是否共地。
- 从设备供电是否正常。
- I/O 电压是否匹配。
- 上拉电阻是否存在。
- 复位脚是否释放。
- 地址选择脚是否影响设备地址。

### 10.2 再确认软件配置

检查点：

- I2C 控制器编号是否选对。
- SCL/SDA 引脚复用是否配置正确。
- 总线速率是否合适。
- 设备地址是否是 7 位地址。
- 寄存器地址宽度是否正确。
- 读写流程是否符合芯片手册。

### 10.3 看 ACK 是否正常

如果地址阶段没有 ACK，优先怀疑：

- 设备地址错。
- 设备没上电。
- 复位还没完成。
- SCL/SDA 连接或复用错误。
- 电平不匹配。
- 总线被占用或拉低。

如果地址有 ACK，但寄存器读写不对，优先怀疑：

- 寄存器地址错。
- 读写流程错。
- 寄存器地址长度错。
- 芯片需要延时或解锁流程。
- 多字节数据顺序拼接错。

### 10.4 用示波器或逻辑分析仪看波形

重点看：

- 有没有 START 和 STOP。
- 地址是否正确。
- 第 9 个时钟是否有 ACK。
- SCL 频率是否符合配置。
- SDA 是否在 SCL 高电平时异常跳变。
- 上升沿是否太慢。
- 是否存在毛刺、时钟拉伸或总线被拉低。

### 10.5 总线被拉低怎么办

如果 SDA 或 SCL 一直是低电平：

- 先确认是不是某个从设备未正常上电或复位。
- 检查主控引脚是否被错误配置成普通 GPIO 输出低。
- 可以尝试重新初始化 I2C 控制器和相关 GPIO。
- 有些场景可以通过手动拉 SCL 产生多个时钟，尝试让从设备释放 SDA。
- 仍然不行时，需要断开可疑从设备或检查硬件短路。

直白说法：

> I2C 总线挂死时，先看是谁把 SCL 或 SDA 拉低。总线不回到高电平，后面的协议分析都没有意义。

## 11. 面试常见问法和直白回答

### 11.1 I2C 是什么

> I2C 是一种两线制、主从式、半双工串行总线，使用 SCL 时钟线和 SDA 数据线通信。它通过设备地址区分从设备，常用于传感器、PMIC、EEPROM、触摸 IC 等低速板级外设。

### 11.2 I2C 为什么需要上拉电阻

> 因为 I2C 的 SCL 和 SDA 通常是开漏结构，设备只能主动拉低总线，高电平需要靠上拉电阻恢复。这样多个设备可以共享总线，避免直接输出高低电平造成冲突。

### 11.3 I2C 的 START 和 STOP 怎么判断

> 当 SCL 为高电平时，SDA 从高变低表示 START；SDA 从低变高表示 STOP。普通数据传输时，SDA 一般在 SCL 低电平期间变化，在 SCL 高电平期间保持稳定。

### 11.4 ACK 和 NACK 有什么意义

> 每传完 8 bit 后，第 9 个时钟用于应答。接收方拉低 SDA 表示 ACK，说明收到了；保持高电平就是 NACK，可能表示地址没响应、数据不接受，或者主机读完最后一个字节。

### 11.5 7 位地址和 8 位地址有什么区别

> 7 位地址是设备真实地址。总线上发送时会把 7 位地址左移一位，最低位放读写位，所以会形成 8 位读写地址。调驱动时要确认接口需要填 7 位地址还是左移后的 8 位地址。

### 11.6 I2C 读寄存器为什么要先写一次

> 第一次写通常不是写数据，而是告诉从设备内部寄存器指针要指向哪个地址。然后通过重复起始信号切换到读模式，从这个寄存器把数据读回来。

### 11.7 I2C 和 SPI 怎么选

> 如果外设低速、数量多、希望节省引脚，适合 I2C；如果需要更高速、更稳定的连续数据传输，比如 Flash、屏幕或高速 ADC，通常更适合 SPI。

### 11.8 I2C 没有 ACK 怎么排查

> 先确认设备是否上电、复位是否完成、SCL/SDA 是否接对、上拉电阻是否存在、引脚复用是否正确；再确认设备地址是否正确，尤其是 7 位地址和 8 位地址有没有混用；最后用逻辑分析仪看地址阶段是否真的发出以及第 9 个时钟有没有 ACK。

## 12. 高频易错点

| 错误说法 | 更准确的说法 |
| --- | --- |
| I2C 只要两根线就一定能通信 | 还需要共地、供电、上拉、电平匹配和正确引脚复用 |
| I2C 地址就是代码里看到的 8 位值 | 要分清 7 位设备地址和带读写位的 8 位地址 |
| 没有 ACK 一定是芯片坏了 | 更常见是地址错、没上电、复位没完成、上拉或复用错误 |
| I2C 高电平是芯片主动输出的 | 开漏结构下高电平通常由上拉电阻产生 |
| I2C 读寄存器就是直接读 | 很多芯片要先写寄存器地址，再 repeated start 读数据 |
| I2C 速度越高越好 | 速率要看从设备能力、上拉电阻、总线电容和线长 |
| ACK 永远由从机发 | 谁接收谁应答，主机读最后一个字节后通常发 NACK |
| I2C 可以随便挂很多设备 | 地址不能冲突，总线电容和上拉能力也有限 |

## 13. 最简记忆版

只想快速记住，可以背下面几句：

- I2C 是两线制串行总线，`SCL` 管时钟，`SDA` 管数据。
- I2C 是主从式通信，主机发起访问，从机按地址响应。
- SCL/SDA 通常是开漏结构，高电平靠上拉电阻。
- SCL 高电平时，SDA 高到低是 START，低到高是 STOP。
- 7 位设备地址发送到总线时，会左移并加上读写位。
- 每 8 bit 后有 1 bit ACK/NACK，用来确认是否收到或是否继续。
- 读寄存器通常是先写寄存器地址，再 repeated start 读数据。
- I2C 不通先查供电、复位、上拉、地址、引脚复用和 ACK。
