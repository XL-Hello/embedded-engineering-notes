# I2C 学习文档：从总线原理到项目调试

> 目标：能够依据器件 Datasheet 完成 I2C 外设的接线、初始化、寄存器读写、波形验证和异常恢复。本文聚焦板级 I2C，不展开高速模式的完整电气规范。

## 1. 整体认知：I2C 是什么？

**I2C（Inter-Integrated Circuit）是一种用于板级低速外设通信的同步、串行、主从式、半双工、多节点总线。**

它由主机发起通信并提供时钟，从设备通过地址被选中；常用于传感器、RTC、EEPROM、PMIC、IO 扩展和触摸控制器等。它的价值在于只用两根共享信号线就能连接多个器件，而非追求高吞吐量。

| 维度 | I2C 特性 |
| --- | --- |
| 传输方式 | 串行、同步 |
| 双工方式 | 半双工（SDA 双向共享） |
| 拓扑 | 总线型，多主/多从在规范上可支持 |
| 设备选择 | 7 位或 10 位地址 |
| 常见速率 | 100 kHz、400 kHz |
| 典型距离 | 板内、短距离 |

## 2. 物理层与硬件连接

| 信号 | 方向 | 作用 |
| --- | --- | --- |
| `SCL` | 主机驱动；从机仅可在时钟拉伸时拉低 | 串行时钟线 |
| `SDA` | 双向 | 地址、读写数据、ACK/NACK |
| `GND` | 共地 | 两端电平的参考基准 |

典型连接如下。`SCL`、`SDA` 是所有设备共享的总线；两个上拉电阻通常只需各一组，不应每个模块都随意重复堆叠。

```text
                         VDD (3.3 V / 1.8 V)
                    ┌─────────────┴─────────────┐
                  Rp_SCL                      Rp_SDA
                  4.7 kΩ                      4.7 kΩ
MCU                 │                           │
┌──────────┐        │                           │
│ I2C_SCL  ├────────┴───────────┬───────────────┬───────────────┬── …
│ I2C_SDA  ├────────────────────┼───────────────┼───────────────┼── …
│ GND      ├────────────────────┼───────────────┼───────────────┼── …
└──────────┘                    │               │               │
                          ┌─────┴─────┐   ┌─────┴─────┐   ┌─────┴─────┐  …
                          │  Sensor   │   │  EEPROM   │   │    RTC    │
                          │  SCL      │   │  SCL      │   │    SCL    │
                          │  SDA      │   │  SDA      │   │    SDA    │
                          │  GND      │   │  GND      │   │    GND    │
                          └───────────┘   └───────────┘   └───────────┘
```

多从机共用同一对线，通过地址区分。例如 `0x50` EEPROM、`0x68` IMU、`0x3C` OLED 控制器可以并挂；前提是地址不冲突，且总线电容和上拉能力满足要求。

## 3. 电气特性：开漏与上拉

I2C 的 SCL/SDA 采用开漏（Open-Drain，或开集）思路：设备只能主动拉低，释放线路后由上拉电阻把线路恢复为高电平。

```text
设备输出 0：晶体管导通，线路被拉低
设备输出 1：晶体管关闭，线路由 Rp 拉高
```

这使多个设备可以安全共享线路：只要任一设备拉低，总线就是低；不会出现推挽输出中“一个强推高、另一个强拉低”的硬冲突。多主仲裁和时钟拉伸也依赖这一特性。

上拉电阻需要在上升时间与灌电流之间折中：

- 太大：RC 上升沿慢，高速时可能无法及时达到逻辑高电平；
- 太小：低电平时灌电流过大，功耗增加，也可能超过器件能力；
- 常见板级经验起点为 `4.7 kΩ`；400 kHz、总线电容较大时常需更小阻值，但必须按器件手册和波形确认；
- 上拉电压必须与 I/O 电平兼容。3.3 V MCU 直接接 5 V 上拉并不一定安全。

近似理解上升沿：`tr ≈ 0.8473 × Rp × Cbus`。线缆、器件引脚和模块都会增加 `Cbus`，所以“线少”不等于可以无限挂设备或无限延长。

## 4. 通信模型与寻址

一次传输由主机发起。普通 MCU 项目多为单主多从；I2C 规范也允许多主机，并通过逐位仲裁决定谁继续占用总线。

```text
Master
 ├── 0x50  EEPROM
 ├── 0x68  IMU
 └── 0x3C  OLED
```

最常见的是 **7 位地址**。在线路上发送“地址字节”时，格式为：

```text
A6 A5 A4 A3 A2 A1 A0 R/W
```

`R/W=0` 表示主机写，`R/W=1` 表示主机读。因此数据手册的 `0x50` 可能是 7 位地址，而总线第一个字节则是写 `0xA0`、读 `0xA1`。不同 HAL/API 对地址参数的要求不同：有的传 7 位地址，有的要求已左移一位；必须查看接口文档，不能靠猜。

10 位地址用于设备数量多或地址资源紧张的场合，首个地址字节为 `11110 A9 A8 R/W`，随后发送第二个地址字节 `A7...A0`；其中 `A9:A8` 与低 8 位共同构成完整地址。10 位读通常先以写方向发出两个地址字节，再用 Repeated START 发出首字节的读方向版本；实际项目应优先按目标芯片手册和控制器 API 的地址模式配置执行。

## 5. 核心时序：START、STOP、Repeated START 与数据约束

| 条件 | SCL 状态 | SDA 变化 | 含义 |
| --- | --- | --- | --- |
| `START` | 高 | 高→低 | 开始占用总线 |
| `STOP` | 高 | 低→高 | 释放总线、结束传输 |
| `Repeated START` | 高 | 高→低 | 不释放总线，重新开始一段寻址 |

特别注意：SCL 高电平时 SDA 的上述跳变具有控制含义；普通数据阶段不应随意变化。Repeated START 常用于“先写寄存器地址，再读数据”，以避免在两阶段之间释放总线。

数据位的关键时序参数如下（具体最小值和最大值按所用速率模式及器件 Datasheet 核对）：

```text
          SDA 数据稳定窗口
SCL  ___/‾‾‾‾‾\___/‾‾‾‾‾\___
SDA  ---<  D0  >---<  D1  >---
          ↑      ↑
      tSU;DAT  tHD;DAT
```

- `tSU;DAT`（data setup time，数据建立时间）：SCL 上升沿采样前，SDA 必须已稳定的最短时间；
- `tHD;DAT`（data hold time，数据保持时间）：SCL 边沿后，SDA 必须继续保持稳定的时间。

这两个参数说明“在 SCL 低电平变 SDA”不是任意时刻翻转，而是要满足接收端的建立/保持窗口。示波器或逻辑分析仪抓到边沿过慢、数据靠近采样沿跳变时，应回查上拉、电容、GPIO 驱动方式和 SCL 配置。

## 6. 协议基本单位：Bit、Byte、ACK

### 一个 Bit 怎样传输

除 START/STOP 外，**SDA 在 SCL 低电平期间改变，在 SCL 高电平期间保持稳定并被采样**。通常先发送 MSB（bit7）。

```text
SCL  __/‾‾\__/‾‾\__
SDA  --<稳定数据>---    （SCL 高电平期间有效）
```

### 一个 Byte 怎样传输

每 8 个数据位后，第 9 个时钟周期用于应答：

| 角色 | 第 9 位 SDA | 含义 |
| --- | --- | --- |
| 接收方 | 拉低 | `ACK`：已接收，可继续 |
| 接收方 | 保持高 | `NACK`：不接收/不继续 |

地址由从机接收，因此地址后的 ACK 一般由被寻址从机给出；写数据时由从机 ACK；读数据时主机是接收方，读到最后一个字节后通常由主机发送 NACK，通知从机结束发送。

## 7. 多主仲裁、时钟同步与 Clock Stretching

### 7.1 多主仲裁与时钟同步

多主机同时检测到总线空闲后都可能发起 START，因此 I2C 不以“先抢到就独占”的方式避免冲突，而是利用开漏的**线与**特性无损仲裁：每个主机在 SCL 高电平期间读取实际 SDA 电平；若自己释放 SDA、想发送 `1`，却读回 `0`，说明另一主机正在发送 `0` 并拉低总线，自己立即失去仲裁。失仲裁主机必须停止驱动 SDA/SCL、清除本次事务状态，待当前传输 STOP 后再按策略重试；它没有破坏赢家已发送的数据。

```text
主机 A：发送 1（释放 SDA）→ 读回 0 → A 失仲裁并退出
主机 B：发送 0（拉低 SDA）→ 总线为 0 → B 继续传输
```

时钟同步也基于开漏：不同主机的 SCL 低电平会叠加，只有所有主机都释放 SCL 后线路才能变高。因此实际低电平由最慢主机决定，高电平开始后先结束高电平的主机又会拉低 SCL；最终各主机同步到共同的时钟节奏。普通单主项目很少亲自实现仲裁，但驱动必须能识别 `arbitration lost` 状态，不能误判为从机 NACK。

### 7.2 Clock Stretching（时钟拉伸）

时钟拉伸是**从机在主机释放 SCL 后继续把 SCL 拉低**，要求主机暂停等待的机制。常见原因是从机尚未处理完上一个字节、正在准备读数据，或内部状态需要短暂完成；部分 EEPROM、传感器和桥接芯片会使用或可能使用它。

主机每次准备进入 SCL 高电平前都应读取实际 SCL：只有读到高才开始高电平计时/采样；若持续为低则启动超时计时，超时后终止事务并执行异常恢复。硬件 I2C 通常自动等待，但仍要配置合理超时；Bit-Bang 则必须在 `SCL=1` 后轮询引脚。不要把“配置了 400 kHz”误解为任何时刻都严格 400 kHz，拉伸会降低平均速率。

## 8. 完整读写流程

### 写一个寄存器

```text
START
→ SlaveAddr + W → ACK
→ RegisterAddr  → ACK
→ Data          → ACK
→ STOP
```

连续写时可在第一个数据后继续发送多个 Data；从设备是否自动递增内部地址取决于其 Datasheet。

### 读一个寄存器

```text
START
→ SlaveAddr + W → ACK
→ RegisterAddr  → ACK
→ Repeated START
→ SlaveAddr + R → ACK
← Data          ← NACK
→ STOP
```

前半段“写”只是设置从设备内部寄存器指针，不是把业务数据写入寄存器。连续读取 `N` 字节时，主机对前 `N-1` 字节回复 ACK，对最后一字节回复 NACK，再发 STOP。

## 9. 关键配置参数

初始化和驱动对接时，至少确认以下项：

| 参数 | 需要确认的内容 |
| --- | --- |
| 总线速率 | 从机支持的 100 kHz / 400 kHz / 更高模式 |
| 地址模式 | 7 位还是 10 位；API 是否要左移地址 |
| GPIO | 复用功能、开漏配置、上拉来源、电压域 |
| 寄存器地址长度 | 8 位、16 位或厂商自定义命令格式 |
| 数据长度/顺序 | 连续读写限制、多字节高低字节顺序 |
| 超时 | 地址、单字节和整笔传输的超时策略 |
| 从机特性 | 上电时间、复位、时钟拉伸、写周期 |

I2C 没有类似 SPI `CPOL/CPHA` 的模式配置；双方必须匹配的是地址、速度、电气条件和特定器件事务格式。

## 10. GPIO 软件模拟（Bit-Bang）

软件模拟能检验是否真正理解协议。核心不是把 GPIO 推高，而是模拟开漏：拉低时设为输出低；释放高电平时切换为输入/高阻（或按平台使用开漏输出高）。

```c
i2c_start();
i2c_write_byte((addr7 << 1) | 0);
i2c_wait_ack();
i2c_write_byte(reg);
i2c_wait_ack();
i2c_repeated_start();
i2c_write_byte((addr7 << 1) | 1);
i2c_wait_ack();
value = i2c_read_byte(/* nack_last = */ true);
i2c_stop();
```

需要实现的原语包括 `start`、`stop`、`write_bit`、`read_bit`、`write_byte`、`read_byte`、`wait_ack`。实现时要处理延时精度、SCL 被从机拉低的时钟拉伸、超时和并发访问；中断抢占会破坏软件时序，因此要慎用或采取临界区保护。

## 11. 硬件 I2C 控制器

硬件外设通常代替软件完成时钟产生、移位、ACK 时序、状态机、中断和 DMA 等工作；但它不会代替你理解从设备的事务协议。

使用 HAL/驱动接口时应明确：

- 单次 API 会不会自动产生 STOP；
- 是否支持 `no-stop` / `repeated-start` 组合传输；
- 返回值和状态寄存器如何区分 NACK、仲裁丢失、总线错误和超时；
- DMA 期间 Buffer 的生命周期、Cache 一致性和并发访问如何保证。

推荐先用阻塞式单字节读写跑通波形，再迁移到中断/DMA。遇到问题时，控制器状态位和逻辑分析仪比只看 API 返回值更可靠。

## 12. 速率与有效吞吐率

面试中被问到 I2C 理论速率时，不要只回答“100 kHz、400 kHz”。可以按“总线时钟 → 单字节开销 → 实际有效速率”三层说明。

### 12.1 常见标准速率

| 模式 | 最高 SCL（典型） | 说明 |
| --- | --- | --- |
| Standard-mode | 100 kHz | 兼容性好 |
| Fast-mode | 400 kHz | 项目最常用 |
| Fast-mode Plus | 1 MHz | 需确认器件与电气条件 |
| High-speed mode | 3.4 MHz | 事务规则和硬件要求更严格 |

这里的 `100 kHz`、`400 kHz` 指的是 SCL 时钟频率，而不是纯数据吞吐率。

### 12.2 单字节的理论上限

I2C 每传输 1 Byte 数据，还需要 1 bit ACK/NACK：

```text
8 bit 数据 + 1 bit ACK/NACK = 9 个 SCL 时钟
```

忽略 START、STOP 和地址等额外开销时：

```text
有效字节速率 ≈ F_SCL / 9
有效数据 bit rate ≈ F_SCL × 8 / 9
```

以 400 kHz I2C 为例：

```text
400000 / 9 ≈ 44 444 Byte/s ≈ 44.4 KB/s
400 kHz × 8 / 9 ≈ 355.6 kbps
```

因此，400 kHz I2C 的理论有效数据率上限约为 44.4 KB/s，而不是 400 KB/s。

### 12.3 地址与事务固定开销

连续写入 `N` Byte 时，地址阶段和每个数据字节各占 9 个时钟，时钟数近似为：

```text
9(N + 1)
```

有效数据吞吐可近似为：

```text
Throughput = N × 8 / [9(N + 1)] × F_SCL
```

400 kHz 下，连续写 1 Byte 时地址和数据各占 9 个时钟，共 18 个时钟：

```text
400 kHz × 8 / 18 ≈ 177.8 kbps ≈ 22.2 KB/s
```

连续写 100 Byte 时：

```text
400 kHz × 800 / 909 ≈ 352 kbps
```

已经接近连续大块传输的理论极限 `355.6 kbps`。一次连续传输的数据越多，地址、START、STOP 等固定开销占比越低，实际带宽越接近上限。

### 12.4 寄存器读取的开销

典型的单字节寄存器读取事务如下：

```text
START
SlaveAddr + W  → ACK
RegAddr        → ACK
Repeated START
SlaveAddr + R  → ACK
Data           ← NACK
STOP
```

粗略计算，地址写、寄存器地址、地址读和数据共约 36 个 SCL 时钟，真正有效数据只有 8 bit。因此 400 kHz 下：

```text
400 kHz × 8 / 36 ≈ 88.9 kbps ≈ 11.1 KB/s
```

这解释了为何 I2C 标称 400 kHz，但每次仅读取一个寄存器时，有效吞吐往往只有十几 KB/s。应优先使用器件支持的 Burst 连续读写以降低协议开销。

### 12.5 影响实际速率的因素

除 ACK/NACK、从机地址、寄存器地址、START、STOP 和 Repeated START 外，以下因素也会进一步降低吞吐：

- **Clock Stretching**：从机可将 SCL 拉低，延后下一时钟；实际平均 SCL 频率会低于配置值。
- **软件与控制器间隙**：软件模拟、驱动调用、中断响应或 DMA 配置都可能在字节或事务之间引入等待。
- **电气条件**：I2C 使用开漏输出加上拉电阻；高电平由上拉电阻给总线电容充电，近似满足 `t_r ≈ 0.8473 × R_p × C_b`。上拉电阻过大、线长增加、设备增多导致总线电容变大，都会使上升沿变慢，限制可稳定使用的 SCL 频率。

因此，400 kHz 能否稳定运行不仅取决于软件配置，还取决于总线电容、线长、设备数量、上拉电阻和器件时序能力。

**一句话结论：开漏输出加上拉电阻的 RC 充电过程，是 I2C 难以提升到数十/数百 MHz 的根本电气限制；SPI 使用推挽输出主动拉高、拉低，边沿更快，因此更适合高吞吐量场景。**

### 12.6 面试速记

```text
I2C 连续传输：1 Byte ≈ 9 clock
理论最大有效字节速率 ≈ SCL / 9

100 kHz → ≈ 11.1 KB/s
400 kHz → ≈ 44.4 KB/s
1 MHz   → ≈ 111 KB/s
```

可直接概括为：I2C 的 100 kHz、400 kHz 是 SCL 时钟频率，不是有效数据吞吐率。连续传输时，每个 Byte 至少需要 9 个时钟，故 400 kHz 的理论最大约为 44.4 KB/s；实际还需扣除地址、控制条件、寄存器地址和从机处理等待等开销。

## 13. 常见错误、排查路径与异常恢复

### 13.1 先判别，再恢复

不要把所有失败都归因于“总线坏了”。先结合控制器状态位和波形，按事务阶段定位：

| 现象/状态 | 常见含义 | 优先检查 |
| --- | --- | --- |
| 地址阶段 NACK | 总线上没有该地址的从机响应 | 7/10 位地址和左移规则、供电/复位、接线、地址脚配置、器件是否尚未上电完成 |
| 数据阶段 NACK | 从机已被选中，但不接受当前数据或不再继续 | 寄存器/命令格式、写保护、FIFO/页边界、EEPROM 内部写周期、数据长度 |
| Arbitration Lost | 发送 `1` 时读到 `0`，其他主机赢得总线 | 多主配置、其他控制器/调试器占线；等待 STOP 后重试 |
| Bus Error / 非法 START/STOP | SCL 高期间出现非预期 SDA 跳变 | 干扰、边沿过慢、GPIO 复用或驱动方式错误、硬件短路 |
| SCL 或 SDA 长期低 | 时钟拉伸未结束、从机卡在半字节、短路或掉电器件反向供电 | 先读两线电平和电源，再限时恢复 |

### 13.2 常见从机事务差异

- **EEPROM**：页写不能跨越其页边界；写 STOP 后存在内部写周期 `tWR`，可按手册等待，或反复发送地址并以 ACK 轮询确认写入完成。
- **传感器**：常以“寄存器地址 + Burst 读取”获取连续寄存器，内部地址是否自动递增、是否要求 repeated START 都以 Datasheet 为准。
- **OLED/显示控制器**：常有控制字区分命令和数据，且一帧传输较长；应分块传输并评估刷新率与 I2C 带宽。

### 13.3 电平转换与上拉定量选择

不同 I/O 电压域不能只靠“都接到 SDA/SCL”解决。常见的双向电平转换方案是每条线使用一个 N 沟道 MOSFET（低压侧栅极接低压 VDD、两侧各自上拉）：任一侧拉低会通过 MOSFET 传递低电平，释放后各侧回到各自电压域。选型时还要确认 MOSFET 的阈值、漏电和目标速率；专用双向 I2C 电平转换器也是更省心的方案。

上拉电阻可先按约束夹取范围，而非只套用 `4.7 kΩ`：由器件允许的低电平灌电流估算 `R_p(min) ≈ (VDD - VOL(max)) / IOL(max)`；由上升时间约束估算 `R_p(max) ≈ tr(max) / (0.8473 × Cbus)`。在该范围内选标准阻值，并用实测波形确认。没有重叠范围时，应降低速率/电容、调整电压域或采用缓冲器。

### 13.4 异常恢复

当总线忙或 SDA 被长期拉低，不要无限重试。一个可执行的恢复策略是：

1. 为一次事务设置超时，停止当前控制器传输；
2. 将 I2C 引脚临时改为 GPIO 开漏；
3. 先释放 SCL 和 SDA，确认 SCL 可以回到高电平；随后保持 SDA 释放，让 SCL 在高低电平之间翻转最多约 9 次，尝试让从机完成残留字节并释放 SDA；
4. 手动生成 STOP（SCL 高时释放 SDA）；
5. 恢复 GPIO 复用并重新初始化 I2C 外设；
6. 重新探测设备；若连续失败，上报设备离线并按业务策略重试。

不能强推高 SDA/SCL；总线恢复前也应先确认硬件短路或掉电从机等根因。对于 EEPROM 等有内部写周期的器件，写后轮询 ACK 或按手册等待，不能立即盲读。


## 14. 面试/复盘速记

### 14.1 I2C 是什么？有什么特点？

I2C 是两线制、同步、串行、半双工的主从通信总线。它使用 `SCL` 和 `SDA` 两根信号线，支持多个设备共享同一条总线。

### 14.2 I2C 为什么需要上拉电阻？

SDA 和 SCL 通常采用开漏输出，只能主动拉低，不能主动输出高电平；因此需要外部上拉电阻将总线释放时拉到高电平。

### 14.3 I2C 的 START 和 STOP 条件是什么？

在 SCL 保持高电平期间，SDA 从高变低是 START；SDA 从低变高是 STOP。

### 14.4 ACK/NACK 是什么？谁产生？

每发送 8 bit 后，第 9 个时钟用于应答。接收方拉低 SDA 表示 ACK；不拉低 SDA 表示 NACK。

### 14.5 I2C 一次完整读写流程是什么？

基本流程是 `START → 地址+R/W → ACK → 数据/寄存器地址 → ACK → STOP`。读取寄存器时，通常还会使用 Repeated START 切换为读方向。

### 14.6 7 位地址、8 位地址和 10 位地址有什么区别？

真正的设备地址通常是 7 bit；在线路上发送时会左移 1 位并在最低位附加 R/W 位，即 `7 bit 地址 << 1` 加 R/W 位。因此许多手册会出现所谓“8 位地址”。10 位地址以 `11110 A9 A8 R/W` 开头，再发送 `A7...A0`，必须在控制器中显式选择 10 位地址模式。

### 14.7 I2C 理论速率怎么计算？

一个 Byte 至少需要 8 bit 数据加 1 bit ACK，即 9 个时钟。400 kHz 连续传输的理论有效字节速率约为 `400 kHz / 9 ≈ 44.4 KB/s`；实际还需扣除地址、控制条件和寄存器地址等协议开销。

### 14.8 I2C 多主机怎么做仲裁和时钟同步？

SDA 是线与结构。多主机发送时同时采样 SDA：若主机自己发送 1 却读到 0，说明其他主机正在拉低总线，该主机失去仲裁，应退出当前传输。SCL 也是开漏，多个主机的低电平会叠加，故时钟同步到最慢者的节奏。

### 14.9 Clock Stretching 是什么？

从机可暂时拉低 SCL，让主机等待，通常用于从机处理速度跟不上时。主机必须读取实际 SCL，并设置等待超时；这会使实际通信速率低于配置的 SCL 频率。

### 14.10 地址 NACK、数据 NACK 和总线卡死如何区分？

地址阶段 NACK 优先查地址、供电、复位和接线；数据阶段 NACK 说明从机已响应，优先查寄存器/命令格式、页边界和内部写周期。SDA 被持续拉低时，再检查短路、掉电从机和时钟拉伸，并可限时输出约 9 个 SCL 脉冲、生成 STOP 后重新初始化。

### 14.11 I2C 为什么通常比 SPI 慢？

I2C 的开漏输出只能主动拉低，高电平靠上拉电阻对总线电容充电，RC 上升沿限制了速率；SPI 推挽输出可主动拉高/拉低，边沿更快，适合更高吞吐量。

### 14.12 不同电平的 I2C 如何连接？

不能让低压 I/O 直接承受高压侧上拉。可使用双向 MOSFET 电平转换或专用 I2C 电平转换器，两侧各自上拉到本侧电源，并按波形验证速度和上升沿。
