# DMA 基础知识总结

> 目标：这篇文档只作为 DMA 入门、嵌入式开发和项目面试复习使用。重点理解 DMA 是什么、它和 CPU/中断的关系、常见传输方向和工作模式，以及 ESP32-S3 的 GDMA 资源特点。
>
> 来源：围绕 DMA 主题整理的基础总结文档，结合 SPI、ADC、Flash、UART 和嵌入式 UI 等常见开发场景，仅供参考。具体通道数量、地址限制和外设支持情况，以对应芯片手册和 SDK 文档为准。

## 1. 先用一句话理解 DMA

**DMA（Direct Memory Access，直接内存访问）是一种由硬件完成数据搬运、减少 CPU 逐字节介入的机制。**

CPU 原本可能需要这样搬运数据：

```text
外设寄存器 -> CPU 读取 -> CPU 写入 RAM
```

使用 DMA 后，数据通路变成：

```text
外设寄存器 <-> DMA <-> RAM
```

CPU 主要负责：

1. 配置源地址、目标地址和传输长度。
2. 启动 DMA 传输。
3. 等待传输完成、半传输或错误事件。
4. 处理已经搬运到内存中的数据。

也就是说，DMA 的核心价值是：**把数据搬运工作交给硬件，让 CPU 有时间处理其他业务。**

## 2. DMA 到底负责什么

可以把 DMA 理解成专职数据搬运通道：

- `CPU`：负责下达任务和处理结果。
- `DMA`：负责按照配置搬运数据。
- `外设`：负责通信协议、采样时序或发送时序。
- `RAM`：负责保存待发送或已接收的数据。

### 2.1 DMA 能做什么

- 按照触发请求，从外设寄存器读取数据并写入内存。
- 从内存读取数据并写入外设寄存器。
- 在部分芯片上完成内存到内存的数据拷贝。
- 根据配置自动递增地址、重复传输或切换描述符。
- 在传输完成、半传输或发生错误时通知 CPU。

### 2.2 DMA 不能做什么

DMA **不会运算，也不理解通信协议**：

- 不能解析 SPI 命令。
- 不能对 ADC 数据做滤波。
- 不能理解 UART 字符串含义。
- 不能擦除或写入 Flash 内部内容。

> 直白理解：SPI、ADC、UART 等外设负责“怎么通信”，DMA 只负责“把数据挪到哪里”。

## 3. 为什么 SPI、ADC、UART 经常配合 DMA

DMA 适合连续、批量、频率较高的数据传输。

| 场景 | 不使用 DMA | 使用 DMA |
| --- | --- | --- |
| ADC 采样 | 每次转换触发中断，CPU 读取数据并写入数组 | DMA 自动把数据寄存器搬运到采样缓冲区 |
| SPI 接收 | CPU 在中断或轮询中逐个读取数据 | DMA 连续把 SPI 接收寄存器写入 RAM |
| SPI 发送 | CPU 循环填充发送寄存器 | DMA 从 RAM 连续取数据交给 SPI |
| UART 收发 | CPU 频繁处理中断，搬运每个字节 | DMA 负责批量收发，CPU 处理整块数据 |
| SPI Flash | CPU 逐字节搬运大块数据 | DMA 负责 SPI 寄存器和 RAM 之间的连续传输 |

例如 ADC 连续采样时：

```text
ADC 转换完成 -> ADC 数据寄存器 -> DMA -> RAM 采样缓冲区
```

如果由 CPU 逐个读取，采样频率越高，中断和数据搬运开销越大，可能出现 CPU 占用过高或丢采样点的问题。

> 注意：DMA 解决的是数据搬运开销，不会自动解决缓冲区溢出、数据处理不及时或总线带宽不足等问题。

## 4. DMA 的常见传输方向

### 4.1 外设到内存（Periph to Mem）

外设产生数据，DMA 将数据写入 RAM。

常见场景：

- ADC 连续采样。
- SPI 接收数据。
- UART 接收数据。
- I2S、摄像头等流式数据接收。

### 4.2 内存到外设（Mem to Periph）

DMA 从 RAM 读取数据，写入外设数据寄存器。

常见场景：

- SPI 发送数据。
- UART 发送数据。
- I2S 播放音频。
- 使用定时器 DMA 输出波形。
- LCD 刷屏。

### 4.3 内存到内存（Mem to Mem）

DMA 直接完成两块内存之间的数据拷贝，可以理解成硬件加速版 `memcpy`。

但是否支持取决于具体 DMA 控制器：

- 有些低端 MCU 只支持外设和内存之间传输。
- 有些 MCU 支持内存到内存传输。
- 不同芯片对地址对齐、可访问内存区域也可能有额外限制。

### 4.4 外设到外设（Periph to Periph）

少数 DMA 控制器支持外设到外设传输，实际项目中相对少见，不能默认所有芯片都支持。

## 5. DMA 控制器、通道和请求

一个 MCU 通常不是只有一个“万能 DMA 通道”，而是由 DMA 控制器和多路通道组成：

```text
DMA 控制器
├── 通道 0：可连接某些外设请求
├── 通道 1：可连接某些外设请求
├── 通道 2：可连接某些外设请求
└── ...
```

每个通道通常需要配置：

- 源地址。
- 目标地址。
- 传输长度。
- 传输方向。
- 单次传输宽度，例如 8 bit、16 bit、32 bit。
- 源地址和目标地址是否递增。
- 触发源、优先级和中断。

不同 MCU 的通道和请求映射方式不完全相同：

- 有些芯片采用固定映射，例如某个通道只能服务某个外设。
- 有些芯片通过 DMA 请求选择器进行灵活映射。
- 有些芯片使用 Stream、Channel 或链表描述符等不同概念。

> 关键点：同一个 DMA 通道在同一时刻通常只能分配给一个传输任务。多个外设能否同时使用 DMA，取决于可用通道、请求映射和总线带宽。

## 6. DMA 的两种基础工作模式

### 6.1 普通模式（Normal）

DMA 完成指定长度的传输后停止，需要软件重新配置或重新启动。

适合：

- 一次性的 SPI Flash 读写。
- 一帧图像或一块屏幕数据发送。
- 一段 UART 数据发送。

### 6.2 循环模式（Circular）

DMA 传输到缓冲区末尾后，自动从缓冲区开头继续工作。

适合：

- ADC 连续采样。
- 音频流接收和播放。
- UART 环形接收。
- 需要持续运行的数据采集任务。

常见的半缓冲处理方式如下：

```text
DMA 填充前半区 -> 触发半传输事件 -> CPU 处理前半区
DMA 填充后半区 -> 触发传输完成事件 -> CPU 处理后半区
DMA 重新从前半区开始填充
```

这样可以让 DMA 和 CPU 交替工作，减少停采和等待。

## 7. DMA 配合中断的标准流程

典型流程可以归纳为：

1. CPU 配置 DMA 的源地址、目标地址、传输长度和传输方向。
2. CPU 配置外设，使其能够产生 DMA 请求。
3. CPU 启动 DMA，然后继续执行其他任务。
4. 外设准备好数据或发送条件满足时，触发 DMA 搬运。
5. DMA 完成半缓冲、整块传输或检测到错误。
6. DMA 产生中断，CPU 在中断或任务中处理结果。

DMA 和中断经常组合使用：

> DMA 负责搬运一整块数据，中断只负责通知 CPU“这一块数据已经准备好了”，从而避免每个字节都触发一次中断。

## 8. 使用 DMA 时需要关注的硬件限制

### 8.1 通道数量

低端 MCU 的 DMA 通道数量有限，多个高速外设同时工作时可能出现资源不足。

### 8.2 总线带宽和访问竞争

DMA 和 CPU 通常共享系统总线。DMA 大量访问 RAM 时，可能与 CPU 产生总线竞争，导致 CPU 访问内存出现等待周期。

### 8.3 地址和内存区域

需要确认：

- DMA 是否支持当前 RAM 区域。
- 源地址和目标地址是否要求对齐。
- 外设寄存器是否允许地址递增。
- Cache、PSRAM 或特殊内存是否需要额外处理。

### 8.4 传输宽度和地址递增

传输宽度常见为 8 bit、16 bit 或 32 bit。配置错误时，可能出现数据错位、地址步进不正确或外设寄存器访问异常。

### 8.5 缓冲区生命周期

DMA 运行期间，源缓冲区不能被提前释放或覆盖；接收缓冲区也不能在 DMA 尚未完成时被 CPU 当作完整数据使用。

> 注意：DMA 不是“开启后一定更快”。对于只有 1～3 个字节的小数据，配置 DMA 的开销可能超过 CPU 直接搬运的开销。

## 9. DMA 和 CPU、中断的区别

| 项目 | CPU 直接搬运 | 中断搬运 | DMA 搬运 |
| --- | --- | --- | --- |
| 数据搬运主体 | CPU 主动执行 | CPU 在中断中执行 | DMA 硬件执行 |
| CPU 介入频率 | 每个字节或每次轮询 | 每个字节或每批数据一次 | 通常在完成/半完成时介入 |
| 配置复杂度 | 低 | 中 | 相对较高 |
| 适合场景 | 少量数据、简单任务 | 中小量数据、实时响应 | 连续大批量数据 |
| 主要问题 | 占用 CPU | 中断频繁 | 通道、总线和缓存限制 |

## 10. 常见面试问题

### Q1：DMA 和中断有什么区别

中断只是通知 CPU 有事件发生，数据仍然通常由 CPU 读取或写入；DMA 则由硬件完成数据搬运。实际项目中常见的组合是：**DMA 搬运整块数据，传输完成后触发一次中断。**

### Q2：DMA 传输时 CPU 还能访问内存吗

通常可以。DMA 和 CPU 会通过总线仲裁共享内存访问，但如果同时访问同一块 RAM，可能产生等待周期并降低性能。

### Q3：使用 DMA 一定比 CPU 搬运快吗

不一定。DMA 更适合连续、大批量或高频数据传输。少量数据传输时，DMA 的配置、启动和中断处理开销可能反而更大。

### Q4：DMA 能不能理解 SPI 或 UART 协议

不能。SPI、UART 等外设负责协议时序和数据收发，DMA 只负责外设寄存器与内存之间的数据搬运。

### Q5：DMA 传输完成后，数据一定可以直接使用吗

不一定。需要确认 DMA 完成标志、缓冲区边界、Cache 一致性和数据处理顺序。使用循环 DMA 时，还要区分半缓冲和整缓冲事件。

## 11. DMA 在常见项目中的应用

### 11.1 SPI 屏幕和 LVGL 刷屏

屏幕刷新通常需要发送大量连续像素数据：

```text
RAM 像素缓冲区 -> DMA -> SPI 发送寄存器 -> 屏幕
```

不使用 DMA 时，CPU 需要循环发送每个像素，容易被长时间占用；使用 DMA 后，CPU 可以并行处理界面逻辑、触摸扫描和其他控制任务。

### 11.2 ADC 传感器采集

可以使用循环 DMA 把 ADC 采样值持续写入缓冲区，再由 CPU 按半缓冲或整缓冲事件批量处理。

```text
ADC -> DMA 循环缓冲区
             ├── 前半区：CPU 处理
             └── 后半区：DMA 填充
```

### 11.3 UART 接收

UART DMA 常用于连续数据流或不定长数据接收。工程中通常还需要配合空闲线检测、环形缓冲区或协议帧解析，DMA 本身不会判断一帧数据在哪里结束。

## 12. ESP32-S3 的 GDMA 资源

以下内容针对 ESP32-S3 的常见硬件和 ESP-IDF 使用方式整理；实际可用外设、通道分配和驱动行为应以具体芯片版本及 ESP-IDF 版本为准。

### 12.1 AHB GDMA 通道组成

ESP32-S3 使用通用 DMA 控制器 GDMA（General DMA）为多类外设提供 DMA 服务。常见资源划分为：

| 类型 | 通道 | 典型方向 |
| --- | --- | --- |
| TX 通道 | `TX_CH0 ~ TX_CH4`，共 5 路 | 内存 -> 外设，部分场景支持内存 -> 内存 |
| RX 通道 | `RX_CH0 ~ RX_CH4`，共 5 路 | 外设 -> 内存 |

合计为 10 路独立物理通道。`TX` 和 `RX` 是不同方向的物理资源，不能简单互相替代。

### 12.2 常见使用方向

- TX 通道：SPI 发送、I2S 播放、UART 发送、LCD 刷屏。
- RX 通道：SPI 接收、I2S 录音、UART 接收、摄像头数据接收。
- 部分 TX 通道：可配置为内存到内存拷贝，例如异步内存拷贝功能的底层实现。

### 12.3 共享和动态分配

支持 GDMA 的外设通常可以在运行时申请空闲的 TX 或 RX 通道。例如：

```text
SPI2 发送 -> TX_CH1
I2S0 播放 -> TX_CH2
SPI3 接收 -> RX_CH0
```

同一通道同一时刻只能分配给一个外设。多个高速外设同时工作时，还需要考虑 GDMA 仲裁和 AHB 总线竞争。

### 12.4 SPI0/SPI1 与其他硬件 FIFO

ESP32-S3 中，连接 Flash/PSRAM 的 SPI0/SPI1 控制器通常使用自身的硬件机制，不按 SPI2/SPI3 的方式占用 GDMA 通道。部分 USB、SDIO、RMT 等外设也可能使用自己的 FIFO 或专用传输机制。

> 这部分容易受到芯片型号、驱动实现和 SDK 版本影响。判断某个外设是否占用 GDMA 时，应以对应 ESP-IDF 驱动文档和实际资源分配结果为准。

### 12.5 ESP32-S3 的链表 DMA

ESP32-S3 支持通过 DMA 描述符链表组织连续或分段缓冲区，适合：

- 环形缓冲区。
- 音频流。
- ADC 连续采集。
- 多块非连续内存的连续传输。

这样可以减少 CPU 频繁停止和重新启动 DMA 的次数。

## 13. ESP32-S3 DMA 资源规划示例

假设项目同时启用以下功能：

| 外设/功能 | 方向 | 示例通道 |
| --- | --- | --- |
| SPI2 TFT 刷屏 | TX | `TX_CH0` |
| SPI3 传感器接收 | RX | `RX_CH0` |
| I2S0 麦克风采集 | RX | `RX_CH1` |
| I2S1 扬声器播放 | TX | `TX_CH1` |
| UART2 高速接收 | RX | `RX_CH2` |
| ADC 连续采集 | RX | `RX_CH3` |
| LCD 刷新 | TX | `TX_CH2` |

此时示例占用：

- TX：`TX_CH0`、`TX_CH1`、`TX_CH2`。
- RX：`RX_CH0`、`RX_CH1`、`RX_CH2`、`RX_CH3`。
- 示例中剩余：`TX_CH3`、`TX_CH4`、`RX_CH4`。

实际项目中不要只看通道数量，还要同时检查：

1. 外设驱动是否真的使用 GDMA。
2. TX/RX 方向是否匹配。
3. DMA 可访问的内存区域是否正确。
4. 多路高速传输是否造成总线拥塞。
5. 是否需要预留通道给后续功能或临时任务。

## 14. ESP32-S3 常见面试问题

### Q1：ESP32-S3 GDMA 一共有多少通道

常见划分为 5 路 TX 加 5 路 RX，共 10 路物理通道。TX 和 RX 方向独立，不能互相替代。

### Q2：读写 Flash 会占用 GDMA 通道吗

连接 Flash/PSRAM 的 SPI0/SPI1 通常不按 SPI2/SPI3 的方式占用 GDMA。具体仍应以芯片手册和 ESP-IDF 驱动实现为准。

### Q3：GDMA 通道不够用怎么办

1. 低速外设改用中断或 CPU 直接搬运。
2. 对不同时工作的任务进行分时复用。
3. 检查是否有外设使用了专用 FIFO 或其他传输机制。
4. 降低传输速率，避免多路数据同时产生突发访问。
5. 在项目设计阶段提前规划 TX/RX 通道和缓冲区。

### Q4：ESP32-S3 GDMA 和早期 ESP32 DMA 有什么区别

可以先这样理解：早期 ESP32 的部分外设具有相对独立的 DMA 资源；ESP32-S3 更强调由统一 GDMA 进行共享和动态分配。这样资源调度更灵活，但也更需要关注通道数量、方向和并发竞争。

## 15. 极简总结

1. DMA 是硬件数据搬运机制，**只搬数据，不运算，也不理解通信协议**。
2. 外设负责通信时序，DMA 负责外设寄存器和内存之间的数据传输。
3. 常见方向是外设 -> 内存、内存 -> 外设，部分芯片支持内存 -> 内存。
4. 普通模式传完指定长度后停止，循环模式可以持续填充缓冲区。
5. DMA 常与中断配合：DMA 搬运整块数据，中断通知 CPU 处理结果。
6. 是否适合使用 DMA，要综合考虑数据量、通道数量、总线带宽、地址限制和缓存一致性。
7. ESP32-S3 常见 GDMA 资源为 5 路 TX 加 5 路 RX，具体外设是否占用 GDMA 需以芯片和 SDK 文档为准。
