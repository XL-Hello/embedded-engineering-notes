## 1. 先用一句话理解 SPI

**SPI 是一种同步、主从式、常见全双工的串行通信接口。**

结构可以先按下面这张图理解：SPI 可以一个主机连接多个从设备，`SCLK` / `MOSI` / `MISO` 通常共享，每个从设备用独立 `CS` 片选线区分。

```text
主机 / Master
+-----------+
|      SCLK | =====================+==========+==========+
|      MOSI | =====================+==========+==========+
|      MISO | =====================+==========+==========+
|       CS0 | -------------------->| CS       |          |
|       CS1 | -------------------------------->| CS       |
|       CS2 | ------------------------------------------>| CS
+-----------+                     |          |          |
                                  |          |          |
                             +----+----+ +---+----+ +---+----+
                             | 设备1  | | 设备2 | | 设备3 |
                             | Flash | |  LCD  | |  ADC  |
                             +-------+ +------+ +------+
```

> 关键点：SPI 的数据线和时钟线可以被多个从设备共享，但片选 `CS` 一般是每个从设备单独一根；主机把某个 `CS` 拉低后，当前通信才属于那个从设备。

它最典型的特点是：

- 主机提供时钟。
- 通过片选信号选择从设备。
- 数据发送和接收可以同时进行。
- 速度通常比 I2C 高。
- 线数比 I2C 多，但时序更直接。

常见用途：

| 用途 | 常见器件 |
| --- | --- |
| 外部存储 | SPI Flash、Nor Flash、Nand Flash |
| 显示设备 | LCD、OLED、墨水屏 |
| 高速采集 | ADC、DAC、高速传感器 |
| 通信模块 | Wi-Fi、蓝牙、射频模块 |
| 触摸和控制 | 触摸 IC、IO 扩展芯片 |

简单记法：

- `SCLK`：Serial Clock，时钟线，由主机输出。
- `MOSI`：Master Out Slave In，主机发、从机收。
- `MISO`：Master In Slave Out，主机收、从机发。
- `CS/SS`：Chip Select / Slave Select，片选信号，用来选中从设备。

## 2. SPI 在嵌入式项目里做什么

SPI 通常用于比 I2C 更高速的数据传输，常见于显示、存储和高速外设。

以主控读取 SPI Flash 的 ID 为例，SPI 的工作可以理解为：

1. 主控拉低片选 `CS`。
2. 主控输出 `SCLK` 时钟。
3. 主控通过 `MOSI` 发送读 ID 命令。
4. Flash 通过 `MISO` 返回 ID 数据。
5. 主控拉高片选 `CS`，结束本次通信。

也就是说，SPI 更像一条高速直连通道：

- 主机负责产生时钟和片选。
- 从设备被片选后才参与通信。
- 主发和主收可以在同一批时钟里同时发生。
- 数据含义由具体芯片手册定义。

## 3. SPI 的四根基本信号线

标准 SPI 最常见的是四线：

| 信号 | 方向 | 含义 |
| --- | --- | --- |
| `SCLK` | 主机到从机 | 时钟线 |
| `MOSI` | 主机到从机 | 主机发送数据 |
| `MISO` | 从机到主机 | 从机返回数据 |
| `CS/SS` | 主机到从机 | 片选信号 |

注意：

- `CS` 通常低电平有效。
- 一个主机可以接多个从设备，但每个从设备通常需要独立片选。
- 没有被片选的从设备一般不应该驱动 `MISO`。

直白说法：

> SPI 通过 SCLK 给节拍，通过 MOSI 发数据，通过 MISO 收数据，通过 CS 选择正在说话的那个从设备。

## 4. SPI 的线制扩展：单线、双线、四线、八线，以及全双工/半双工

SPI 最容易混淆的一点，是“几线 SPI”可能是在数**数据线宽度**，也可能是在数板上接了几根信号线。下面的“单线、双线、四线、八线”通常指一次时钟传输时参与数据传输的位数，而不是把 `SCLK`、`CS` 也算进去后的总线数。

### 4.1 先区分两种说法

| 说法 | 通常表示什么 | 典型信号 |
| --- | --- | --- |
| 标准“四线 SPI” | 四根基本信号线 | `SCLK`、`MOSI`、`MISO`、`CS` |
| 单线 / Single SPI | 每个方向每拍传 1 bit | 常用 `MOSI` 和 `MISO`，或一个共享 `IO` |
| 双线 / Dual SPI | 数据阶段每拍传 2 bit | `IO0`、`IO1` |
| 四线 / Quad SPI（QSPI） | 数据阶段每拍传 4 bit | `IO0` ~ `IO3` |
| 八线 / Octal SPI（OSPI/OPI） | 数据阶段每拍传 8 bit | `IO0` ~ `IO7`，部分器件还有 `DQS` |

所以，标准“四线 SPI”不等于 QSPI：前者强调 `SCLK + MOSI + MISO + CS` 这四根基础信号，后者强调同一时钟下可用 4 根数据线并行传输。

### 4.2 单线 SPI：最常见的标准 SPI

单线 SPI（Single SPI）通常指数据宽度为 1 bit：每个时钟周期，数据线一次传 1 bit。

- **标准四线、全双工接法**：`MOSI` 和 `MISO` 分开，主机可同时发 1 bit、收 1 bit。
- **三线 / 单数据线接法**：`MOSI` 和 `MISO` 合并为一根双向 `SDIO/IO`，发送和接收轮流进行。
- 常见于普通传感器、ADC、DAC、显示控制器和低速配置接口。

```text
标准单线全双工：
主机 -- MOSI --> 从机    每拍可发 1 bit
主机 <-- MISO -- 从机    同一拍可收 1 bit

单数据线半双工：
主机 <------ IO ------> 从机    同一时刻只能由一方驱动
```

### 4.3 双线、四线、八线 SPI：用更多数据线提高吞吐量

扩展 SPI 会在数据阶段并行使用多根 `IO/DQ` 线。时钟仍然由主机提供，`CS` 仍然用于选择器件；增加的是数据通道宽度。

| 类型 | 数据线数 | 每个时钟可传数据量 | 常见应用 |
| --- | --- | --- | --- |
| Single SPI | 1 | 1 bit | 普通外设、兼容模式 Flash |
| Dual SPI | 2 | 2 bit | Dual Flash、部分高速外设 |
| Quad SPI / QSPI | 4 | 4 bit | NOR Flash、XIP 代码读取 |
| Octal SPI / OSPI / OPI | 8 | 8 bit | 高性能 NOR Flash、大容量外部存储 |

例如，同样使用 50 MHz 时钟、都采用 SDR（单沿传输）时，单方向的理论数据线吞吐量大致是：Single 为 50 Mbit/s、Dual 为 100 Mbit/s、Quad 为 200 Mbit/s、Octal 为 400 Mbit/s。标准单线全双工可同时拥有一个发送方向和一个接收方向；实际速度还会受命令、地址、dummy cycle、片选间隔和控制器效率影响，不能只按倍数估算有效读写速度。

很多 Flash 的一次读操作不是从头到尾都使用多线：命令和地址阶段可能仍是单线，之后的数据阶段才切到双线、四线或八线。例如手册中的 `1-1-4` 往往表示“命令单线、地址单线、数据四线”；`1-4-4` 则表示“命令单线、地址四线、数据四线”。具体编码以芯片手册为准。

### 4.4 全双工和半双工

| 方式 | 数据线组织 | 是否能在同一时钟内同时收发 | 常见场景 |
| --- | --- | --- | --- |
| 全双工 | 发送、接收各有独立方向的线，例如 `MOSI` + `MISO` | 可以 | 标准四线 SPI、边发边收的移位寄存器类器件 |
| 半双工 | 多根或一根数据线在发送和接收阶段复用，方向需要切换 | 不可以 | 3-wire SPI、Dual/Quad/Octal Flash 读写数据阶段 |

标准 SPI 从电气能力上通常是全双工：主机每输出一个时钟，既可以从 `MOSI` 送出一位，也可以从 `MISO` 收回一位。但很多具体协议的命令阶段只要求主机发送，读数据阶段只要求从机输出，因此一次事务在**协议层面**看起来仍像“先写、再读”。

Dual/Quad/Octal SPI 中的 `IO0` ~ `IOn` 常常都是双向线：写数据时由主机驱动，读数据时由从机驱动。这类用法通常属于半双工，切换方向时要遵守芯片规定的 turnaround / dummy cycle；否则双方同时驱动数据线，可能造成数据错误甚至总线冲突。

### 4.5 常见名称和使用注意点

- **3-wire SPI**：通常是 `SCLK + CS + 一根双向数据线`，本质是单数据线半双工；但少数芯片的命名会不同，必须看引脚说明。
- **QSPI / OSPI**：常用于 Flash，不是所有 SPI 控制器都支持。主控的“QSPI 外设”往往还带 memory-mapped / XIP 等存储访问功能。
- **DDR / DTR 模式**：部分 Octal Flash 可在时钟上升沿和下降沿都传数据；这提高的是每根数据线每周期的传输次数，和增加数据线数量是两个维度。
- **显示屏的“4-wire SPI”**：有时实际是 `SCLK`、`MOSI`、`CS`、`DC`，其中 `DC` 是数据/命令选择而不是 SPI 数据线；它仍可能是单线、只写、半双工接口，并不等于 QSPI。
- **引脚复用**：不少 Flash 在普通 SPI 模式下把 `IO0` 当 `MOSI`、`IO1` 当 `MISO`，进入 Quad/Octal 模式后这些脚才改为双向数据线；未按手册使能模式时，多线读写不会生效。

### 4.6 QSPI 和 QPI：接线相同，传输阶段不同

在支持 Quad 的 SPI Flash 上，QSPI 和 QPI 通常使用的是同一组物理引脚：`CS`、`SCLK`、`IO0`、`IO1`、`IO2`、`IO3`。因此原理图上的接线看起来完全一样；不同名字描述的是**命令、地址、数据这三个阶段分别用了几根数据线**，不是描述引脚数量。

| 模式 | 命令阶段 | 地址阶段 | 数据阶段 | 常见写法 |
| --- | --- | --- | --- | --- |
| QSPI / Quad 模式 | 通常单线 | 单线或四线 | 四线 | `1-1-4`、`1-4-4` |
| QPI（Quad Peripheral Interface） | 四线 | 四线 | 四线 | `4-4-4` |

例如，`1-4-4` 表示命令在 `IO0` 上单线发送，地址和数据使用 `IO0` ~ `IO3` 四线传输；`4-4-4` 则表示从命令 opcode 开始就由四根 IO 线并行传输。按常见 Flash 定义，QPI 的命令、地址和数据始终使用四根 IO，而 QSPI 的命令通常仍走单线。Winbond 对两者的说明也采用这一划分：[What is the difference between QSPI and QPI?](https://www.winbond.com/hq/support/faq/technical/?__locale=en)

直白理解：

> QSPI 和 QPI 的“路”是同一组 `IO0` ~ `IO3`，但 QSPI 往往先用一条路报出命令，再把四条路用于传地址和数据；QPI 从报命令开始就四条路一起用。

QPI 的优势主要是缩短命令和地址阶段的时钟开销；对于连续的大块数据读取，二者的数据阶段都可能是四线，实际增益未必成倍。使用时还要注意：有些 Flash 需要先发送厂商规定的“进入 QPI”指令，进入后普通单线指令可能不再可用，必须用 QPI 方式退出或复位；主控的 QSPI 外设也不一定支持 `4-4-4` 时序。因此，最终应以目标 Flash 的指令表和主控参考手册为准。

面试或项目描述时可以这样说：

> 标准 SPI 常用 MOSI 和 MISO 实现全双工；为了提升 Flash 等存储器的数据吞吐量，可以把数据阶段扩展为 Dual、Quad 或 Octal。多线 SPI 通常复用双向 IO，因此一个数据阶段通常按半双工工作，实际命令、地址和数据各用几根线要以芯片手册为准。

## 5. SPI 为什么通常速度比 I2C 高

SPI 常见速度比 I2C 高，原因包括：

- SPI 一般是推挽输出，边沿更快。
- SPI 不需要每个字节都等 ACK。
- SPI 没有总线地址阶段，片选直接选设备。
- SPI 可以全双工，同时发送和接收。
- SPI 协议本身更简单，开销更小。

但这不代表 SPI 一定更好。

SPI 的代价是：

- 线更多。
- 从设备多时片选线会增加。
- 没有标准 ACK，出错检测通常要靠上层协议或芯片状态寄存器。
- 高速时更依赖布线、时钟质量和采样时序。

## 6. SPI 的 CPOL 和 CPHA

SPI 最容易把人绕住的概念是 `CPOL` 和 `CPHA`。

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| `CPOL` | Clock Polarity，时钟极性 | 决定 SCLK 空闲时是高电平还是低电平 |
| `CPHA` | Clock Phase，时钟相位 | 决定在第几个边沿采样数据 |

### 6.1 CPOL

`CPOL` 决定时钟空闲状态：

| CPOL | SCLK 空闲电平 |
| --- | --- |
| `0` | 低电平 |
| `1` | 高电平 |

### 6.2 CPHA

`CPHA` 决定采样发生在哪个时钟边沿：

| CPHA | 通俗理解 |
| --- | --- |
| `0` | 第一个有效边沿采样 |
| `1` | 第二个有效边沿采样 |

### 6.3 SPI 四种模式

CPOL 和 CPHA 组合成四种常见模式：

| 模式 | CPOL | CPHA | 常见说法 |
| --- | --- | --- | --- |
| `Mode 0` | 0 | 0 | 空闲低，第一个边沿采样 |
| `Mode 1` | 0 | 1 | 空闲低，第二个边沿采样 |
| `Mode 2` | 1 | 0 | 空闲高，第一个边沿采样 |
| `Mode 3` | 1 | 1 | 空闲高，第二个边沿采样 |

重点：

> 主机和从机的 SPI Mode 必须一致。模式配错时，常见现象是读出来的数据整体不对、偶发错位，或者完全读不到正确 ID。

## 7. SPI 的片选 CS

SPI 不像 I2C 那样靠设备地址区分从设备，SPI 通常靠片选线选择设备。

典型规则：

- `CS` 拉低：选中从设备。
- `CS` 拉高：释放从设备，通信结束。
- 多个从设备共享 `SCLK/MOSI/MISO` 时，每个从设备通常单独接一根 `CS`。

示例：

```text
CS 拉低 -> 发送命令 -> 发送/接收数据 -> CS 拉高
```

注意：

- 有些芯片要求一次命令期间 `CS` 不能中途拉高。
- 有些芯片会在 `CS` 拉高后才真正提交操作。
- 多个从设备共用总线时，不能同时选中两个会驱动 `MISO` 的设备。

直白说法：

> SPI 的 CS 就像“点名”。主机先点名某个芯片，那个芯片才开始听命令和回数据。

## 8. SPI 写数据和读数据流程

### 8.1 写数据流程

以写寄存器为例，典型流程：

1. 主机拉低 `CS`。
2. 主机发送写命令。
3. 主机发送寄存器地址。
4. 主机发送要写入的数据。
5. 主机拉高 `CS`。

示例：

```text
CS Low -> WriteCmd -> RegAddr -> Data -> CS High
```

### 8.2 读数据流程

以读寄存器为例，典型流程：

1. 主机拉低 `CS`。
2. 主机发送读命令。
3. 主机发送寄存器地址。
4. 主机继续输出时钟。
5. 从机通过 `MISO` 返回数据。
6. 主机拉高 `CS`。

示例：

```text
CS Low -> ReadCmd -> RegAddr -> DummyClock -> DataOut -> CS High
```

为什么读数据时主机还要发送时钟：

- SPI 是同步通信，从机不能自己产生时钟。
- 主机要继续输出 `SCLK`，从机才有节拍把数据移出来。
- 有些控制器读数据时会在 `MOSI` 上发送 dummy byte，例如 `0x00` 或 `0xFF`。

直白说法：

> SPI 读数据不是从机主动吐数据，而是主机继续打时钟，从机跟着节拍把数据送出来。

## 9. SPI 常见速率和数据宽度

SPI 没有像 I2C 那样固定的标准速率表，具体速度取决于主控、从设备和板级硬件。

常见范围：

| 场景 | 常见速率 |
| --- | --- |
| 低速传感器 | 几百 kHz 到几 MHz |
| 普通外设 | 1 MHz 到 10 MHz |
| SPI Flash | 十几 MHz 到几十 MHz |
| QSPI/OSPI Flash | 更高，取决于芯片和布线 |

常见数据宽度：

- 8 bit 最常见。
- 有些控制器支持 16 bit 或 32 bit。
- 也有双线、四线、八线 SPI 扩展，例如 Dual SPI、Quad SPI、Octal SPI。

注意：

> 速率越高，对线长、阻抗、采样时序、驱动能力和电源噪声越敏感。调试时不要只看软件配置，还要看波形。

## 10. 驱动里容易出问题的点

做 SPI 驱动时，常见问题通常集中在模式、片选、命令格式和时序。

常见风险：

- **CPOL/CPHA 配错**：采样边沿不对，数据错位或读值异常。
- **片选极性配错**：从设备没有真正被选中。
- **片选时序不对**：命令过程中 CS 被提前拉高或延时不足。
- **MOSI/MISO 接反**：只能发不能收，或者完全无响应。
- **速率过高**：低速器件或板级波形不支持。
- **命令格式错**：读写命令、地址长度、dummy cycle 不符合手册。
- **字节序错误**：多字节数据高低位拼接反了。
- **多个设备 MISO 冲突**：两个从设备同时驱动 MISO。
- **GPIO 复用错误**：SCLK/MOSI/MISO/CS 没切到 SPI 功能。
- **电平不匹配**：主控和从设备 I/O 电压不一致。

## 11. SPI 不通怎么排查

排查建议先确认硬件和基础配置，再看协议波形。

### 11.1 先确认硬件连接

检查点：

- `SCLK` 是否接到从设备时钟脚。
- `MOSI` 和 `MISO` 有没有接反。
- `CS` 是否接对，极性是否正确。
- 主控和从设备是否共地。
- 从设备供电是否正常。
- I/O 电平是否匹配。
- 复位脚、写保护脚、保持脚是否处于正确状态。

### 11.2 再确认软件配置

检查点：

- SPI 控制器编号是否选对。
- 引脚复用是否正确。
- `CPOL/CPHA` 是否和芯片手册一致。
- 片选方式是硬件 CS 还是 GPIO CS。
- SPI 速率是否超过从设备上限。
- 数据位宽和字节序是否正确。
- 命令、地址、dummy cycle 是否符合手册。

### 11.3 看片选和时钟

如果完全无响应，先看：

- `CS` 有没有被拉低。
- `SCLK` 有没有输出。
- `MOSI` 上有没有命令数据。
- `MISO` 是否一直高、一直低或高阻。

如果 `CS` 和 `SCLK` 都正常，但数据不对，重点看：

- SPI Mode 是否匹配。
- 采样边沿是否正确。
- 速率是否过高。
- 从设备是否需要 dummy cycle。
- 命令地址格式是否正确。

### 11.4 用示波器或逻辑分析仪看波形

重点看：

- `CS` 拉低到第一个时钟之间的延时。
- `SCLK` 空闲电平和采样边沿。
- `MOSI` 命令是否和手册一致。
- `MISO` 是否在正确边沿变化。
- 时钟频率是否符合配置。
- `CS` 是否在一次事务中异常跳变。

直白说法：

> SPI 不通时，先看有没有片选和时钟；有时钟再看模式和命令；有命令再看 MISO 有没有按节拍回数据。

## 12. 面试常见问法和直白回答

### 12.1 SPI 是什么

> SPI 是一种同步、主从式、常见全双工的串行通信接口。主机通过 SCLK 提供时钟，通过 MOSI 发送数据，通过 MISO 接收数据，通过 CS 选择从设备。

### 12.2 SPI 为什么速度通常比 I2C 快

> SPI 没有地址阶段和 ACK 开销，通常使用推挽输出，主机通过片选直接选择设备，并且可以全双工传输，所以在很多场景下速度比 I2C 更高。

### 12.3 MOSI 和 MISO 分别是什么

> MOSI 是 Master Out Slave In，表示主机发给从机的数据线；MISO 是 Master In Slave Out，表示从机返回给主机的数据线。

### 12.4 CPOL 和 CPHA 是什么

> CPOL 表示时钟空闲电平，CPHA 表示数据在哪个时钟边沿采样。二者组合成 SPI Mode 0 到 Mode 3，主机和从机必须配置一致。

### 12.5 SPI 读数据为什么还要发 dummy byte

> 因为 SPI 从机不能自己产生时钟，主机必须继续输出 SCLK，从机才能把数据移出来。控制器读数据时通常会发送 dummy byte 来产生这些时钟。

### 12.6 SPI 多个从设备怎么连接

> 多个从设备可以共享 SCLK、MOSI、MISO，但每个从设备通常需要独立 CS。通信时主机只拉低目标设备的 CS，其他设备保持未选中状态。

### 12.7 SPI 没有响应怎么排查

> 先看供电、复位、片选、时钟和引脚复用；再确认 MOSI/MISO 有没有接反、CPOL/CPHA 是否正确、速率是否过高、命令和地址格式是否符合芯片手册。

## 13. 高频易错点

| 错误说法 | 更准确的说法 |
| --- | --- |
| SPI 只要接四根线就能通信 | 还要配置正确的片选、模式、速率、命令和引脚复用 |
| SPI 不需要片选 | 标准多从机场景通常靠 CS 选择设备 |
| SPI Mode 随便选 | 主机和从机的 CPOL/CPHA 必须一致 |
| 读 SPI 时从机会主动发数据 | 主机必须继续给时钟，从机才会移出数据 |
| SPI 一定比 I2C 好 | SPI 速度高，但线更多，片选更多，缺少标准 ACK |
| MISO 可以多个从设备同时驱动 | 未选中的从设备应释放 MISO，否则会总线冲突 |
| 速率越高越好 | 高速 SPI 更依赖布线、时序、电源和器件能力 |
| CS 拉高拉低无所谓 | 很多芯片靠 CS 边沿识别一笔完整事务 |

## 14. 最简记忆版

只想快速记住，可以背下面几句：

- SPI 是同步、主从式、常见全双工串行接口。
- `SCLK` 给时钟，`MOSI` 主发从收，`MISO` 主收从发，`CS` 选择从设备。
- SPI 通常比 I2C 快，但线更多。
- `CPOL` 决定时钟空闲电平，`CPHA` 决定采样边沿。
- SPI Mode 0/1/2/3 必须和从设备手册一致。
- SPI 读数据时主机也要继续输出时钟。
- 多个从设备共享数据线时，片选不能乱。
- SPI 不通先查供电、复位、片选、时钟、模式、速率和命令格式。
