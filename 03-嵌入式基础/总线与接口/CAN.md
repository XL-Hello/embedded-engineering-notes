# CAN 基础知识总结

> 目标：这篇文档只作为 CAN 入门和项目面试复习使用，不展开复杂的汽车网络架构、功能安全和控制器内部实现。重点记住：CAN 是什么、CAN_H/CAN_L 怎么工作、仲裁和报文 ID 的意义、数据帧格式、ACK 和错误处理、常见问题怎么排查。
>
> 来源：围绕 CAN 主题AI整理的基础总结文档，本人除了课本上，未接触过CAN相关的内容，所以仅供参考，适合扫盲。

## 1. 先用一句话理解 CAN

**CAN 是一种多主、差分、广播式、可靠性较高的串行通信总线。**

它最典型的特点是：

- 使用两根差分信号线：`CAN_H` 和 `CAN_L`。
- 总线上多个节点都可以主动发送数据。
- 报文不是按设备地址发送，而是按 `ID` 标识数据含义和优先级。
- 通过非破坏性仲裁解决多个节点同时发送的问题。
- 具备 CRC、ACK、错误计数、错误帧等机制，可靠性比普通串口更强。

常见用途：

| 用途 | 常见场景 |
| --- | --- |
| 汽车电子 | ECU、仪表、BMS、车身控制、底盘控制 |
| 工业控制 | PLC、伺服、电机驱动、传感器网络 |
| 电池和电源系统 | BMS、电池包、充电设备 |
| 机器人和设备内部通信 | 控制板、执行器、传感器模块 |
| 工程机械和农机 | 控制器、仪表、执行机构 |

简单记法：

- `CAN_H`：差分高线。
- `CAN_L`：差分低线。
- `Node`：总线上的一个通信节点。
- `ID`：报文标识符，同时影响仲裁优先级。
- `Frame`：CAN 总线上传输的一帧报文。

## 2. CAN 在嵌入式项目里做什么

CAN 通常不是简单地“主机访问从机”，而是多个控制器在同一条总线上广播状态、命令和诊断信息。

以 BMS 给整车控制器发送电池状态为例，可以理解为：

1. BMS 节点准备一帧电池电压、电流、SOC 等数据。
2. BMS 使用约定好的 CAN ID 发送报文。
3. 总线上所有节点都能看到这帧报文。
4. 关心这个 ID 的节点接收并解析数据。
5. 不关心这个 ID 的节点通过过滤器或软件逻辑忽略它。

也就是说，CAN 更像一条共享广播总线：

- 每个节点都可以发送。
- 报文 ID 表示“这是什么数据”，不是“发给谁”。
- 接收方根据 ID 决定是否处理。
- 总线通过仲裁机制保证高优先级报文先发送。

## 3. CAN_H 和 CAN_L 为什么用差分信号

CAN 使用差分传输，核心信号是 `CAN_H` 和 `CAN_L` 之间的电压差。

这样设计的好处是：

- 抗干扰能力强。
- 适合较长线缆和复杂电磁环境。
- 共模噪声对两根线影响相近，接收端看差值时可以抵消一部分干扰。
- 比单端信号更适合汽车和工业现场。

直白理解：

> CAN 接收器主要看 CAN_H 和 CAN_L 之间的差值，而不是单独看某一根线对地电压。两根线一起被干扰时，差值变化较小，所以抗干扰能力更强。

### 3.1 显性电平和隐性电平

CAN 总线上常说的两种逻辑状态是：

| 状态 | 逻辑含义 | 总线表现 |
| --- | --- | --- |
| `Dominant` | 显性，通常表示逻辑 0 | `CAN_H` 升高，`CAN_L` 降低，形成明显差分电压 |
| `Recessive` | 隐性，通常表示逻辑 1 | `CAN_H` 和 `CAN_L` 电压接近，差分电压较小 |

重点：

- 显性位会覆盖隐性位。
- 多个节点同时发送时，只要有节点发送显性位，总线就表现为显性。
- 仲裁机制就是利用这个特性实现的。

直白说法：

> CAN 总线上 0 比 1 更“强”。如果一个节点发 0，另一个节点发 1，总线上看到的是 0。

## 4. CAN 为什么需要终端电阻

CAN 总线两端通常需要各接一个 `120Ω` 终端电阻。

它的作用主要是：

- 减少信号反射。
- 保持总线阻抗匹配。
- 提高长线或高速通信时的波形质量。

常见结构：

```text
节点A ---- 节点B ---- 节点C ---- 节点D
  |                              |
120Ω                           120Ω
```

注意：

- 终端电阻应该放在总线物理两端，而不是每个节点都放。
- 两个 `120Ω` 并联后，用万用表量 CAN_H 和 CAN_L，常见等效电阻约为 `60Ω`。
- 如果电阻太多，负载过重；如果缺少终端，波形容易反射、通信不稳定。

## 5. CAN 报文 ID 和仲裁

### 5.1 CAN ID 是什么

CAN 报文中没有传统意义上的目标设备地址，核心标识是 `ID`。

`ID` 的作用有两个：

- 表示报文内容类型，例如电池状态、车速、温度、控制命令。
- 参与总线仲裁，ID 数值越小，优先级越高。

常见 ID 类型：

| 类型 | ID 长度 | 常见叫法 |
| --- | --- | --- |
| 标准帧 | 11 bit | Standard ID |
| 扩展帧 | 29 bit | Extended ID |

### 5.2 仲裁是怎么工作的

当多个节点同时发送报文时，CAN 不会让它们直接冲突损坏数据，而是逐位比较 ID。

仲裁规则可以简单理解为：

- 每个发送节点一边发送，一边监听总线实际电平。
- 如果自己发送隐性位 `1`，但总线实际是显性位 `0`，说明有更高优先级报文在发送。
- 该节点立刻退出发送，等待下一次机会。
- 发送显性位的一方继续发送，报文不会被破坏。

示例：

```text
节点A ID: 0x100
节点B ID: 0x080

ID 数值更小的 0x080 优先级更高，所以节点B 会赢得仲裁。
```

直白说法：

> CAN 的仲裁不是靠先抢到总线的人赢，而是靠 ID 优先级决定。ID 越小，越容易先发出去。

## 6. CAN 数据帧基本格式

常见 CAN 数据帧可以粗略分成以下部分：

| 字段 | 含义 |
| --- | --- |
| `SOF` | 帧起始 |
| `ID` | 报文标识符 |
| `RTR` | 区分数据帧和远程帧 |
| `Control` | 控制字段，包含数据长度等信息 |
| `Data` | 数据区，经典 CAN 最多 8 字节 |
| `CRC` | 循环冗余校验 |
| `ACK` | 应答位 |
| `EOF` | 帧结束 |

经典 CAN 的数据区长度是 `0 ~ 8` 字节。

如果是 CAN FD：

- 数据区可以超过 8 字节，最大可到 64 字节。
- 数据阶段可以使用更高比特率。
- 需要控制器、收发器和网络中其他节点都支持 CAN FD。

不要把经典 CAN 和 CAN FD 混在一起理解。实际项目里要先确认硬件和协议栈支持哪一种。

## 7. CAN 的 ACK 是什么

CAN 的 ACK 和 I2C 的 ACK 不完全一样。

在 CAN 中：

- 发送节点发送完整报文后，会在 ACK 位释放总线。
- 任意一个正确接收到该报文的节点，都可以在 ACK 位发送显性位。
- 发送节点检测到 ACK，说明总线上至少有一个节点正确收到了这帧。

重点：

- ACK 不代表目标应用已经处理成功。
- ACK 只说明物理总线上有节点正确接收并通过校验。
- 如果总线上只有一个发送节点，没有其他节点应答，发送端可能会报 ACK 错误。

直白说法：

> CAN 的 ACK 是“总线上有人正确收到了”，不是“指定对象已经执行命令了”。

## 8. CAN 位时序和波特率

CAN 常见波特率有：

| 波特率 | 常见理解 |
| --- | --- |
| `125 kbps` | 低速、线缆较长场景常见 |
| `250 kbps` | 工业和车载场景常见 |
| `500 kbps` | 经典 CAN 中很常见 |
| `1 Mbps` | 经典 CAN 较高速率，对线长和布线要求更高 |

配置 CAN 波特率时，不能只看一个频率数字，还要关注位时序参数：

- 同步段。
- 传播段。
- 相位缓冲段 1。
- 相位缓冲段 2。
- 采样点。
- 同步跳转宽度 `SJW`。

实际项目里最常见的问题是：

- 两个节点波特率不一致。
- 波特率看起来一样，但采样点或时序参数不匹配。
- 控制器时钟源配置错误，导致实际波特率偏差。

直白说法：

> CAN 通信双方不仅要“波特率一样”，位时序也要合理。时钟源配错时，软件里写 500 kbps，线上不一定真是 500 kbps。

## 9. CAN 过滤器有什么用

CAN 是广播式总线，所有节点理论上都能看到总线上的所有报文。

过滤器的作用是：

- 在硬件层面筛选需要接收的 ID。
- 减少 CPU 中断和软件处理压力。
- 只让关心的报文进入接收 FIFO 或邮箱。

常见过滤方式：

| 方式 | 含义 |
| --- | --- |
| 精确匹配 | 只接收某一个 ID |
| 掩码匹配 | 接收一组符合规则的 ID |
| 全接收 | 调试时接收所有报文 |

调试阶段可以先配置成全接收，确认总线上是否有报文；稳定后再收窄过滤范围。

## 10. 驱动里容易出问题的点

做 CAN 驱动时，常见问题通常集中在硬件连接、波特率、过滤器和收发器状态。

常见风险：

- **CAN_H 和 CAN_L 接反**：多数情况下无法正常通信。
- **缺少共地**：差分信号也需要合理的参考地和共模范围。
- **终端电阻错误**：缺少、过多或位置不对都会影响波形。
- **波特率不一致**：节点之间无法正确解析帧。
- **位时序参数不合适**：采样点错误导致偶发错误帧。
- **收发器未使能**：`STB`、`EN`、`SILENT` 等引脚状态不对。
- **控制器模式错误**：还停在初始化、回环、静默或监听模式。
- **过滤器配置过窄**：总线上有报文，但软件收不到。
- **ID 类型不匹配**：标准帧和扩展帧混用。
- **数据字节顺序错误**：协议解析高低字节或大小端弄反。
- **总线负载过高**：报文太密，低优先级消息延迟变大。
- **节点错误状态异常**：进入 error passive 或 bus off 后不再正常发送。

## 11. CAN 不通怎么排查

排查建议从硬件、电气、控制器配置、协议解析逐层看。

### 11.1 先确认硬件连接

检查点：

- `CAN_H` 和 `CAN_L` 有没有接反。
- 节点之间是否共地。
- CAN 收发器供电是否正常。
- 收发器使能、待机、静默模式引脚是否正确。
- 总线两端是否各有一个 `120Ω` 终端电阻。
- 用万用表量 `CAN_H` 和 `CAN_L` 等效电阻是否接近 `60Ω`。
- 线缆是否过长、分支是否过长、接插件是否接触不良。

### 11.2 再确认软件配置

检查点：

- CAN 控制器编号是否选对。
- GPIO 复用是否配置正确。
- 控制器时钟源是否正确。
- 波特率和位时序是否与其他节点一致。
- 控制器是否已经退出初始化模式。
- 是否处于回环、静默、监听等特殊模式。
- 过滤器是否允许目标 ID 进入接收 FIFO。
- 标准帧和扩展帧配置是否匹配。

### 11.3 看总线上有没有波形

用示波器或逻辑分析仪重点看：

- 发送时 `CAN_H` 和 `CAN_L` 是否有差分变化。
- 差分电压是否正常。
- 波特率是否接近配置值。
- 是否有 ACK 位。
- 是否频繁出现错误帧。
- 波形边沿是否反射、过冲或振铃明显。

如果 TX 引脚有波形，但 CAN_H/CAN_L 没波形，优先怀疑：

- 收发器未供电。
- 收发器未使能。
- 控制器和收发器连接错误。
- 收发器损坏。

### 11.4 有发送但没有 ACK 怎么办

如果发送端一直报 ACK 错误，优先怀疑：

- 总线上只有一个节点，没人应答。
- 其他节点没有上电或没有正常工作。
- 波特率或位时序不一致。
- CAN_H/CAN_L 接反或断线。
- 终端电阻或线缆问题导致接收失败。
- 对端处于静默模式，只监听不应答。

### 11.5 能收到但数据不对怎么办

如果能收到报文，但解析结果不对，优先怀疑：

- ID 对应关系理解错。
- 标准帧和扩展帧弄混。
- 数据字节顺序错。
- 信号起始位、长度、缩放系数、偏移量解析错。
- 有符号数和无符号数处理错。
- 不同协议版本的报文定义不一致。

## 12. 面试常见问法和直白回答

### 12.1 CAN 是什么

> CAN 是一种多主、广播式、差分串行通信总线，常用于汽车电子和工业控制。它通过报文 ID 标识数据类型和仲裁优先级，具备 CRC、ACK、错误处理等机制，可靠性比较高。

### 12.2 CAN 为什么抗干扰能力强

> 因为 CAN 使用 CAN_H 和 CAN_L 差分传输，接收端主要看两根线之间的电压差。外界噪声同时影响两根线时，差分值变化相对较小，所以抗干扰能力比单端信号强。

### 12.3 CAN 的显性和隐性是什么意思

> 显性位通常表示逻辑 0，隐性位通常表示逻辑 1。显性位会覆盖隐性位，所以多个节点同时发送时，只要有节点发 0，总线就表现为 0。CAN 仲裁就是利用这个特性实现的。

### 12.4 CAN ID 有什么作用

> CAN ID 不是设备地址，而是报文标识符。它表示这帧数据的含义，同时也决定仲裁优先级。ID 数值越小，优先级越高。

### 12.5 CAN 如何解决多个节点同时发送

> 多个节点同时发送时，会一边发送一边监听总线。谁发送隐性位但读到显性位，说明自己优先级低，就退出发送；优先级更高的报文继续发送，数据不会被破坏。

### 12.6 CAN 为什么要终端电阻

> 终端电阻用于阻抗匹配和减少信号反射。典型 CAN 总线两端各接一个 120Ω 电阻，用万用表量 CAN_H 和 CAN_L 时，常见等效电阻约为 60Ω。

### 12.7 CAN 的 ACK 表示什么

> CAN 的 ACK 表示总线上至少有一个节点正确接收到了该帧，并通过校验后在 ACK 位应答。它不代表应用层已经处理成功，也不代表某个指定节点一定收到了。

### 12.8 CAN 收不到数据怎么排查

> 先查硬件连接、供电、收发器使能、终端电阻和 CAN_H/CAN_L；再查波特率、位时序、控制器模式、GPIO 复用和过滤器；最后用示波器或 CAN 分析仪看总线上是否有波形、ACK 和错误帧。

### 12.9 标准帧和扩展帧有什么区别

> 标准帧使用 11 位 ID，扩展帧使用 29 位 ID。两者 ID 长度不同，驱动和过滤器配置也要对应，否则可能出现总线上有报文但软件收不到的情况。

### 12.10 CAN 和 RS485 有什么区别

> RS485 主要定义物理层差分传输，具体协议要自己设计；CAN 不仅有差分物理层，还定义了帧格式、仲裁、ACK、CRC 和错误处理机制。CAN 更像完整总线协议，RS485 更像一种常用物理接口。

## 13. 高频易错点

| 错误说法 | 更准确的说法 |
| --- | --- |
| CAN 是主从通信 | CAN 是多主广播式通信，任意节点都可以发送 |
| CAN ID 是设备地址 | CAN ID 表示报文含义和优先级，不是目标地址 |
| ID 越大优先级越高 | ID 数值越小，仲裁优先级越高 |
| CAN 只要两根线就行 | 还要供电、共地、收发器、终端电阻和正确布线 |
| 差分信号就完全不需要地 | 实际系统仍需要合理参考地和共模范围 |
| 终端电阻每个节点都要接 | 通常只在总线物理两端各接一个 120Ω |
| 有 ACK 就代表应用处理成功 | ACK 只代表至少一个节点正确接收了物理帧 |
| 波特率一样就一定能通信 | 位时序、采样点、时钟源也要匹配 |
| 收不到报文一定是总线没数据 | 也可能是过滤器太窄、模式错误或 ID 类型不匹配 |
| CAN FD 和经典 CAN 可以随便混用 | CAN FD 需要硬件、控制器、收发器和网络节点共同支持 |

## 14. 最简记忆版

只想快速记住，可以背下面几句：

- CAN 是多主、广播式、差分串行总线。
- CAN 用 `CAN_H` 和 `CAN_L` 传输差分信号，抗干扰能力强。
- CAN 报文靠 ID 表示数据含义和仲裁优先级，不靠设备地址。
- ID 数值越小，优先级越高。
- 显性位通常是 0，隐性位通常是 1，显性会覆盖隐性。
- 经典 CAN 一帧最多 8 字节数据，CAN FD 可以更多。
- CAN 总线两端通常各接一个 `120Ω` 终端电阻，等效约 `60Ω`。
- CAN 的 ACK 只表示总线上有人正确收到了帧，不代表应用处理完成。
- CAN 不通先查 CAN_H/CAN_L、共地、终端电阻、收发器使能、波特率、位时序和过滤器。
