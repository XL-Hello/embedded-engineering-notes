# CAN 系列文档导读

CAN 这个主题按**问题类型**拆成四篇，而不是按知识点深浅拆。判断自己该看哪一篇，只需要回答一个问题：**你现在卡在哪一步？**

| 文档 | 标题 | 回答的问题 | 适用阶段 |
| --- | --- | --- | --- |
| [CAN_v0.1.md](CAN_v0.1.md) | CAN 基础知识总结 | 它是什么、CAN_H/CAN_L 怎么工作、仲裁和 ID 什么意义、帧长什么样、不通怎么查 | 入门、面试复习、快速建立概念 |
| [CAN_v0.2.md](CAN_v0.2.md) | CAN FD 和 CAN XL 基础知识总结 | 经典 CAN 卡在哪里、FD 和 XL 各改了什么、三代差在哪、能不能混在一条总线上、怎么选 | 要选协议版本，或面对混合网络 |
| [CAN_v0.3.md](CAN_v0.3.md) | CAN 进阶：从一个位算到一条总线 | 位时序怎么算、采样点定在哪、时钟容差够不够、总线负载和最坏响应时间是多少 | 参数要自己算出来并验证 |
| [CAN_v0.4.md](CAN_v0.4.md) | CAN 落地：单帧之上的协议栈与软件实现 | 每个字节表示什么、装不下怎么分段、诊断和刷写怎么做、整网怎么休眠、代码写在哪一层 | 总线已经能跑，要把业务做出来 |

四篇的交接点很清晰：

```text
v0.1 终点：知道 CAN 怎么工作，总线不通时能按流程排查
        ▼
v0.2 起点：经典 CAN 的带宽和 8 字节载荷不够用了
v0.2 终点：确定用经典 CAN / FD / XL，以及能否与现有节点共存
        ▼
v0.3 起点：参数都知道叫什么，但不知道怎么算出一组能用的值
v0.3 终点：位时序配置表、时钟容差核算表、错误状态诊断表、总线负载与最坏响应时间表
        ▼
v0.4 起点：总线跑得动了，但报文里每个位表示什么、代码写在哪，都还没有答案
v0.4 终点：信号数据库、分段传输参数表、诊断服务清单、网络管理状态表、验证矩阵
```

## 覆盖范围差异

- **v0.1** 只讲经典 CAN，偏概念与现象：差分电平、显隐性、终端电阻、ID 仲裁、数据帧、ACK、过滤器、排查流程。列出了位时序的段名和常见波特率，但不给公式。
- **v0.2** 讲三代演进，主线是"帧里能装多少"和"数据段能跑多快"这两次扩容。重点在帧格式对比、兼容性陷阱和选型。给出采样点的经验区间与结论，但不展开算法。
- **v0.3** 只做"可计算的部分"，把一条总线从一个位算到整网负载：晶振 → 位时间 → 采样点 → 采样错误 → 错误帧 → 错误计数与总线状态 → 单帧时长 → 总线负载与最坏响应时间。每章产出一份可填写、可核对的表格，并围绕同一个贯穿网络反复计算。
- **v0.4** 只讲"单帧之上"：信号定义 → 分段传输 → 诊断服务 → 网络管理 → 软件实现 → 验证。它直接引用 v0.3 的位时序与负载结论，不重复推导；沿用 v0.3 的同一个网络，并在其上增加诊断与刷写需求。

**报文级与信号级的分界**：报文的 ID、周期、长度、负载与时限属于 v0.3；报文内部的起始位、字节序、缩放系数与复用属于 v0.4。两篇在这条线上互不重叠。

三篇共用的底层概念（双线差分介质、显隐性规则、逐位仲裁）在 v0.1 讲清后，v0.2、v0.3、v0.4 直接引用，不重复展开。

## 使用建议

- 第一次接触 CAN：按 v0.1 → v0.2 顺读。
- 总线不通、报文收不到：进 v0.1 的排查章节，按现象分层。
- 要上 CAN FD 或面对新旧节点混接：进 v0.2，重点看兼容性和选型两章。
- 要配位时序寄存器、核算容差、评估总线负载：进 v0.3。
- 报文能收发但解析不对、要做诊断刷写、要让整网睡下去：进 v0.4。
- 收不到报文这类现象横跨多篇：先按 v0.1 排查硬件与配置，确认是位时序问题转 v0.3，确认是过滤器或信号定义问题转 v0.4。
