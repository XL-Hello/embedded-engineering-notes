# VMware Workstation 优化设置

> 目标：只通过 VMware Workstation 与宿主机相关设置，改善虚拟机的响应速度、图形体验和磁盘性能。调整虚拟硬件前必须先彻底关闭虚拟机，不要在挂起状态下修改。

## 1. 先用一张图确定设置位置

```text
VMware Workstation
├─ 编辑 -> 首选项                 全局设置：内存、更新、共享目录等
├─ 虚拟机 -> 设置 -> 硬件          单台 VM：CPU、内存、显示器、硬盘、网络
├─ 虚拟机 -> 快照                 快照创建、删除与合并
└─ 虚拟机文件所在位置              SSD/NVMe、可用空间、同步/杀毒排除
```

优先级通常是：**虚拟机放 SSD/NVMe → 合理分配 CPU/内存 → 开启 3D → 管理快照 → 检查 Hyper-V/VBS 兼容模式**。

## 2. 处理器：少而够用，不要占满宿主机

位置：`虚拟机 -> 设置 -> 硬件 -> 处理器`。

| 宿主机规格 | 推荐起点 | 说明 |
| --- | --- | --- |
| 4 核 / 8 线程 | 2 vCPU | 保留资源给 Windows 和 VMware 自身 |
| 8 核以上 | 4 vCPU | 大多数桌面和开发场景的平衡点 |
| 12 核以上 | 4～6 vCPU | 确有并行负载时再逐步提高 |

- 优先设置为“1 个处理器 + N 个核心”，让虚拟机以单 CPU 插槽、多核心方式运行。
- 不要分配全部逻辑线程。宿主机资源不足时，VM 和 Windows 会相互抢占，反而更卡。
- `虚拟化引擎`中与嵌套虚拟化相关的选项（如虚拟化 Intel VT-x/EPT 或 AMD-V/RVI）只在虚拟机内需要运行 Hyper-V、WSL2、Docker Desktop 等场景开启；不需要时不必勾选。
- 虚拟化 IOMMU 也只在客体系统确有相应需求时开启，普通桌面 VM 通常不需要。

## 3. 内存：避免宿主机与虚拟机同时换页

位置：`虚拟机 -> 设置 -> 硬件 -> 内存`；全局策略在 `编辑 -> 首选项 -> 内存`。

| 宿主机内存 | 单台 VM 推荐起点 | 注意点 |
| --- | --- | --- |
| 16 GB | 6～8 GB | 宿主机同时开浏览器/IDE 时宜从 6 GB 起 |
| 32 GB | 8～12 GB | 一般桌面 VM 的舒适范围 |
| 64 GB 及以上 | 12～16 GB 起 | 按实际 VM 数量和负载增加 |

- 不要把宿主机绝大部分内存分给虚拟机；Windows 开始分页时，虚拟机体感会明显变差。
- `首选项 -> 内存`中保持默认自动管理通常最稳妥。只有确认宿主机内存充足、且 VM 有明显内存抖动时，才考虑将内存更多保留在物理内存中。
- 同时运行多台虚拟机时，应按总内存计算，而不是分别按每台最大值配置。

## 4. 显示器：开启 3D，按需提高显存

位置：`虚拟机 -> 设置 -> 硬件 -> 显示器`。

```text
勾选：加速 3D 图形
显存：使用 VMware 可设置的较高值
多显示器：仅在确有需要时开启
```

3D 加速主要改善桌面动画、窗口拖动、浏览器和图形应用体验，不会提升 CPU 编译或磁盘速度。若开启后出现黑屏、花屏或宿主机 GPU 驱动异常，可先关闭 3D 验证兼容性，再更新宿主机显卡驱动和 VMware Workstation。

## 5. 虚拟磁盘：位置、格式与快照比容量更重要

位置：`虚拟机 -> 设置 -> 硬件 -> 硬盘`；虚拟机目录中通常包含 `.vmx`、`.vmdk` 等文件。

| 设置项 | 推荐 | 原因 |
| --- | --- | --- |
| 宿主机存放位置 | 本机 SSD/NVMe | 直接决定虚拟磁盘 I/O 延迟 |
| 磁盘文件 | 新建时优先“存储为单个文件” | 减少大量小分片文件的管理开销 |
| 磁盘容量 | 预留足够空间 | 防止快照和临时文件膨胀导致宿主机磁盘满 |
| 压缩/整理 | 客体删除大量文件后再按需执行 | 回收 `.vmdk` 占用；执行时会有较高 I/O |
| 预分配空间 | 容量大、长期重负载且 SSD 空间充足时可考虑 | 创建较慢、占用立即增大；一般按需分配即可 |

避免将整个 VM 放在机械硬盘、U 盘、网络盘、云同步目录中。宿主机磁盘建议保留至少 15%～20% 空闲空间，尤其是使用快照时。

## 6. 快照：短期回滚工具，不是长期备份

位置：`虚拟机 -> 快照 -> 快照管理器`。

```text
修改系统/安装大型软件前 -> 创建快照
验证完成且不再需要回退 -> 删除快照
删除后 -> 等待 VMware 完成合并，不要强制关机
```

- 快照会创建增量磁盘，磁盘写入路径变长；快照越多、保留越久，I/O 影响通常越明显。
- 删除快照不是简单删文件，VMware 需要合并数据。合并过程中保持宿主机供电、磁盘空间和 VMware 进程正常。
- 重要虚拟机应使用关机后的副本或专业备份，不要只依赖快照。

## 7. 网络：优先稳定，再选择模式

位置：`虚拟机 -> 设置 -> 硬件 -> 网络适配器`；全局网络在 `编辑 -> 虚拟网络编辑器`。

| 模式 | 适用场景 | 设置建议 |
| --- | --- | --- |
| NAT | VM 访问互联网、无需被局域网主动访问 | 默认优先，兼容性通常较好 |
| 桥接 | VM 需要作为局域网独立设备被访问 | 选择实际在用的物理网卡，避免自动桥接误选 VPN/虚拟网卡 |
| 仅主机 | 仅与宿主机通信、隔离测试 | 不提供公网访问，必要时配合第二块 NAT 网卡 |

未使用的网络适配器不要额外添加；避免同时启用多个功能重复的网卡，以免客体路由优先级混乱。VPN、企业安全软件或切换 Wi-Fi/有线网络后出现断网，可在虚拟网络编辑器中确认 VMnet0 的桥接网卡和 VMnet8 的 NAT 状态。

## 8. 宿主机兼容层：检查 Hyper-V 与 VBS

BIOS/UEFI 中应开启：

```text
Intel VT-x / Intel Virtualization Technology
或 AMD-V / SVM Mode
```

Windows 任务管理器 →“性能”→“CPU”中应显示“虚拟化：已启用”。

VMware 可与 Hyper-V、WSL2、Windows Sandbox、内核隔离（VBS）共存，但部分硬件和版本组合下可能进入兼容模式，性能或功能会受影响。若 VMware 异常缓慢：

1. 先更新 VMware Workstation 与宿主机显卡/芯片组驱动。
2. 确认 BIOS 虚拟化已启用。
3. 仅在不需要 Hyper-V、WSL2、Sandbox、VBS 等功能时，再评估关闭相应 Windows 功能或安全策略。

不要为了追求性能而在不了解影响的情况下关闭系统安全功能。

## 9. 设置完成后的检查清单

- VM 文件位于本机 SSD/NVMe，宿主机磁盘有足够空闲空间。
- CPU 和内存没有占满宿主机资源；多 VM 总量已核算。
- 已开启 3D 图形加速，出现异常时能回退验证。
- 快照数量少，旧快照已在 VMware 内正常删除/合并。
- 网络模式与使用场景匹配；桥接绑定到正确的物理网卡。
- BIOS 虚拟化已启用；Hyper-V/VBS 仅在确认必要时调整。

一套稳妥的起点（宿主机 32 GB、8 核以上、SSD/NVMe）：`4～6 vCPU + 8～12 GB 内存 + 3D 加速 + NAT + 单文件虚拟磁盘 + 少量短期快照`。之后再根据实际卡顿类型逐项调整，而不是一次性把所有资源拉满。
