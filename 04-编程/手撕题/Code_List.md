# 编程题整理

> 本文用于整理常见数据结构、算法和嵌入式 C 编程题。每道题包含题意、考察重点和实现要求，面试时应先说明思路、边界条件和复杂度，再写代码。

## 一、链表

### 1. 实现单链表的逆置

**题目说明**：给定单链表 `1 -> 2 -> 3 -> NULL`，将其修改为 `3 -> 2 -> 1 -> NULL`，要求尽量原地完成。

**考察重点**：指针保存、链表连接关系、头结点变化以及空链表和单节点链表的处理。

**实现要求**：使用 `prev`、`current`、`next` 三个指针迭代完成，不新建节点；时间复杂度 `O(n)`，额外空间复杂度 `O(1)`。需要说明返回新的头指针，避免在修改 `current->next` 后丢失后续节点。

### 2. 判断单链表中是否存在环

**题目说明**：判断链表是否存在某个节点的 `next` 指针指向此前出现过的节点。

**考察重点**：快慢指针算法，以及为什么快慢指针相遇就能证明存在环。

**实现要求**：使用 Floyd 快慢指针，慢指针每次走一步、快指针每次走两步；快指针或其 `next` 为空时表示无环。时间复杂度 `O(n)`，额外空间复杂度 `O(1)`，不能通过修改节点或使用哈希集合完成。

### 3. 求两个单链表的相交节点

**题目说明**：两个链表可能在某个节点开始共用后续节点，求第一个实际相同的节点，而不是值相同的节点。

**考察重点**：区分“节点地址相同”和“节点值相同”，以及两个链表长度不同的处理方式。

**实现要求**：可先求长度并对齐较长链表，也可使用“双指针切换链表头”的方法。两个指针分别走完 `A+B` 和 `B+A` 后会对齐；若没有相交点，最终同时为 `NULL`。时间复杂度 `O(m+n)`，额外空间复杂度 `O(1)`。

### 4. 求有环链表的第一个入环节点

**题目说明**：判断链表有环后，找到从链表头开始首次进入环的节点。

**考察重点**：Floyd 算法中相遇点与入环点的关系，不能把快慢指针第一次相遇点直接当作入环点。

**实现要求**：第一阶段让快慢指针相遇；第二阶段将一个指针放回头结点，两个指针每次各走一步，下一次相遇点就是入环点。正确处理空链表、无环链表和头结点就是入环点的情况；时间复杂度 `O(n)`，空间复杂度 `O(1)`。

### 5. 删除单链表中的一个节点

**题目说明**：删除链表中指定节点，需讨论指定节点是通过头指针找到的，还是只提供待删除节点指针。

**考察重点**：头结点删除、尾节点删除、节点不存在以及内存释放。

**实现要求**：若有头指针，使用前驱节点遍历并重新连接；删除头结点时更新头指针，删除尾节点时将前驱的 `next` 置空并释放节点。若题目只给待删节点指针，只能在该节点不是尾节点时把后继节点内容复制过来再删除后继节点，并明确说明尾节点无法用该方法删除。时间复杂度通常为 `O(n)`。

### 6. 递归合并两个有序链表

**题目说明**：将两个按升序排列的单链表合并为一个仍然升序的链表，例如 `1->4` 与 `2->3` 合并为 `1->2->3->4`。

**考察重点**：递归终止条件、节点复用、相等元素的处理和递归栈空间。

**实现要求**：比较两个头节点，将较小者作为当前头节点，再递归合并其后续部分；任一链表为空时直接返回另一个链表。不得重新复制节点；时间复杂度 `O(m+n)`，递归额外空间为 `O(m+n)`，也应能说明如何改为迭代版本以避免栈深度问题。

## 二、二叉树

### 1. 二叉树遍历

**题目说明**：实现前序、中序、后序和层序遍历，并说明不同遍历顺序的访问规则。

**考察重点**：递归与栈、队列的对应关系，以及二叉搜索树中序遍历有序这一性质。

**实现要求**：递归版本要处理空节点；非递归版本使用栈实现 DFS，使用队列实现 BFS/层序遍历。要求输出或收集节点值，不能依赖全局变量；时间复杂度 `O(n)`，空间复杂度为递归栈或辅助容器的 `O(h)`，层序遍历最坏为 `O(n)`。

### 2. 求二叉树深度

**题目说明**：求从根节点到最深叶子节点的节点数；空树深度为 `0`。

**考察重点**：递归定义 `depth = 1 + max(left, right)`，以及 DFS 与 BFS 两种实现方式。

**实现要求**：递归时正确处理空树；迭代时可按层计数，只有完成一层后深度才加一。明确题目按“节点数”还是“边数”定义深度；时间复杂度 `O(n)`。

### 3. 判断是否为平衡二叉树

**题目说明**：判断任意节点的左右子树高度差是否不超过 `1`。

**考察重点**：避免对每个节点重复计算高度，以及用特殊返回值提前终止。

**实现要求**：后序遍历同时返回子树高度；若发现不平衡则返回 `-1`，父节点继续向上传播，最终判断根节点结果。时间复杂度应为 `O(n)`，不能使用“对每个节点再调用一次求高度”的 `O(n²)`实现。

## 三、排序与查找算法

### 1. 快速排序

**题目说明**：选择一个基准值，通过分区将小于基准的元素放左侧、大于基准的元素放右侧，再递归排序两边。

**考察重点**：分区边界、基准选择、重复元素和最坏情况。

**实现要求**：实现原地版本，说明基准可选首元素、尾元素或随机元素；平均时间复杂度 `O(n log n)`，最坏为 `O(n²)`，额外空间来自递归栈。需要处理空数组、单元素数组和重复值，避免分区循环不推进。

### 2. 冒泡排序

**题目说明**：重复比较相邻元素，将较大值逐步交换到后面。

**考察重点**：循环边界、交换次数和提前结束优化。

**实现要求**：每轮将未排序区间的最大值放到末尾；增加 `swapped` 标记，在一轮没有交换时提前结束。平均和最坏时间复杂度 `O(n²)`，最好情况经优化后为 `O(n)`，额外空间复杂度 `O(1)`，且通常是稳定排序。

### 3. 归并排序

**题目说明**：将数组递归拆分成两半，分别排序后再合并为有序数组。

**考察重点**：分治、合并过程、临时空间和稳定性。

**实现要求**：合并时使用两个有序区间的游标，剩余部分直接拷贝；相等元素优先取左侧以保持稳定性。时间复杂度始终为 `O(n log n)`，额外空间复杂度 `O(n)`；应注意临时数组的申请和释放。

### 4. 堆排序

**题目说明**：构建最大堆，每次将堆顶最大值交换到数组末尾，再恢复剩余区间的堆性质。

**考察重点**：数组下标与完全二叉树的映射、向下调整和建堆复杂度。

**实现要求**：从最后一个非叶节点开始向下调整，建堆时间复杂度为 `O(n)`；排序阶段每次缩小堆范围，整体为 `O(n log n)`，额外空间 `O(1)`。同时了解使用 `priority_heap` 等优先队列容器实现时，通常是“不断取出堆顶”而非原地堆排序，空间和接口语义不同。

### 5. 插入排序

**题目说明**：维护一个已排序区间，将当前元素插入到该区间的正确位置。

**考察重点**：元素移动而非不必要的交换、逆序数据和稳定性。

**实现要求**：从第二个元素开始，向前移动大于当前值的元素，再插入当前值。最好时间复杂度 `O(n)`，平均和最坏为 `O(n²)`，额外空间 `O(1)`；适合数据量小或基本有序的数组。

### 6. 选择排序

**题目说明**：每轮在未排序区间中找到最小值，与当前区间首元素交换。

**考察重点**：最小值下标维护、循环边界和稳定性。

**实现要求**：每轮只进行至多一次交换；时间复杂度无论最好、平均还是最坏都为 `O(n²)`，额外空间 `O(1)`。普通交换版本通常不稳定，应能说明与插入排序的差异。

### 7. 二分查找

**题目说明**：在已按升序排列的数组中查找目标值，返回其下标；需要时进一步求第一个或最后一个等于目标值的位置。

**考察重点**：有序前提、区间定义、整数溢出和重复元素。

**实现要求**：统一使用左闭右闭或左闭右开区间，不能混用；中点写成 `left + (right - left) / 2`。明确找不到时的返回值；时间复杂度 `O(log n)`，空间复杂度 `O(1)`。查找边界时，即使找到目标也要继续收缩区间。

## 四、数组

### 1. 数组基础与边界处理

**题目说明**：针对数组进行遍历、插入、删除、去重、旋转或区间处理，并根据具体题意选择合适算法。

**考察重点**：连续内存、下标范围、原地修改、重复值和空间复杂度。

**实现要求**：所有访问都必须满足 `0 <= index < length`；明确数组长度为 `0`、只有一个元素和输入指针为空时的行为。涉及删除或插入时说明元素移动方向，避免覆盖尚未处理的数据；优先给出时间和额外空间复杂度。

## 五、字符串

> 以下题目按 C 风格以 `\0` 结尾的字符串为前提，必须考虑空指针、空字符串、目标缓冲区容量和重叠内存。

### 1. 字符串复制

**题目说明**：实现类似 `strcpy` 的函数，将源字符串（包含结尾 `\0`）复制到目标缓冲区。

**考察重点**：是否复制终止符、目标空间是否足够，以及源和目标重叠时的行为。

**实现要求**：目标指针和源指针有效，目标空间至少能容纳源字符串加 `\0`；复制完成后目标必须是合法 C 字符串。应说明该接口不检查容量，生产代码更适合使用带容量参数的安全封装；时间复杂度 `O(n)`。

### 2. 字符串翻转

**题目说明**：将字符串原地翻转，例如 `abcd` 变为 `dcba`。

**考察重点**：双指针交换、终止符位置，以及 ASCII 字符和多字节字符的区别。

**实现要求**：先找到字符串长度，再从两端向中间交换，不移动 `\0`；空字符串和单字符无需特殊修改。若输入为 UTF-8，按字节翻转会破坏编码，应明确题目只要求 ASCII，或另行按字符处理。

### 3. 单词顺序翻转

**题目说明**：将句子中的单词顺序翻转，例如 `I love C` 变为 `C love I`。

**考察重点**：单词边界、连续空格、首尾空格和原地算法。

**实现要求**：先整体翻转字符串，再逐个翻转每个单词；需要明确是否保留原空格格式。若要求规范化空格，则应跳过连续空格并移动有效字符；时间复杂度 `O(n)`，额外空间复杂度 `O(1)`。

## 六、图

### 1. 图的遍历：DFS 与 BFS

**题目说明**：从指定顶点访问图中所有可达顶点，分别实现深度优先搜索和广度优先搜索。

**考察重点**：邻接矩阵与邻接表、访问标记，以及有向图和无向图的差异。

**实现要求**：每个顶点最多访问一次；DFS 可用递归或显式栈，BFS 使用队列。必须处理非连通图（对所有未访问顶点继续遍历）；邻接表实现的复杂度为 `O(V+E)`。

### 2. 判断图中是否存在环

**题目说明**：判断有向图或无向图是否包含环，需先明确图的类型。

**考察重点**：无向图的父节点判断、有向图的递归栈状态，以及拓扑排序的应用。

**实现要求**：无向图 DFS 时忽略回到父节点的边；有向图使用 `0/1/2` 三色标记，遇到当前递归路径中的顶点即存在环。也可对有向图使用 Kahn 拓扑排序，若处理顶点数少于 `V` 则有环。

### 3. 最短路径

**题目说明**：求单源到其他顶点的最短距离，并根据边权选择算法。

**考察重点**：BFS、Dijkstra、Bellman-Ford 的适用条件。

**实现要求**：无权图使用 BFS；非负权图使用 Dijkstra（优先队列优化后通常为 `O((V+E)logV)`）；允许负权边时使用 Bellman-Ford，并检测负环。需要保存前驱节点，才能恢复具体路径而不只是输出距离。

### 4. 拓扑排序

**题目说明**：对有向无环图给出满足所有依赖关系的顶点顺序，例如课程先修关系或任务构建顺序。

**考察重点**：入度、队列、环检测和结果是否唯一。

**实现要求**：使用入度为 `0` 的队列逐步删除顶点，或使用 DFS 后序栈；结果数量小于顶点总数时说明存在环，不能得到合法拓扑序。时间复杂度 `O(V+E)`。

## 七、嵌入式常考的函数实现

### 1. ringbuffer

**题目说明**：实现固定容量的环形缓冲区，用于 UART、DMA、日志或采样数据的生产者与消费者解耦。

**详细资料**： [编程 ringbuffer 基础.md](ringbuffer/编程%20ringbuffer%20基础.md)；[当前 C 实现 rb.c](ringbuffer/rb.c)。

**实现要求**：明确 `head`（写索引）和 `tail`（读索引）的含义；正确处理空、满、回绕、批量读写、清空、销毁和溢出统计。当前实现采用“空一格法”，实际容量为 `size - 1`；`rb_put()` 在空间不足时只写入可用部分并返回实际写入长度。还要说明单生产者单消费者与多任务并发时的锁策略，不能把 `volatile` 当作线程安全保证。

### 2. `memcpy`

**题目说明**：将指定字节数从源内存复制到目标内存。

**考察重点**：按字节复制、长度为零、指针有效性和内存重叠。

**实现要求**：实现类似 `void *memcpy(void *dst, const void *src, size_t n)` 的接口；源和目标区域重叠时行为未定义，若需要支持重叠应实现 `memmove` 语义。返回目标地址，时间复杂度 `O(n)`；优化实现可讨论按字宽复制，但必须处理对齐和尾部字节。

### 3. `strcpy`

**题目说明**：复制源字符串及结尾的 `\0` 到目标缓冲区。

**考察重点**：字符串终止符、目标容量和返回值。

**实现要求**：逐字节复制，直到复制 `\0` 为止，并返回目标首地址。接口本身无法知道目标缓冲区大小，应说明缓冲区不足会造成越界；面试中可补充带容量参数的安全版本。

### 4. `strncpy`

**题目说明**：最多复制 `n` 个字符；若源字符串较短，目标剩余区域用 `\0` 填充。

**考察重点**：`strncpy` 不一定自动添加终止符，以及补零行为可能带来的性能开销。

**实现要求**：源长度大于等于 `n` 时，目标结果可能没有 `\0`，调用方不能直接当作字符串使用；源较短时必须将剩余位置补零。需要区分“定长字段复制”和“安全字符串复制”，不可简单把它当作始终安全的 `strcpy`。

### 5. `strlen`

**题目说明**：计算以 `\0` 结尾的字符串长度，不计入 `\0`。

**考察重点**：终止条件、空字符串和返回类型。

**实现要求**：从首地址遍历到 `\0`，返回 `size_t`；空字符串长度为 `0`。源指针必须指向合法且以 `\0` 结尾的内存，否则会越界读取；时间复杂度 `O(n)`，不要把字节数和字符数在 UTF-8 场景下混为一谈。

### 6. `strcmp`

**题目说明**：按字典序比较两个以 `\0` 结尾的字符串。

**考察重点**：逐字节比较、无符号字符比较和返回值语义。

**实现要求**：比较到首个不同字节或遇到 `\0`；返回值只需保证小于 `0`、等于 `0` 或大于 `0`，不能依赖具体差值。应使用 `unsigned char` 语义避免字符值大于 `127` 时出现符号扩展问题；时间复杂度最坏为 `O(min(m,n))`。


### 7. `queue`

**题目说明**：使用 C 实现一个基于链表的通用消息队列。生产者调用 `queue_put()` 将消息放入队尾，消费者调用 `queue_get()` 从队头取出消息，满足 FIFO 顺序。消息应独立封装类型、长度和负载，以便承载命令、事件、结构体等任意二进制数据；先实现单生产者单消费者（SPSC），再扩展为多生产者多消费者（MPMC）。

**考察重点**：链式队列的 `head`/`tail` 维护、消息数据所有权、可变长度数据的深拷贝、空队列处理，以及 SPSC 与 MPMC 的同步边界。

**消息与队列接口建议**：

```c
typedef struct message {
    uint32_t type;             // 消息类型：命令、事件、数据等
    size_t len;                // payload 的有效字节数
    uint8_t data[];            // 柔性数组：紧随节点保存任意负载的副本
} message_t;

/* 队列内部节点；对调用者隐藏，避免消息所有权与链表节点回收相互干扰。 */
typedef struct queue_node {
    message_t *msg;
    struct queue_node *next;
} queue_node_t;

typedef struct {
    queue_node_t *head;        // 队头/哨兵（消费者侧）
    queue_node_t *tail;        // 队尾（生产者侧）
    size_t count;
} message_queue_t;

bool queue_put(message_queue_t *q, uint32_t type,
               const void *data, size_t len);
message_t *queue_get(message_queue_t *q);
void message_destroy(message_t *msg);
```

`queue_put()` 应申请 `sizeof(message_t) + len` 字节，将 `type`、`len` 和负载**深拷贝**到消息对象，再用内部节点将其追加到队尾；`queue_get()` 返回消息对象的所有权，由消费者处理完成后调用 `message_destroy()` 释放。这样不会引用生产者的临时栈变量，也能传递任意长度的结构体或字节数据。

#### 第一阶段：单生产者单消费者（SPSC）

- 只有一个生产者调用 `queue_put()`，只有一个消费者调用 `queue_get()`；入队、出队均为 `O(1)`。
- 最简单的学习实现可在外层保证 `put` 与 `get` 不并发；要实现真正并发的无锁 SPSC，节点 `next` 及发布/读取顺序必须使用 C11 原子操作和 release/acquire 内存序，不能只加 `volatile`。
- 推荐使用哨兵节点：生产者只推进 `tail`，消费者只推进 `head` 并回收旧哨兵，可避免空/非空切换时的特殊分支。消息对象和内部节点分离后，消费者可安全释放取得的消息，而队列仍按自己的时机回收旧哨兵。销毁队列前必须确保生产者和消费者都已停止。

```text
put:  新内部节点 ──追加到 tail->next──> tail 指向新节点
get:  读取 head->next；为空则队空，否则前移 head 并交付其中的消息对象
```

#### 第二阶段：多生产者多消费者（MPMC）

多个任务同时修改 `head`、`tail` 和 `count` 时，不能在 SPSC 实现上简单增加 `volatile`。工程上优先采用：

1. **互斥锁**保护链表和计数的入队/出队操作；锁内只做指针连接、摘链和计数更新，不做耗时业务处理。
2. **计数信号量或条件变量**表示“队列非空”，使消费者在无消息时阻塞而非轮询；如需限制内存，还应增加“空闲槽位”信号量或最大消息数。
3. 在 RTOS 项目中，若消息大小固定，优先使用系统队列；若消息可变长，可使用消息缓冲区，或采用“内存池 + 指针队列”。不要在 ISR 中对该链表队列执行 `malloc/free` 或互斥锁操作。

**实现要求**：

- 正确处理 `data == NULL && len > 0`、内存申请失败、空队列、队列销毁时残留消息等情况。
- 明确负载所有权：本题采用“入队深拷贝、出队者负责释放”；不能返回指向已释放节点或生产者临时数据的指针。
- 若实现有界队列，应明确队满时采取拒绝、阻塞、超时或丢弃策略；无界链式队列仍受堆内存上限约束。
- 分析复杂度：单次入队/出队为 `O(1)`；额外空间为当前消息总大小及节点开销。MPMC 版本还需说明锁竞争和唤醒开销。

**追问**：为什么 MPMC 不直接做无锁队列？无锁 MPMC 需要处理 CAS 竞争、ABA 问题、节点安全回收和内存序，正确性验证成本很高。一般嵌入式业务队列优先使用 Mutex + 信号量；只有吞吐量、时延和锁竞争确实构成瓶颈时，再评估成熟的无锁算法或库。

## 八、答题与自测要求

1. 先写清输入、输出、边界条件和数据结构约束，再开始编码。
2. 至少验证空输入、单元素、重复值、最大容量、回绕、找不到目标和非法指针等情况。
3. 说明时间复杂度、额外空间复杂度，以及是否原地、是否稳定、是否支持并发。
4. C 语言题要检查内存分配失败、越界、内存泄漏、终止符和释放顺序。
5. 涉及链表或图时，建议画出指针/顶点关系后再实现；涉及环形缓冲区时，至少手工演算一次索引回绕。
