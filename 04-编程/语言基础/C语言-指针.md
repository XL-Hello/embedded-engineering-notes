# C 语言指针：专题讲解与面试高频题

> 目标：不仅会写 `*p` 和 `&x`，还要能解释地址、对象、数组、函数调用、内存生命周期之间的关系，并避开嵌入式开发中最常见的野指针、越界和回调问题。

---

## 1. 先建立一个正确的心智模型

变量是内存中的一个对象；**地址**是该对象所在位置的编号；**指针**则是专门保存地址的变量。

```c
int value = 10;
int *p = &value;

*p = 20;          /* 通过 p 访问并修改 value */
printf("%d\n", value); /* 20 */
```

```text
value：存放整数 10 的对象
&value：value 的地址
p：存放 &value 的指针变量
*p：p 指向的那个 int 对象，即 value 本身
```

必须区分下面四件事：

| 写法 | 含义 | 类型示例 |
|---|---|---|
| `value` | 对象中的值 | `int` |
| `&value` | 取对象地址 | `int *` |
| `p` | 指针变量中保存的地址 | `int *` |
| `*p` | 按 `int` 方式访问 p 指向的对象 | `int` |

指针不是“一个永远有效的地址”。它是否可解引用取决于：地址是否有效、是否对齐、指向对象是否仍活着、访问类型是否合理、是否有访问权限。

## 2. 指针的声明、初始化和解引用

### 2.1 声明容易误读的原因

`*` 属于变量名，不属于基础类型：

```c
int *p1, p2;       /* p1 是 int *，p2 是 int，极易出错 */
int *p3, *p4;      /* 两个都是 int * */
```

工程中建议一行只声明一个指针，或使用 typedef：

```c
typedef int *int_ptr_t;
int_ptr_t p1, p2;
```

### 2.2 初始化优先于“以后再说”

```c
int *p = NULL;     /* 尚未指向有效对象时，先置空 */

int x = 1;
p = &x;
*p = 2;
```

未初始化的局部指针保存的是不确定值。对它解引用是未定义行为，可能立即崩溃，也可能悄悄破坏其他内存。

### 2.3 `NULL` 不是可访问地址

`NULL` 表示“不指向任何对象”。可以比较、赋值和传递，但不能写 `*NULL`。访问前通常判断：

```c
if (p != NULL) {
    *p = 0;
}
```

注意：非 `NULL` 也不等于有效；野指针通常非空。

## 3. 指针运算：按“元素大小”移动

指针加减不是简单的字节加减，而是按其指向类型的大小移动。

```c
int a[4] = {10, 20, 30, 40};
int *p = a;

printf("%d\n", *(p + 2));  /* 30 */
```

若 `sizeof(int) == 4`，`p + 2` 的实际地址比 `p` 大 8 字节。只有在**同一个数组对象（或数组尾后一位）**的范围内进行指针运算才有定义；数组尾后一位可用于比较，不能解引用。

合法且常见：

```c
for (int *it = a; it != a + 4; ++it) {
    printf("%d ", *it);
}
```

不要对两个无关对象的指针做减法或大小比较，也不要靠“地址相减”猜结构布局。

## 4. 数组、指针与字符串

### 4.1 数组名常常衰变为首元素指针，但它不是指针

在大多数表达式中，数组名 `a` 会转换为 `&a[0]`，因此 `a[i]` 等价于 `*(a + i)`。

```c
int a[5];
int *p = a;
```

但两者本质不同：

| 项目 | 数组 `a` | 指针 `p` |
|---|---|---|
| `sizeof` | 整个数组字节数 | 指针本身字节数 |
| 能否重新赋值 | 不能 | 可以 |
| `&a` 类型 | `int (*)[5]` | 不适用 |

数组作为函数参数时会调整为指针，函数内无法靠 `sizeof(arr)` 得到元素总数：

```c
void process(int arr[], size_t count); /* 等价于 int *arr */
```

长度必须显式传入，或由协议/结构体字段携带。

### 4.2 字符数组与字符串常量

```c
char buf[] = "hello";           /* 可修改的数组副本 */
const char *msg = "hello";      /* 指向字符串字面量，不可修改 */

buf[0] = 'H';
/* msg[0] = 'H';  未定义行为，不能这样写 */
```

字符串以 `\0` 结束。复制时必须为结束符留出空间，优先使用带容量的接口或自行限制长度。`strcpy` 不知道目标缓冲区大小，嵌入式项目中尤应谨慎。

## 5. 多级指针与二维数组

### 5.1 二级指针：修改“调用者的指针”

当函数需要改变外部指针变量本身（例如分配内存、链表头插）时，传入其地址：

```c
int alloc_buffer(uint8_t **out, size_t len)
{
    if (out == NULL) return -1;
    *out = malloc(len);
    return *out == NULL ? -1 : 0;
}
```

调用：`uint8_t *buf = NULL; alloc_buffer(&buf, 128);`

`uint8_t **` 不是“任意二级指针都能替换”的通用类型。尤其不要把 `T **` 随意强转为 `const T **`，可能绕过 const 限制。

### 5.2 二维数组不是 `int **`

```c
int matrix[3][4];
int (*row)[4] = matrix;  /* 指向含 4 个 int 的一行 */
```

`matrix + 1` 要跨过一整行 4 个 `int`，所以正确形参需知道列数：

```c
void show(int a[][4], size_t rows);
/* 或：void show(int (*a)[4], size_t rows); */
```

`int **` 适用于“指针数组，每行单独分配”的数据结构；它与连续二维数组的内存布局不同，不能混传。

## 6. 指针与函数：传值、输出参数、回调

C 语言所有实参传递都是值传递。传指针时，复制的是地址；借助该地址可修改调用者对象。

```c
void swap(int *a, int *b)
{
    if (a == NULL || b == NULL) return;
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
```

### 6.1 函数指针与回调

```c
typedef void (*button_cb_t)(uint8_t id, void *ctx);

void button_register(button_cb_t cb, void *ctx);
```

驱动或事件框架保存回调函数地址，在中断下半部/任务上下文触发时调用它。`ctx` 用来绑定实例状态，避免全局变量。

关键风险：注册后，回调函数和 `ctx` 指向的对象必须在注销前一直有效；不能把一个即将返回的栈对象地址作为长期 `ctx`。

```c
void init(void)
{
    int local = 1;
    button_register(on_button, &local); /* 错：init 返回后 local 已失效 */
}
```

## 7. const 与指针：看 `const` 修饰谁

从变量名向左读，左边没有再向右读：

| 声明 | 含义 |
|---|---|
| const int *p / int const *p | 两种写法完全等价：不能通过 p 修改 *p，p 可改指向 |
| `int * const p` | p 必须始终指向同一地址，`*p` 可改 |
| `const int * const p` | 指向和内容都不能通过 p 修改 |

int const *p 与 const int *p 只是 const 的书写位置不同，语义完全相同。

只读输入参数宜声明为 `const`：

```c
uint16_t crc16(const uint8_t *data, size_t len);
```

它既表达接口契约，也能让编译器帮助阻止误写。不要为了消除警告而随手强转掉 `const`；若原对象确实是只读的，后续写入仍是未定义行为。

## 8. 指针与内存生命周期

### 8.1 常见存储期

| 对象来源 | 常见位置 | 有效期 |
|---|---|---|
| 局部变量 | 栈 | 所在代码块/函数执行期间 |
| `static` 对象 | 静态区 | 整个程序运行期 |
| `malloc` | 堆 | 从成功分配到 `free` |
| 全局对象 | 静态区 | 整个程序运行期 |

### 8.2 四类高频故障

```c
int *bad_return(void)
{
    int x = 1;
    return &x;         /* 悬空指针：函数返回后 x 已失效 */
}

int *p = malloc(sizeof *p);
//上面等于(int *p = malloc(sizeof(int));)
free(p);
*p = 1;                /* use-after-free */
free(p);                /* double free */

int *q;                /* 未初始化 */
*q = 1;                /* 野指针 */
```

释放后把**当前拥有者**的指针置为 `NULL` 是好习惯，但它不能清除别处保存的别名。资源接口应明确所有权：谁创建、谁释放、释放后谁不得再用。

### 8.3 嵌入式场景的额外注意

- 很多 MCU 堆小且易碎片化：长期运行路径优先静态分配、内存池或固定块分配。
- DMA 缓冲区必须在 DMA 完成前保持有效；缓存系统平台还须考虑 cache clean/invalidate 与对齐。
- ISR 与任务共享指针/缓冲区，要用临界区、原子操作或 RTOS 同步机制保护；`volatile` 不能替代同步。
- 外设寄存器地址通常通过 `volatile` 指针访问，表示每次读写都必须真实发生：`volatile uint32_t *reg`。

## 9. 结构体指针、链表和 `void *`

### 9.1 `.` 与 `->`

```c
struct device { uint8_t id; uint32_t baud; };
struct device dev = {0};
struct device *pd = &dev;

dev.id = 1;
pd->baud = 115200;     /* 等价于 (*pd).baud */
```

`(*pd).baud` 中括号不可省：`.` 的优先级高于 `*`，`*pd.baud` 会被理解为 `*(pd.baud)`。

### 9.2 `void *` 是“无类型对象地址”

`void *` 可保存任意对象指针，在 C 中对象指针可隐式转换到/从 `void *`。但不能直接解引用或做标准意义上的指针运算，必须先转回正确类型：

```c
void print_u32(const void *data)
{
    const uint32_t *p = data;
    printf("%u\n", *p);
}
```

传入类型、对齐和有效期仍由调用双方约定；`void *` 不会自动带来类型安全。

## 10. 实战排错清单

遇到 HardFault、随机复位、数据偶发错误时，按以下顺序检查：

1. 指针是否初始化，是否可能为 `NULL`？
2. 指向对象是否仍在生命周期内？是否返回了局部变量地址？
3. 缓冲区长度、下标和 `memcpy`/字符串终止符是否越界？
4. 指针类型、结构体对齐、二维数组列数是否匹配？
5. 分配与释放是否成对，是否存在别名导致的重复释放或悬空访问？
6. 是否跨 ISR/任务/DMA 使用？对象和缓存一致性是否受保护？
7. 打开编译器告警：`-Wall -Wextra -Werror`，必要时借助 ASan/Valgrind（主机侧）复现。

## 11. 面试高频问题与回答要点

### 11.1 指针和引用（C++）有什么区别？

指针是保存地址的对象，可为空、可改指向、可做有限指针运算，需要显式解引用；引用通常是对象别名，初始化后不能改绑定，语法上像普通变量。C 语言没有引用，接口中常用“指针参数 + 空指针检查”表达可选输出或对象访问。

### 11.2 数组名和指针完全一样吗？

不一样。数组名在多数表达式中会衰变为首元素地址，所以访问形式相似；但数组拥有固定大小和存储空间，不能被赋值，`sizeof(array)` 是数组总大小，而 `sizeof(pointer)` 只是地址大小。作为函数参数时数组会退化成指针，长度信息会丢失。

### 11.3 `int **` 与二维数组 `int a[M][N]` 为什么不能互换？

连续二维数组的行地址步长由 `N` 决定，类型是指向 `N` 个 `int` 的数组的指针，即 `int (*)[N]`；`int **` 是指向“int 指针”的指针，要求内存中先放指针表。两者布局不同，强行转换会以错误步长读地址，导致访问异常。


### 11.4 为什么 `free(p)` 后还建议 `p = NULL`？

`free` 不会改变传入的指针副本，p 仍保存旧地址，误用会形成悬空指针。置空能让同一变量的二次释放变为安全的 `free(NULL)`，也更容易发现误用；但其他别名仍然悬空，因此真正关键是明确所有权和生命周期。

### 11.5 `malloc`、`calloc`、`realloc` 有什么区别和坑？

三者都从堆申请内存，成功时返回可由 `free` 释放的地址，失败时返回 `NULL`；在 C 中不需要也不建议强转 `malloc` 的返回值。它们的区别在于申请方式与初始化行为：

| 接口 | 形式 | 成功后的内容 | 典型用途 |
|---|---|---|---|
| `malloc` | `malloc(bytes)` | 未初始化，内容不确定 | 后续会立刻完整写入的缓冲区 |
| `calloc` | `calloc(count, size)` | 所有字节置零 | 需要清零的数组、状态结构体 |
| `realloc` | `realloc(ptr, bytes)` | 调整已有块，原内容尽量保留 | 动态数组扩容/缩容 |

```c
/* 1. malloc：只申请，不清零 */
uint8_t *buf = malloc(len);
if (buf == NULL && len != 0) {
    return -1;
}

/* 2. calloc：申请 count 个元素，并将所有字节置零 */
uint32_t *table = calloc(count, sizeof(*table));
if (table == NULL && count != 0) {
    return -1;
}

/* 3. realloc：使用临时指针接收结果 */
void *tmp = realloc(buf, new_len);
if (tmp != NULL) {
    buf = tmp;          /* 可能原地扩展，也可能搬到新地址 */
} else {
    /* 失败时：旧 buf 仍有效，仍可使用或 free */
}
```

必须注意以下陷阱：

- `malloc` 得到的字节没有初始化，直接读取是错误的；若需要默认清零，可用 `calloc` 或在确认分配成功后 `memset`。
- `calloc` 的“清零”是**所有 bit 为 0**。对整数和字节缓冲区通常就是数值 0；不要把它当作所有平台上一切对象（尤其特殊浮点/指针表示）的通用初始化替代品。结构体需要严格初始化语义时，优先使用初始化器或逐字段赋值。
- `calloc(count, size)` 与 `malloc(count * size)` 都要防整数乘法溢出；`calloc` 的两个参数形式更便于表达元素数量与元素大小，但调用前仍要做上限检查。
- `realloc` 可能移动内存，成功后原指针不可再使用；若块内或其他地方保存了指向该块内部的指针，也要在移动后重新计算。
- 绝不能直接写 `p = realloc(p, n)`：失败时会丢失旧地址，导致无法继续使用或释放原内存。
- `malloc(0)` / `calloc(0, size)` 的结果不可解引用，可能返回 `NULL`，也可能返回可传给 `free` 的特殊地址。`realloc(p, 0)` 的处理在不同 C 标准和实现中容易产生歧义，工程中不要依赖它释放内存；需要释放时明确写 `free(p); p = NULL;`。
- 所有成功分配的块必须只 `free` 一次；`free(NULL)` 安全，但 `free` 后的别名仍是悬空指针。

嵌入式中还要评估堆碎片和实时性。初始化阶段或短生命周期对象可谨慎使用动态分配；长期运行的高频路径通常优先静态内存、内存池或固定块分配。

### 11.6 `volatile` 能解决多线程/中断共享数据问题吗？

不能。`volatile` 仅约束编译器不要省略或合并访问，适用于寄存器、可能被硬件/ISR改变的对象。它不提供原子性、互斥、内存顺序或复合操作保护。共享数据仍需按平台使用临界区、原子操作、信号量/队列等同步机制。

### 11.7 如何设计一个安全的“输出缓冲区”接口？

传入缓冲区和容量，返回实际长度或错误码；写入前检查指针、容量和每次剩余空间，并约定是否写终止符。例如：`int format(char *out, size_t cap, size_t *used)`。不要只传 `char *out` 而完全不知道可写大小。
