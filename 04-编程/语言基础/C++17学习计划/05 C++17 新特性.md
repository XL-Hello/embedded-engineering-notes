# C++17 新特性

本文对应 [C++17 学习计划](../C++17学习计划.md)的第五阶段，承接 [STL 与泛型编程](STL%20与泛型编程.md)。

本阶段要解决三个问题：如何简化模板与局部变量的表达，如何用类型区分“无值”和“多种结果”，以及如何控制视图、分配和并行执行带来的成本。

所有 `cpp` 代码均以 C++17 为基准，未注明“完整示例”的是局部片段。编译器支持语法，不代表目标标准库、RTOS 移植层和链接配置已经提供全部功能。

## 一、语言表达与编译期机制

### 1.1 局部表达与头文件变量

#### 1.1.1 结构化绑定与初始化语句


```cpp
#include <map>
#include <string>

std::map<int, std::string> names{{1, "uart"}, {2, "spi"}};
for (const auto& [id, name] : names) {
    // id 和 name 引用当前元素的组成部分。
}

if (auto it = names.find(1); it != names.end()) {
    // it 的作用域覆盖条件及相应分支。
}
```

结构化绑定可用于数组、符合 tuple 协议的类型和满足规则的数据成员分解。`auto [a,b]` 通常建立隐藏对象的副本，再绑定其元素；`auto&` 和 `const auto&` 则按引用方式分解，不能只看名字像引用就认定没有复制。

`if`、`switch` 的初始化语句可以把辅助变量限制在整个语句内，包括 `else` 分支，减少外层名字和意外复用。

```cpp
// readStatus() 返回整数，具体实现由平台提供。
switch (int status = readStatus(); status) {
case 0: break;
default: /* 使用 status 报告错误 */ break;
}
```

#### 1.1.2 内联变量与头文件常量


```cpp
// config.hpp 中：
inline constexpr int maxChannels = 8;

struct Limits {
    inline static int retryCount = 3;
};
```

内联变量允许在多个翻译单元中出现符合 ODR 的定义，使头文件可以直接提供这个变量的定义。普通命名空间作用域 `inline` 变量通常表示同一个实体，而不是每个源文件独立拥有一份。

`inline` 不自动让共享可变状态线程安全，也不代表变量存储位置或读取一定被优化掉。公共配置优先用不可变值；确需全局可变状态时明确同步与初始化依赖。

### 1.2 编译期分支与模板推导

#### 1.2.1 `if constexpr` 与模板实例化


```cpp
#include <string>
#include <type_traits>

template<class T>
std::string describe(const T& value) {
    if constexpr (std::is_integral_v<T>) {
        return std::to_string(value);
    } else {
        return value.name();
    }
}
```

普通 `if` 即使运行时总走其中一支，模板实例化时也通常需要两支都合法。`if constexpr` 的条件必须是编译期常量；在模板实例化中，条件确定后，被丢弃的分支不再按该实例进行实例化。

但分支仍须能够解析，非依赖名字等仍要满足相应检查；模板外写 `if constexpr(false)` 也不是隐藏任意非法代码的方法。`describe(42)` 不要求整数有 `name()`，而非整数类型必须满足另一分支的接口。规则可查阅 [C++17 草案的 if 语句章节](https://timsong-cpp.github.io/cppwp/n4659/stmt.if)。

#### 1.2.2 折叠表达式


```cpp
template<class... Args>
constexpr auto sum(Args... args) {
    return (0 + ... + args);
}

static_assert(sum(1, 2, 3) == 6);
```

这里的 `constexpr` 让满足条件的调用可以参与编译期计算，函数也可以接收运行时参数。

折叠把参数包沿某个运算符展开。带初始值的二元折叠能定义空包行为；例如整数求和可以用零。无初始值的空包只有少数运算符有规定结果，不能假定所有折叠都接受零个参数。

左右折叠的括号结合方式不同；减法、除法等不满足结合律时尤其需要检查。表达式计算类型和溢出规则仍然适用。

#### 1.2.3 CTAD 与 `constexpr` Lambda


```cpp
#include <array>
#include <utility>

std::pair pair{1, 2.5};      // 推导为 pair<int, double>
std::array values{1, 2, 3};  // 推导为 array<int, 3>

constexpr auto square = [](int value) constexpr {
    return value * value;
};
static_assert(square(4) == 16);
```

类模板实参推导通过构造函数和推导指引确定模板参数，不意味着可以根据任意使用场景推导所有参数。上例 `array` 的元素类型需要满足相应推导规则。

满足常量求值要求的 Lambda 可以参与编译期计算；它也可以处理运行时输入。需要动态分配或其他不满足 C++17 常量求值规则的操作，不能仅加 `constexpr` 就变成编译期操作。

### 1.3 保证的拷贝消除

```cpp
struct Token {
    Token() = default;
    Token(const Token&) = delete;
    Token(Token&&) = delete;
};

Token makeToken() { return Token{}; }
Token token = makeToken();
```

这些同类型纯右值初始化情形可以直接构造结果，不需要可用的复制或移动构造。析构函数仍必须满足相应可访问性等要求。

若改为 `Token local; return local;`，具名返回值优化在 C++17 中仍非强制，不能依靠它绕过不可用的复制和移动。可对照 [C++17 初始化规则](https://timsong-cpp.github.io/cppwp/n4659/dcl.init)与[可选的拷贝消除情形](https://timsong-cpp.github.io/cppwp/n4659/class.copy.elision)。

## 二、数据状态与标准库工具

### 2.1 optional、variant 与 any

#### 2.1.1 `optional`：可能没有值


```cpp
#include <optional>

std::optional<int> parseChannel(int raw) {
    if (raw < 0 || raw >= 8) {
        return std::nullopt;
    }
    return raw;
}

// 在函数中使用：
if (auto channel = parseChannel(3)) {
    int index = *channel;
    (void)index;
}
```

`optional<T>` 内部管理有值/无值状态，保存 `T` 本身不需要额外动态分配，但 `T` 自己仍可能分配。解引用前必须确认有值；`value()` 在无值时抛出 `bad_optional_access`，`value_or()` 提供备用值。

它只表达“没有”，不携带原因。若要区分参数错误、超时和设备断开，应该设计错误枚举配合结果类型，或用 `variant` 表达成功/错误。`std::expected` 不属于 C++17。

#### 2.1.2 `variant` 与 `visit`：有限种结果


```cpp
#include <string>
#include <type_traits>
#include <variant>

enum class Error { timeout, disconnected };
using Result = std::variant<int, Error>;

Result result = 42;
std::string text = std::visit([](const auto& value) -> std::string {
    using T = std::decay_t<decltype(value)>;
    if constexpr (std::is_same_v<T, int>) {
        return std::to_string(value);
    } else {
        return value == Error::timeout ? "timeout" : "disconnected";
    }
}, result);
```

`variant` 是类型安全的联合体，只保存某一个候选类型的值。`get_if<T>(&result)` 返回指针，类型不匹配时为空；`get<T>` 不匹配时抛出 `bad_variant_access`。

`visit` 的访问器必须能处理所有可能的候选组合，并满足返回类型要求。替换内部对象时若构造抛异常，`variant` 可能进入 `valueless_by_exception()` 状态，不宜简单认为它永远装着某个候选。

#### 2.1.3 `any`：开放的类型集合


```cpp
#include <any>
#include <string>

std::any item = std::string{"uart"};
if (auto* name = std::any_cast<std::string>(&item)) {
    // 通过 name 访问保存的字符串。
}
```

`any` 适合必须在运行时保存不同、预先难以枚举的可复制类型。指针形式的 `any_cast` 在不匹配时返回空，值或引用形式可能抛 `bad_any_cast`。

它需要运行时类型匹配，可能动态分配，并丢失接口层面的具体类型信息。已知消息只有几种时，`variant` 往往比 `any` 更容易穷尽检查。

### 2.2 string_view 的借用边界

```cpp
#include <string>
#include <string_view>

std::string storage = "uart:115200";
std::string_view view{storage};
auto name = view.substr(0, 4);
```

视图保存字符范围，不延长 `storage` 的生命。原字符串销毁或操作导致字符地址失效后，视图也会悬空。不要返回局部字符串的视图，也不要把临时拼接结果的视图保存在外部。

`string_view::data()` 不保证视图末尾有 `\0`。传给只接受 C 字符串的 API 时，通常要构造拥有内容的 `std::string`，或使用明确接受指针和长度的接口。构造和连续字符范围规则见 [C++17 string_view 章节](https://timsong-cpp.github.io/cppwp/n4659/string.view)。

### 2.3 filesystem 与 byte

```cpp
#include <filesystem>
#include <system_error>

std::error_code error;
bool present = std::filesystem::exists("config.ini", error);
if (error) {
    // 查询失败；不能和“路径不存在”混为一谈。
}
```

文件系统操作可使用相应的 `error_code` 重载处理常见系统错误，减少基于异常的控制流；这不构成“整个调用绝不抛任何异常”的普遍承诺。路径查询与后续打开之间仍可能发生变化，不能用一次 `exists()` 检查保证之后访问成功。

目标需要文件系统能力和相应标准库实现。较旧工具链还可能需要额外链接配置，应以实际工具链为准。

```cpp
#include <cstddef>

std::byte flags{0x03};
flags |= std::byte{0x04};
unsigned int raw = std::to_integer<unsigned int>(flags);
```

`byte` 用于原始字节，支持相应位运算，但不是普通算术整数。它不能自动处理协议端序、内存映射寄存器访问或结构体序列化。

### 2.4 接口检测与泛型调用

#### 2.4.1 `void_t` 检测某个表达式是否成立


```cpp
#include <type_traits>
#include <utility>

template<class T, class = void>
struct HasRead : std::false_type {};

template<class T>
struct HasRead<T, std::void_t<decltype(std::declval<T&>().read())>>
    : std::true_type {};
```

若表达式替换成功，偏特化可匹配；否则回到主模板。这只检查表达式是否可形成，不证明读取不会阻塞、不会失败，也不证明返回值符合业务单位。

`declval` 用于不求值语境中构造类型表达式，不能拿来实际创建运行时对象。

#### 2.4.2 `_v`、`conjunction` 与 `disjunction`


```cpp
template<class... Ts>
using AllIntegral = std::conjunction<std::is_integral<Ts>...>;

static_assert(AllIntegral<int, unsigned int>::value);
static_assert(std::disjunction_v<std::is_integral<int>, std::is_enum<int>>);
```

`is_same_v<T,U>` 等 `_v` 写法简化 `::value`。`conjunction` 组合逻辑与，`disjunction` 组合逻辑或，并具有相应的短路实例化特征；这与运行时分支是不同层面的机制。

类型约束负责检查表达式和类型条件；范围、设备状态、帧长度等仍要在运行时检查。

#### 2.4.3 `invoke` 与 `apply`


```cpp
#include <functional>
#include <tuple>

struct Sensor { int read(int gain) const { return 10 * gain; } };
Sensor sensor;
int first = std::invoke(&Sensor::read, sensor, 2);

auto args = std::make_tuple(2, 3);
int second = std::apply([](int a, int b) { return a + b; }, args);
```

`invoke` 统一调用普通函数、函数对象和成员指针；`apply` 把 tuple 类对象里的元素展开成函数参数。它们简化泛型包装，仍需要被调用对象和参数有效、生命周期正确。

## 三、资源成本与执行边界

### 3.1 内存资源与缓存干扰

#### 3.1.1 `pmr`：替换容器的内存来源


```cpp
#include <cstddef>
#include <memory_resource>
#include <vector>

alignas(std::max_align_t) std::byte buffer[1024];
std::pmr::monotonic_buffer_resource arena{
    buffer, sizeof buffer, std::pmr::null_memory_resource()};
std::pmr::vector<int> values{&arena};
values.reserve(16);
```

声明顺序保证 `values` 先析构，`arena` 后析构，底层缓冲区最后结束生命周期。单调资源通常逐步分配、集中回收，单个 `deallocate` 不回收相应块；反复扩容会消耗更多区域。

若不提供空上游，缓冲区不足时可能继续从默认上游分配。本例使用 `null_memory_resource()`，不足时抛出 `bad_alloc`，因此不是禁用异常环境下的自动替代方案。

资源本身不会自动延长生命；不能在容器仍使用存储时调用 `release()`。单调资源也不是线程安全资源。资源契约可查阅 [C++17 内存资源章节](https://timsong-cpp.github.io/cppwp/n4659/mem.res)。

#### 3.1.2 干扰尺寸与伪共享


`std::hardware_destructive_interference_size` 和 `std::hardware_constructive_interference_size` 在 `<new>` 中提供与缓存干扰相关的实现定义常量。

不同线程频繁修改恰好落在同一缓存行的独立变量，可能产生伪共享。可以在实现支持时用破坏性干扰尺寸辅助对齐或隔离，但不能假定它在所有工具链可用，也不能把数值写死为 64。

对齐会增加对象大小，也可能改变公开结构的 ABI。需要测量缓存行为后再决定是否值得隔离；这主要解决性能，不能修复数据竞争。

### 3.2 锁管理与并行算法

#### 3.2.1 共享锁与多锁管理


`std::shared_mutex` 是 C++17 的读写互斥工具，配合 `shared_lock` 允许多个只读持有者，写入使用独占锁。读少写多、临界区很短时未必比普通互斥量更快，也不保证特定公平性。

`std::scoped_lock` 可一次管理多个互斥量，通过相应的死锁避免机制获取它们。它解决这次组合获取的顺序问题，不能解决系统中所有其他资源依赖造成的死锁。具体用法见下一阶段。

#### 3.2.2 并行算法


```cpp
#include <algorithm>
#include <execution>

// values 已填充，比较操作没有共享写入副作用。
std::sort(std::execution::par, values.begin(), values.end());
```

`seq`、`par`、`par_unseq` 表达不同执行许可，`par` 不保证一定创建线程，也不保证一定更快。不要让一次迭代等待另一次迭代完成，否则串行执行的合法实现可能无法推进。

`par_unseq` 还允许同一线程内未排序的交错执行，不适合使用阻塞同步等不满足相应约束的操作。标准执行策略下，用户回调逃逸异常通常导致 `std::terminate`，不要依赖外层 `catch` 恢复。细节见 [C++17 并行执行规则](https://timsong-cpp.github.io/cppwp/n4659/algorithms.parallel.exec)。

实际是否需要额外后端库取决于标准库实现。实时设备线程通常先使用成本可预测的串行算法，再对可独立处理的大批量数据评估并行化。

## 四、命令解析与综合实践

### 4.1 命令解析实践与自查

#### 4.1.1 完整示例：不复制输入的命令解析


这个单文件示例使用 `string_view` 借用输入，用 `optional` 表达解析失败，用 `variant` 保存两种命令。可用 `g++ -std=c++17 -Wall -Wextra cpp17.cpp -o cpp17` 编译。

```cpp
#include <cassert>
#include <optional>
#include <string_view>
#include <type_traits>
#include <variant>

struct Start { int channel; };
struct Stop {};
using Command = std::variant<Start, Stop>;

std::optional<Command> parse(std::string_view text) {
    if (text == "STOP") {
        return Command{Stop{}};
    }
    if (text.size() == 7 && text.substr(0, 6) == "START " &&
        text[6] >= '0' && text[6] <= '7') {
        return Command{Start{text[6] - '0'}};
    }
    return std::nullopt;
}

int main() {
    auto command = parse("START 3");
    if (!command) {
        return 1;
    }
    int activeChannel = -1;
    std::visit([&](const auto& item) {
        using T = std::decay_t<decltype(item)>;
        if constexpr (std::is_same_v<T, Start>) {
            activeChannel = item.channel;
        } else {
            activeChannel = -1;
        }
    }, *command);
    assert(activeChannel == 3);
    const auto invalid = parse("START 9");
    assert(!invalid);
    return 0;
}
```

返回值只保存通道整数，不保存输入视图，所以调用结束后不再依赖输入字符。当前协议只接受单个 0～7 通道；若扩展为多位数字、校验和或错误分类，需要明确新的解析规则与结果类型。

#### 4.1.2 练习与自查


| 练习 | 要做的事情 | 检查点 |
| --- | --- | --- |
| 结构化绑定 | 对比按值、按引用遍历 map | 能说明是否复制，键能否修改 |
| 编译期分支 | 为整数和自定义类型实现不同处理 | 丢弃分支不依赖非法的非依赖名字 |
| 结果设计 | 把命令解析扩展为带错误原因的 variant | 能区分无值与失败原因 |
| 字符视图 | 传递子串并调用长度明确的接口 | 不依赖末尾零，不返回短命存储的视图 |
| 内存资源 | 使用固定缓冲区并限制容器容量 | 上游策略明确，资源活得比容器久 |
| 性能评估 | 比较串行与并行算法的批量耗时 | 计入线程后端、数据规模与异常策略 |
